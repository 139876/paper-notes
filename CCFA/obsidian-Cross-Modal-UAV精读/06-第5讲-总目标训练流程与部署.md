# 第 5 讲：总目标、训练流程与部署

> [!tip] 本讲目标
> 把前面两讲的模块**拼成一个完整系统**，并搞清楚一个工程上最关键的问题：
> **训练完之后，到底哪些东西被删掉了？**

---

## 6.1 总损失（论文 Eq.14）

$$
\mathcal{L} = \underbrace{\mathcal{L}_f}_{\text{SFI：特征搬运}} + \underbrace{\mathcal{L}_{cls}}_{\text{API：分类搬运}} + \underbrace{\mathcal{L}_{loc}}_{\text{API：定位搬运}}
$$

```
        ↑ ↑              ↑ ↑              ↑ ↑
    特征搬运          分类搬运        定位搬运
   （SFI 模块）      （API 模块）     （API 模块）
```

**超参一览**：π₁ = 0.3，π₂ = 0.7，ρ = 0.7，λ = 0.5

---

## 6.2 Algorithm 1（每个训练迭代做一遍）

1. 取一批 IR 图和**对应**的 RGB 图
2. **老师前向** → 拿到 $\{F_{IR}, p_{IR}, R_{IR}\}$（**参数冻结，不更新** 🧊）
3. **学生前向** → 拿到 $\{F_{RGB}, p_{RGB}, R_{RGB}\}$
4. 用上面 4 个量算总损失 $\mathcal{L}$
5. **只更新学生参数**：
   $$\theta_{RGB} \leftarrow \theta_{RGB} - \eta \cdot \frac{\partial \mathcal{L}}{\partial \theta_{RGB}}$$

> 🎯 **类比**
> 标准的"老师-学生"流程。老师是**已经毕业的高徒**，**不再学习**（冻结），只负责指点；学生每节课都在更新。

> [!note] 为什么老师必须冻结？
> 因为我们要的是"**从 IR 提取知识**"这件事。如果老师也在跟着 RGB 一起变，那两个模态会**一起漂移**，残差信息就无从对齐了。
> 而且冻结老师还省掉了它那一半的反向传播计算。

---

## 6.3 三个模块的"接口"一览

| 模块 | 输入 | 输出 | 作用位置 |
|---|---|---|---|
| $T_{IR}$ / $T_{RGB}$ | backbone 特征 $F$ | 对齐后的 $F$ | 维度对齐 |
| **SFI** | $F_{IR}, F_{RGB}$ | $M, \bar M$ → $\mathcal{L}_f$ | Backbone 之后 |
| **API** | $p_{IR}, p_{RGB}, R_{IR}, R_{RGB}$ | $w_{ciou}$ → $\mathcal{L}_{cls}, \mathcal{L}_{loc}$ | 检测头之后 |

---

## 6.4 部署阶段：到底删了什么

> [!quote] 论文 Sec. III-E 原文
> *"我们移除 IR 检测器、SFI 模块和 API 模块的所有参数，只把 RGB 图像喂给 RGB 检测器做实时检测。"*

```
【训练阶段】需要红外相机 + 两个模型（成本高无所谓）
 ┌──────────┐  X_IR   ┌───────────────────┐
 │ 红外图像  │ ──────► │ IR 检测器 (老师)   │  参数冻结 🧊
 └──────────┘         └───────────────────┘        │
                                                     │  知识
 ┌──────────┐  X_RGB  ┌───────────────────┐        ▼
 │ 彩色图像  │ ──────► │ RGB 检测器 (学生)  │ ◄───────┘
 └──────────┘         └───────────────────┘  训练参数 ✏️
                              ▲ SFI(搬特征) + API(搬预测)

【部署阶段】只要彩色相机 + 一个模型
 ┌──────────┐  ┌───────────────────┐  ┌──────────┐
 │ 彩色图像  │─►│ RGB 检测器 (学生)   │─►│ 目标框+类别│
 └──────────┘  └───────────────────┘  └──────────┘
             IR检测器 / SFI / API 全部删掉 ✅
```

**删除清单：**

| 删除项 | 省下来的东西 |
|---|---|
| IR 检测器 | 约 40M 参数 + 一次前向 |
| SFI 模块（含相似度图计算） | 显存 + 计算 |
| API 模块（含 $w_{ciou}$ 计算） | 显存 + 计算 |
| **红外相机** | **> 5000 美元** + 供电 + 体积 + 重量 |

> [!success] 为什么这个思路值得做？
> 因为"**训练时多花钱、部署时省钱**"在工程上非常划算。
> 你不会为了省训练成本，而牺牲部署时的重量、功耗和成本。
> 训练成本是一次性的，部署成本是**每台无人机 × 每一次飞行**都要付的。

## 6.5 训练 vs 部署 开销对照

| | 训练 | 部署 |
|---|---|---|
| 需要红外相机 | ✅ | ❌ |
| 需要两个检测器 | ✅ | ❌ |
| 需要 SFI / API | ✅ | ❌ |
| 前向次数 | **2 次**（老师 + 学生） | **1 次** |
| 参数量 | — | **约 40M**（单模态的一半） |
| 推理速度 | — | 与普通单模态**完全一样** |

> ⚠️ **训练成本翻倍这件事论文没提**——老师虽然冻结，但前向计算量实打实多了一倍。

## 6.6 这套设计的一般性

本文的骨架其实可以**抽象成三层**：

```
第 1 层 · 范式：   训练期用特权信息（多模态），部署期只留最小模态
第 2 层 · 搬运什么：特征（SFI）+ 预测（API）
第 3 层 · 搬多少：  残差 > 共性（π），老师可信度 > 盲信（w_ciou），老师 < 真值（ρ, λ）
```

> 🎯 **类比**
> 这就像一份完整的教案：
> - **范式** = 允许用教辅书备课
> - **搬运什么** = 课件 + 真题讲解（不只是知识点，还包括解题思路）
> - **搬多少** = 重点讲学生不会的，但以教材为准
>
> 而**部署阶段**（正式考试），学生手里只有一张白纸和一支笔。

这个抽象是你以后把 CKD **迁移到别的问题**时的抓手 → [[paper-notes/CCFA/obsidian-Cross-Modal-UAV精读/09-第8讲-批判性评价与可做选题]]。

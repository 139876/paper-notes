# 公共基础 9 · 梯度下降与反向传播

> [!note] 这是**公共基础知识**
> 这篇笔记与 CCFA-Net **没有绑定关系** —— 换任何论文、任何项目都用得上。
> 读 CCFA-Net 时它是「地基」；不读这篇论文，它照样是一篇独立的基础课。
> 底部还标了它在**方向知识脉络**里的位置，方便你把单点知识挂回整张地图。

## 9.1 一句话定义

> **反向传播 = 用链式法则，把"损失"从输出层一路倒推回每一个参数，算出"每个参数该往哪调、调多少"。**
> **梯度下降 = 拿到梯度后，沿"下坡最快"的方向迈一小步。**

一个负责**算方向**，一个负责**走路**。

---

## 9.2 训练循环的全貌

```
    ┌──────────────┐   前向传播 FWD    ┌──────────────┐
    │   输入图像 x  │ ────────────────▶ │   预测 ŷ      │
    └──────────────┘                   └──────┬───────┘
                                             │
                                    损失函数 L(ŷ, y)
                                             │  得到一个标量 L
                                             ▼
    ┌──────────────┐   反向传播 BWD    ┌──────────────┐
    │  参数 θ 更新 │ ◀────────────────  │  梯度 ∂L/∂θ  │
    └──────────────┘                   └──────────────┘
          ↑                                      │
          └──────── 梯度下降：θ ← θ − lr·∂L/∂θ ──┘
```

**一个 batch 的一次训练 = 前向一次 + 反向一次 + 更新一次。**

---

## 9.3 梯度下降：沿着最陡的下坡方向

参数更新公式（SGD）：

$$
\theta_{t+1} = \theta_t - \eta \cdot \frac{\partial \mathcal{L}}{\partial \theta_t}
$$

| 符号 | 名字 | 含义 |
|---|---|---|
| θ | 参数 | 卷积核里的每个数字 |
| ∂L/∂θ | **梯度** | "损失对 θ 的敏感度"，正数=增大 θ 会让损失变大 |
| η | **学习率 (learning rate)** | 每步走多远 |

### 梯度下降的直观含义

想象你站在山坡上，**看不见地形**，只能靠脚底感觉坡度：

- 脚底感觉"往右往下" → 你往右走一步 → 这就是"负梯度方向"
- 步子迈多大 → **学习率 η**

> 🎯 **比喻**
> 梯度下降 = **在浓雾里下山**。
> 你不知道山谷在哪，只知道脚下的坡度往哪边更陡（梯度），然后朝那边迈一步（−η·grad）。
> **学习率就是你的步幅**：
> - 太大 → 一脚跨过山谷，摔到对面更高的山坡（**震荡/发散**）
> - 太小 → 天黑前走不到底（**训练极慢**）
> - 刚好 → 稳稳下到谷底

### 学习率是最重要的超参数

| η 太大 | η 太小 | η 刚好 |
|---|---|---|
| 损失来回跳（震荡）、甚至发散成 NaN | 下降极慢；还容易停在平坦区 | 稳步下降 |

> [!tip] 论文里的学习率策略（本文的设置）
> 本文用 **SGD + momentum 0.9，weight decay 1e-4，初始 lr = 0.01**，在 **第 16 和第 22 epoch 各乘 0.1**（即 step decay）。
> 这就是典型的"**先大步跑，后期减速微调**"。为什么要在后期减 lr？因为后期损失曲面陡峭度变化大，小步更稳。

## 9.4 反向传播：链式法则的"接力跑"

### 一条链的直觉

```
x ──[f1]──▶ a ──[f2]──▶ b ──[f3]──▶ ŷ ──[Loss]──▶ L
```

要算"x 变一点点，L 会变多少"，就是把所有环节的敏感度**乘起来**：

$$
\frac{\partial \mathcal{L}}{\partial x}
=
\frac{\partial \mathcal{L}}{\partial \hat{y}}
\cdot
\frac{\partial \hat{y}}{\partial b}
\cdot
\frac{\partial b}{\partial a}
\cdot
\frac{\partial a}{\partial x}
$$

这就是**链式法则**。

> 🎯 **比喻：传话游戏**
> 一排人站成一排，最后一个人大喊一声"多少钱？"，消息要**原样传回**第一个人。
> 每个人要问清楚："传给你时变大了几倍？"然后把倍数**依次相乘**回传。
> 反向传播就是这个过程，**乘的每一个数就是那一层的导数**。

### 关键洞察：为什么反向传播是"复用"而不是"重算"

前向传播时，**中间结果都还留在内存里**（如 `a`、`b`）。
反向传播直接用它们算局部导数，**不需要重新前向一遍**。
这让训练成本 ≈ 2× 前向，而不是 N×。

### 每一层的职责

| 部件 | 前向时 | 反向时 |
|---|---|---|
| 卷积核 | 用输入和输出算特征图 | 收到上游梯度 → 算出"每个核权重该怎么调" |
| BN | 归一化 | 把梯度**平均分配**给每个样本（这一步正是"让梯度流起来"的关键，见 [[08-激活函数]] 的梯度消失） |
| ReLU | 砍掉负数 | 把负半轴的梯度**直接置 0**（所以 ReLU 也会导致死神经元） |

## 9.5 冻结参数：本文的关键工程手法

PyTorch 里冻结一个模块：

```python
for p in encoder.parameters():
    p.requires_grad = False
```

**发生了什么？**

| | 参数还在前向计算里吗 | 会被更新吗 | 梯度会算出来吗 |
|---|---|---|---|
| 冻结（`requires_grad=False`） | **会**（照常算特征） | **不会** | **不会算**（反向传播到此为止） |

> [!important] 这里有个特别容易搞混的点
> **冻结 ≠ 不参与前向。** 冻结的编码器**照样输出特征**（本文的 S2 就是它给的），
> 只是它的参数**不更新**，梯度**不往里流**。
> 一句话：**"只读，不写"**。

## 9.6 梯度是怎么"通"到各个分支的

本文的整体梯度流向（后面 [[04-第3讲-多任务损失与梯度冲突]] 会详细拆）：

```
                        ┌─────────────────────┐
                        │   冻结编码器 (S1+S2)  │  ← 参数不更新
                        └──────────┬──────────┘
                                   │ S2 特征
                 ┌─────────────────┴─────────────────┐
                 │                                   │
        ┌────────▼────────┐              ┌───────────▼──────────┐
        │  CCDD 去雾分支   │              │  ResNet 后段 + FPN   │
        │  （可训练）       │              │  → MFAM → TOOD      │
        └────────┬────────┘              └───────────┬──────────┘
                 │  L_dh（SSIM + L1 + 梯度）          │ L_od（分类+回归）
                 └─────────────────┬─────────────────┘
                                   ▼
                    总损失 L = L_od + λ·L_dh
                                   │
                          反向传播（从 L 开始倒推）
                                   │
        ┌──────────────────────────┴─────────────────────────┐
        ▼                                                    ▼
CCDD 的参数更新                                  检测分支的参数更新
（收到 L_dh + 经 CFFM 传来的 L_od 的梯度）      （收到 L_od + 经 CFFM 传来的 L_dh 的梯度）
```

**注意 CFFM 的位置**：它是**两条分支之间唯一的高架桥**。梯度要跨过"雾域 ↔ 净域"这道墙，只能走它。

> [!important] 这就是"联合学习"和"级联"的根本区别（梯度视角）
> - **级联（先去雾再检测）**：去雾网络训完就**冻结**（或只用自己的损失训），检测器看到的是去雾后的**新图像**。梯度**不跨接缝**。
> - **联合**：两条分支**端到端连着**，损失加在一起反向传播，梯度**真的能从检测头一路回到去雾分支的每一个卷积核**。
>
> 所以联合学习里，去雾分支收到的梯度不只来自 `L_dh`，还来自**检测任务的反馈** —— 这就是"联合"能产生 1+1>2 的机制来源。
> 详见 [[03-第2讲-Lipschitz不匹配]]（为什么会产生 1+1<2 的风险）。

## 9.7 一个必须算清的账：梯度从哪来，到哪去

以 **CCD D 里的一个卷积核** 为例，它收到两股梯度：

$$
\frac{\partial \mathcal{L}}{\partial W_{\text{CCDD}}}
=
\underbrace{\frac{\partial \mathcal{L}_{\text{od}}}{\partial W_{\text{CCDD}}}}_{\text{来自检测任务}}
+
\lambda \cdot
\underbrace{\frac{\partial \mathcal{L}_{\text{dh}}}{\partial W_{\text{CCDD}}}}_{\text{来自去雾任务}}
$$

- 第一项：路径是 `检测头 → FPN → S3/S4/S5 → ... → CFFM → CCDD`。CFFM 的可微融合让这条路**存在**。
- 第二项：路径是 `重建图像 → SSIM/L1/L_grad → CCDD`，是**直连**的。

**如果 CFFM 不可微（比如用硬阈值取大/取小），第一项就没了** —— 去雾分支就只剩自己的损失，联合学习的"互相促进"直接失效。
→ 这解释了 CFFM 为什么必须是**逐像素自适应加权**（可微），见 [[07-第6讲-CFFM跨域特征融合]]。

## 9.8 常见误解

| 误解 | 正解 |
|---|---|
| 反向传播 = 梯度下降 | 反向传播**只负责算梯度**，梯度下降**只负责更新参数**。前者是"怎么算"，后者是"怎么走"。 |
| 冻结 = 这个模块不参与计算 | 冻结的模块**照常前向**，只是不更新参数、梯度不回流。 |
| 学习率越大收敛越快 | 学习率太大会**震荡甚至发散**，反而更慢或不收敛。 |
| 梯度是"损失函数对参数的偏导" | 对，但更准确说是**在当前参数点处的偏导**，是一个**方向 + 幅度**，不是"参数该变成多少"。 |
| 梯度下降是全局最优的 | 只保证**局部**下降。深度网络损失曲面非凸，"山谷"很多，这就是为什么需要 SGD + momentum + 学习率调度这一套。 |
| momentum 0.9 是什么意思 | 梯度里混入 90% 的历史方向（惯性），用来**在一致方向上加速、在来回震荡方向上减速**。 |

## 9.9 超参数：你调的 vs 网络学的

> [!important] 一句话定义
> **超参数 = 训练开始之前由你（人）手动定好、而且不会被梯度下降学出来的那些数字。**

### 参数 vs 超参数（最容易混的一对）

| | **参数 (parameter)** | **超参数 (hyperparameter)** |
|---|---|---|
| 谁定的 | **学出来的** | **人定的** |
| 什么时候变 | 训练中每一步都被更新 | 训练**前**定好，训练中不变 |
| 存哪 | `model.parameters()`，进 checkpoint | **不进模型权重**，写在配置文件/实验设置里 |
| 例子 | 卷积核里每个数字、BN 的 γ/β、fc 的 W 和 b | lr、batch size、epochs、λ、网络宽度、block 个数、kernel size |
| PyTorch | `conv.weight` | `nn.Conv2d(256, 48, 3)` 里的 `256, 48, 3` |

> **判据一句话**：训练前你手填进代码里的是**超参**；训练中被梯度改出来的是**参数**。

> 🎯 **比喻**
> - **参数** = 学生做题时写下的答案 —— 做题过程中不断改
> - **超参数** = 老师定的考纲、评分标准、考卷难度 —— 考试前定好，做题时不能改
>
> 换个说法：**参数是模型脑子里的知识，超参数是调教它的说明书。**

### 再细分：架构超参 / 训练超参 / 数据超参

> 这个区分正好接上 [[11-ResNet残差网络]] 里那张表。

| 类型 | 改了会怎样 | 本文例子 |
|---|---|---|
| **架构超参数** | **模型结构本身变了**（参数量、FLOPs 都变） | 网络宽度、block 个数、kernel size、CCDD 的 `256→48`、MFAM 的 3/5/7、TAL 的 β=6 |
| **训练超参数** | **结构不变**，只改"怎么训" | lr、momentum、weight decay、batch size、epochs、λ=0.5、翻转概率 |
| **数据超参数** | 数据怎么用 | 8:1:2 划分、输入 1333×800 |

> 🎯 **比喻**
> **架构超参 = 买什么配置的电脑**（CPU 型号、内存大小）；
> **训练超参 = 怎么用它**（插什么电、跑多久、每次喂多少数据）。
> 买错型号是**买错了机器**，用错方法是**方法不对** —— 排查问题时先分清是哪一类。

### 本文（CCFA-Net）的超参全表

| 类别 | 超参数 | 值 |
|---|---|---|
| 训练 | optimizer | SGD + momentum 0.9 |
| | lr / 调度 | 0.01；在第 16、22 epoch 各乘 0.1 |
| | weight decay | 1e-4 |
| | batch size | **2**（很小，见下） |
| | epochs | 24 |
| | 增强 | 随机翻转 p=0.5 |
| | 输入尺寸 | 1333 × 800 |
| 多任务 | λ（去雾损失权重） | **0.5** |
| 架构 | 骨干 | ResNet-50（ImageNet 预训练），conv1+stage1 **冻结** |
| | CCDD | RFEB ×2；重建 conv 256→48；PixelShuffle(4) |
| | MFAM | 多尺度 3/5/7；δ 自适应 |
| | 检测头 | TOOD；TAL β=6、γ=6 |
| | FPN | in=[256,512,1024,2048]，out=256，start_level=1，num_outs=5 |
| **缺失** | **随机种子 / warmup** | ⚠️ **论文没给** → 复现时必须自己定并在报告里写明 |

### 三条纪律（踩过坑才知道）

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | **绝不能在测试集上调超参** | 那是**数据泄漏**：你用测试集的信息挑了超参，报出来的 mAP 就虚高了。必须在**验证集**上调。本文用 HazyDet 的 val（1000 张）；RDDTS 是**零微调**测试，所以 28.7 这个数才可信。 |
| 2 | **超参不算模型的一部分，但必须写进论文** | 它不进 checkpoint，但别人**复现不了**就是你的问题。Table 7 那种效率表还要单独说明推理设置。 |
| 3 | **超参越多越难调，也越容易过拟合验证集** | 搜 100 组组合、每组都看验证集 → 你其实是在**用验证集训练**，最后验证集会过于乐观。 |

### 为什么论文要做超参消融

Table 13 的 λ 消融（0 → 52.8，0.5 → **54.6**，1 → 54.3，10 → 54.0）本质上是在证明：
**"λ=0.5 这个超参的选择是稳的、不是瞎调出来的"** ——
因为把 λ 在 0.5~1 之间移动，性能只掉 0.3，说明方法对这个超参**不敏感**，这叫**鲁棒性好**。

> 反过来，如果 λ 从 0.5 动一点点性能就崩，那说明这个超参其实承担了模型的核心工作，
> 审稿人会怀疑"你调参调出来的"。

> [!tip] 复现者的实操顺序
> 1. 先**照抄**论文的超参（本文的表就是给你抄的）
> 2. 再逐个改动，**一次只动一个**，用验证集比较
> 3. 最后在**测试集**上跑一次，报告结果 + 记录你改过的每一项

## 9.10 自测题

1. 写出 SGD 的参数更新公式，说清三个符号各自的含义。
2. 学习率设太大 / 太小分别会出现什么现象？
3. 冻结一个模块（`requires_grad=False`）后：它还参与前向吗？梯度会算进它吗？它的参数会更新吗？
4. 在链 `x → a → b → ŷ → L` 中，`∂L/∂x` 是怎么由四个局部导数组成的？
5. **在本文的 CCDD 里，一个卷积核收到的梯度由哪两部分构成？各自走哪条路径？**
6. **如果 CFFM 改成"取最大值"的硬操作（不可微），联合学习的"互相促进"会怎样？为什么？**
7. 下面这些里，哪些是**超参数**、哪些是**参数**？请分类：
   `lr=0.01` · `conv.weight` 里的数字 · `batch size=2` · `BN 的 γ` · `CCDD 的 48 通道` · `λ=0.5` · `epochs=24`
8. 为什么**绝对不能**在测试集上调超参？本文的 RDDTS 为什么"零微调"反而更可信？

<details>
<summary>👉 自测答案</summary>

**1.** `θ_{t+1} = θ_t − η·∂L/∂θ`。θ 是参数；∂L/∂θ 是梯度（损失对参数的敏感度，符号指方向）；η 是学习率（步长）。

**2.** 太大 → 在谷底两侧来回**震荡**，甚至损失发散成 NaN；太小 → 下降极慢，且容易在平坦区停滞。本文用 lr=0.01 并在 16/22 epoch 各 ×0.1，就是典型的"先大步后小步"。

**3.**
- 参与前向：**会**（照常输出 S2 特征）
- 梯度算进它：**不会**（反向传播到此为止）
- 参数更新：**不会**

一句话：冻结 = "只读，不写"。

**4.**
$$
\frac{\partial L}{\partial x}=\frac{\partial L}{\partial \hat{y}}\cdot\frac{\partial \hat{y}}{\partial b}\cdot\frac{\partial b}{\partial a}\cdot\frac{\partial a}{\partial x}
$$
即各环节局部导数**依次相乘**。

**5.**
$$
\frac{\partial L}{\partial W_{CCDD}}=\frac{\partial L_{od}}{\partial W_{CCDD}}+\lambda\frac{\partial L_{dh}}{\partial W_{CCDD}}
$$
- **检测路径**：检测头 → FPN → S3/S4/S5 → **CFFM** → CCDD（必须穿过 CFFM 这座桥）
- **去雾路径**：重建图 → SSIM + L1 + L_grad → CCDD（直连）
- λ = 0.5。

**7.**
- **超参数**：lr=0.01、batch size=2、CCDD 的 48 通道、λ=0.5、epochs=24
- **参数**：conv.weight 里的数字、BN 的 γ（γ 初始值 1 是超参，训练后学到的值是参数）

**8.** 在测试集上调超参 = **数据泄漏**：你用测试集的信息挑了超参，报出的 mAP 会虚高（乐观偏差）。
RDDTS 是**零微调**测试（模型完全没在这批真实雾数据上训练过、也没用它选过超参），所以 28.7 这个数是**干净的泛化能力**证明。

**6.** "互相促进"**基本失效**。因为检测路径上的梯度必须**穿过 CFFM**；硬取最大不可微，梯度在那里被截断，检测任务的梯度**传不到** CCDD。CCDD 就退化成"只被自己的去雾损失训练"的独立去雾网络，联合学习变成"级联"。**这正是 CFFM 必须用可微的逐像素加权、而不是硬融合的原因。**

</details>

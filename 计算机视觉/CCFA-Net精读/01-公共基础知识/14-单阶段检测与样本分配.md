## 0.5 插播：YOLO 去哪了？

![[YOLO-在单阶段谱系中的位置.png]]

### 一句话回答

> **YOLO 当然单阶段 —— 它是单阶段的祖师爷之一（YOLOv1, 2016）。**
> 但这一篇的主线是 **"谁是正样本"**（样本分配），而 **YOLO 在这条线索上的理论贡献直到 v7/v8 才补齐**，
> 所以它没被选作主干 —— **不是遗漏，是线索不同**。

### 两条主线的分工

| | 主线 A · 样本分配理论线 | 主线 B · 工程效率线 |
|---|---|---|
| 代表 | RetinaNet → FCOS → ATSS → TOOD → DETR | YOLOv1 → v3 → v5/vX → v8 |
| 解决的核心问题 | **正样本怎么定、损失怎么加权** | **怎么做到又快又准**（架构、增广、训练技巧） |
| 关键贡献 | Focal Loss / centerness / 自适应阈值 / TAL / 匈牙利匹配 | 端到端单阶段 / CSP / 解耦头 / mosaic / EMA / anchor-free |
| **本文用哪条** | **就是这条**（检测头 = TOOD） | 平行线，本文没走 |

> 🎯 **比喻**
> 主线 A 是**"怎么当老师"** —— 题目（哪个框该学）、评分（损失怎么算）、批改（梯度回传）。
> 主线 B 是**"怎么当运动员"** —— 跑得快、动作不受伤、装备趁手。
> 两者都要，但**本文的创新点全在"怎么当老师"这条线上**，所以我只讲 A。

### 为什么 YOLO 串不进主线 A

**因为 YOLO 不是"一个方法"，而是一条"产品线"。**

- RetinaNet 是一篇论文、一个公式（Focal Loss），可以被"引用 + 改进"。
- YOLO v1 到 v9 **每版的架构、损失、训练策略、数据增广全换**：
  v1 网格中心规则 → v3 anchor + FPN → v5 解耦头 + mosaic + EMA → v8 anchor-free + TAL。
  你没法说"YOLO 方法是 X"，只能说"YOLOv5 是 YOLOv4 的某个改进"。
  **没有统一锚点，就串不成一条"每步修上一步"的理论链。**

### 但！YOLO 在"样本分配"这条线上其实有两个关键节点

| YOLO 版本 | 它的样本分配机制 | 对应主线 A 的哪一环 |
|---|---|---|
| YOLOv1（2016） | 网格中心规则：目标中心落在哪个网格，哪个网格负责它 | 无对应（这是最早的粗糙版） |
| YOLOv3（2018） | anchor + IoU 阈值选正样本 | ≈ Faster R-CNN 那套**固定阈值** |
| YOLOX（2021） | **SimOTA**：每个真值框动态算 top-k 候选 | **≈ ATSS**（同一个思想） |
| YOLOv8（2023） | **TaskAlignedAssigner** | **= 直接搬用 TOOD 的 TAL** |

> [!important] 这里是很多人不知道的事实
> **ultralytics 把 TOOD 的 TAL 原封不动搬进了 YOLOv8。**
> 也就是说，在"样本分配"这条线上，**YOLOv8 是 TOOD 的下游，不是上游**。
>
> 顺带解释了为什么 YOLOv8 的 anchor-free 分支和 TOOD、FCOS 长得像 —— **它们本来就是同一套逻辑的不同实现**。

## 1. 单阶段的第一性原理：密集预测

**两阶段的问法**："图里有车吗？在哪？" → 先给出一批候选框，再逐个判断。
**单阶段的问法**："特征图的**每个位置**，分别回答一次：这里有车吗？框有多大？"

![[单阶段-密集预测与正负失衡.png]]

> 🎯 比喻
> - **两阶段 = 撒网**：先撒一张大网（1000 个候选框），再逐个检查网眼里的东西。
> - **单阶段 = 挨家挨户敲门**：图上每个位置都敲一次门，问"有人吗"。
> 单阶段没有"先圈再认"这一步，所以快；但它必须对**成千上万个位置**都给出判断。

**代价是什么？** 特征图上一个位置 = 一个候选答案。800×1333 的输入、FPN 输出 stride 8 的那层 → 约 100×167 ≈ **1.7 万个位置**，每个位置还要跨 5 层 FPN 都算一遍。
于是**绝大多数"答案"都是"这里什么都没有"**。

> [!danger] 单阶段的"原罪"：正负样本极度不平衡
> 一张图 1 万个位置，可能只有 3 个是真的车。
> **正负比例 1 : 3000**，而交叉熵损失会让 3000 个"答对了的空白"去支配梯度。

**对比一下两阶段是怎么绕开这个问题的**（仓库实测 `faster-rcnn_r50_fpn.py`）：
- RPN：`RandomSampler(num=256, pos_fraction=0.5)` → **128 正 / 128 负**（人为拉平）
- RoI 头：`RandomSampler(num=512, pos_fraction=0.25)` → **128 正 / 384 负**

> **两阶段靠"采样"强行制造平衡；单阶段没有采样这一步，所以只能从"损失权重"或"样本分配"上想办法。**
> 这就是接下来四招的由来。

## 2. 第一招：Focal Loss（RetinaNet, 2017）——压住背景的**损失权重**

**要解决的问题**：背景样本太多，它们的"负样本损失"把梯度淹没了。

**思路**：一个**已经学会的**样本，它的预测概率已经很高，继续在它身上花梯度是浪费。**把这种简单样本的权重压下去**，让梯度集中在难样本上。

$$
\mathrm{FL}(p_t)=-\alpha_t\left(1-p_t\right)^{\gamma}\log(p_t)
$$

**逐项拆开看：**

| 项 | 含义 | 默认值 |
|---|---|---|
| p_t | **目标类别**的预测概率（预测对了就接近 1） | — |
| log(p_t) | 普通交叉熵 | — |
| (1-p_t)^γ | **调制项**（modulating factor）：压低"已经学会的"样本 | γ = 2 |
| α_t | **权重项**：给正负样本不同的权重 | 正样本 0.25 / 负样本 0.75 |

![[FocalLoss-权重曲线.png]]

**数字账（一定要自己算一遍）：**

| 样本 | p_t | γ=0（普通 CE）权重 | γ=2 权重 | 效果 |
|---|---|---|---|---|
| 易背景（已经学会"这里没车"） | 0.99 | 1.0 | (0.01)^2 = 1×10⁻⁴ | **降 10000 倍** |
| 困难样本（车只露了一个头） | 0.2 | 1.0 | (0.8)^2 = 0.64 | 几乎不压 |

> [!important] 这就是 γ 的全部含义
> **γ 越大，越"只关注难样本"。** γ=0 就退化成普通交叉熵。
> RetinaNet 论文里 γ=2、α=0.25 是网格搜索出来的默认值。

**仓库实测**（`configs/tood/...hazydet.py`）：
- ATSS baseline：`initial_loss_cls=FocalLoss(gamma=2.0, alpha=0.25)`
- TOOD：前期用上面的 Focal Loss，**后期换成 `QualityFocalLoss(beta=2.0)`**（质量感知，见第 4 节）

> [!warning] Focal Loss 解决的**不是**"谁是正样本"
> 它只调整**已经定好身份**的样本的损失权重。
> "这个位置到底算不算正样本"这个问题，Focal Loss 一点没碰。
> **这是接下来三招要解决的。**

## 3. 第二招：FCOS（2019）——把 anchor 拆了

**要解决的问题**：anchor 有三个硬伤。
1. **超参数多**：尺度、长宽比、IoU 阈值，全靠手调；
2. **正负样本还是靠 IoU 阈值划**（同样的老问题）；
3. **anchor 与特征图位置绑定**，换分辨率就要重调。

**FCOS 的做法：让每个位置直接预测"四条边离我多远"。**

$$
(l,\,t,\,r,\,b)=\left(x-x_l,\;y-y_t,\;x_r-x,\;y_r-y\right)
$$

- 一个位置 (x,y) 预测 4 个**相对距离**，四边一确定，框就出来了；
- **不需要任何 anchor 模板**；
- 回归损失用 **IoU Loss**（直接优化 IoU，而不是 L1）。

**两个配套零件：**

**① centerness（中心度）**
一个位置如果恰好在目标正中心，它负责的框最准、最不容易出错。定义大致是"到四条边的距离越均衡，centerness 越高"。

$$
\mathrm{centerness}=\frac{\sqrt{\min(l,r)\cdot\min(t,b)}}{\max(l,r)\cdot\max(t,b)+1}
$$

- 这个分数在**推理时不参与**（只用来训练时选样本和加权分类损失）；
- 但它是**后面 ATSS 的地基**——ATSS 就是用 centerness 来衡量"这个点有多可靠"。

**② level assignment（层级归属）**
FPN 有 5 层，每层 stride 不同（8/16/32/64/128），**每层只负责一定尺寸范围的目标**：
- stride 8 那层负责小目标（框小 → stride 要小，才能有足够分辨率）；
- stride 128 那层负责超大目标。
> 一句话：**小目标要细看（用高分辨率的小 stride 层），大目标要概览（用低分辨率的大 stride 层）。**

**仓库实测**（`configs/fcos/fcos_r50_fpn_1x_hazydet.py`）：

| 项 | 值 |
|---|---|
| head | `FCOSHead`, `stacked_convs=4`, `feat_channels=256` |
| strides | `[8, 16, 32, 64, 128]`（**没有 anchor_generator**） |
| 分类损失 | `FocalLoss(gamma=2.0, alpha=0.25)` |
| 回归损失 | `IoULoss` |
| centerness 损失 | `CrossEntropyLoss` |
| 推理 | `nms_pre=1000`, `score_thr=0.05`, **NMS IoU 0.5** |
| 论文成绩 | Table 2：Car 54.4 / Truck 27.1 / Bus 56.2 → **mAP 45.9** |

> [!note] 注意最后一行
> FCOS 是 anchor-free 了，**但仍然要用 NMS 去重**。
> **"去 anchor" ≠ "去 NMS"。** 要去掉 NMS，得等到下一节的 DETR。

## 4. 第三招：ATSS（2020）——让目标自己决定谁是正样本

**要解决的问题**：就算不用 anchor 了，"正样本"还是靠 **IoU ≥ 0.5 这样的固定阈值**来划。
这个阈值对小目标**极不友好**：一个小车在特征图上只占 1.7 个格子（14 px / stride 8），**跟任何候选点的 IoU 都可能达不到 0.5** → **一个正样本都分不到** → 这个目标彻底学不会。

**ATSS（Adaptive Training Sample Selection）的两步法：**

![[ATSS-两步选样本.png]]

**第一步 · 候选生成（按位置，不按 IoU）**
对每个 GT，取**离 GT 中心最近的 k=9 个特征点**（含中心点本身）作为候选。
> 这一步**完全不看 IoU**，只看几何距离——**保证候选一定"在目标上"**，哪怕 IoU 不高。

**第二步 · 用 IoU 统计反过来定阈值**
1. 算这 9 个候选与 GT 的 IoU；
2. 取 IoU 最大的若干个（实现上取 top-k）；
3. 用它们的 **IoU 均值**作为阈值 τ；
4. **IoU ≥ τ 的候选点 → 正样本**。

**为什么这样更好？** 因为 τ 是**每个目标自己算出来的**，不是全局写死的 0.5：
- **大目标** → 候选点密集、IoU 都高 → τ 高 → 但正样本数量也多；
- **小目标** → 候选点少、IoU 都低 → τ 自动降下来 → **照样能分到正样本**。

> 🎯 比喻
> 固定阈值 0.5 = "用一把尺子量所有人，够高才算数"。
> ATSS = "**每个人用自己的尺子**：先量 9 次，取平均线作为自己的及格线"。
> 小个子天生量得低，但他的及格线也低，所以不会被误杀。

**仓库实测**（`configs/atts/...hazydet.py`）：`assigner=dict(type='ATSSAssigner', topk=9)`。
> [!danger] 这份 baseline 配置有 bug
> `ATSSHead` 里写的是 `num_classes=80`（COCO 的类别数），而 HazyDet 只有 3 类（Car/Truck/Bus）。
> **直接跑它得到的数字是错的。** 复现任何 baseline 前，第一件事就是查 `num_classes`。

## 5. 第四招：TOOD（2021）——任务对齐（本文采用）

**要解决的问题**：ATSS 用 **centerness** 衡量"这个点靠不靠谱"，但 centerness 只看**定位**。
TOOD 指出一个更根本的现象——**分类与定位会"空间错位"**：
> 一个点可能**分类分很高**（它那一片像素确实是车的一部分），但**它不是框的中心**；
> 另一个点可能**定位最准**（正好在中心），但那一点的像素**被雾糊了、特征很弱**、分类分不高。
> **你让谁当正样本？**

**TOOD 的答案：按"对齐度"选。**

$$
\text{alignment metric}=\text{cls\_score}^{\alpha}\cdot \text{loc\_quality}^{\beta}
$$

- 仓库实测：`alpha=1`, `beta=6`；
- β 取得这么大（6），就是在说：**"框要准"比"分类要对"重要得多**。

**TAL（Task-aligned Assigner）**：对每个 GT，把所有层、所有位置按对齐度排序，取 **top-k=13** 个当正样本。**"分类好且框准"的点优先获得监督。**

> [!important] TOOD 的完整机制（交互特征提取、层注意力、预测对齐、TAL 全流程）在本库另一篇
> 👉 [[09-第8讲-TOOD检测头精讲]] —— 那一篇是**逐行拆解 TOOD 论文**；
> 这一篇只讲**它在单阶段谱系里解决了什么问题**，别重复读。

**仓库实测的 TOOD 配置（本文检测器）**：

| 项 | 值 | 含义 |
|---|---|---|
| `anchor_type` | `anchor_free` | 走 FCOS 那条路 |
| `initial_assigner` | `ATSSAssigner(topk=9)` | **前 4 个 epoch** 用 ATSS 分配 |
| `assigner` | `TaskAlignedAssigner(topk=13)` | **之后**换成 TAL |
| `initial_epoch` | **4** | 这个"分阶段"是隐藏细节，论文没写 |
| `initial_loss_cls` | `FocalLoss(γ=2, α=0.25)` | 前期分类损失 |
| `loss_cls` | `QualityFocalLoss(β=2)` | 后期换成**质量感知**：用定位质量给分类加权 |
| `loss_bbox` | `GIoULoss(weight=2.0)` | 回归 |
| `bbox_coder` | `DeltaXYWHBBoxCoder(target_stds=[0.1,0.1,0.2,0.2])` | 回归 4 个相对偏移 |

## 6. 第五招：DETR（2020）——干脆取消"谁是正样本"这个环节

**思路：把检测看成"集合预测"。**
- 模型输出固定数量（比如 100）的**查询（query）**，每个查询产出一个框；
- 真值只有几个框 → 用**匈牙利匹配**在预测集合和真值集合之间做**一对一最优匹配**；
- 匹配上的算正样本，其余的算"无目标"。

**于是"样本分配"这个环节被数学最优解直接替代了**——不需要 IoU 阈值，不需要 top-k，不需要 centerness。

**代价：**
1. 早期收敛很慢（Deformable DETR 用可变形注意力加速，DINO 用对比去噪 + 混合查询继续优化）；
2. 小目标弱（query 数量有限、分辨率不足）；
3. 一度慢于同期的 one-stage 很多。

> [!tip] 一句话记住三条线的关系
> - **两阶段**：用 **RPN 先筛**，把候选数量从 1.7 万压到 1000 → 分类头只在少量候选上工作。
> - **单阶段（anchor-free）**：不筛，靠**样本分配规则**告诉每个位置"你该不该负责"。
> - **DETR**：不筛也不靠规则，直接用**最优匹配**把这件事一步做掉。
>
> **三者的共同敌人都是同一个：正负样本失衡 + 小目标样本太少。**

## 7. 五种"样本分配"解法对比（本篇核心表）

| 方法 | 谁来决定正样本 | 阈值 | 对小目标的友好度 | 是否要 NMS |
|---|---|---|---|---|
| 两阶段 RPN + IoU 阈值 | RPN 的 `MaxIoUAssigner` | 固定 0.7 / 0.3 | 中（先筛后分类，质量还行） | 要 |
| 单阶段 anchor-based（RetinaNet） | IoU 阈值 + 大量采样 | 固定 0.5 | **差**（小目标分不到正样本） | 要 |
| 单阶段 anchor-free（FCOS） | 逐点预测 + centerness | 无固定阈值 | 中 | 要 |
| 单阶段动态分配（**ATSS**） | 按 GT 中心的 9 个候选 + IoU 均值 τ | **自适应** | **好** | 要 |
| 任务对齐（**TOOD**） | 对齐度 `cls^α · loc^β` 排序取 top-13 | **自适应** | **最好** | 要 |
| 集合预测（DETR） | 匈牙利匹配（最优解） | 无 | 早期差 | **不要** |

**一句话总结这条演化线：**
> 从"**人定阈值**"（0.5）→ 到"**目标自己定阈值**"（ATSS）→ 到"**按任务需求定**"（TOOD）→ 到"**交给最优匹配**"（DETR）。
> **越往后，越不依赖人调的魔法数字。**

## 8. 落到本文：TOOD 在 CCFA-Net 里的位置

**CCFA-Net 的检测链路（从特征到框）：**

```
图像
 └─ 冻结编码器（ResNet-50 的 S1+S2）──→ S2 特征（浅层，纹理）
 └─ FPN ──→ P3~P7（5 层，stride 8~128）
 └─ ★ MFAM（多尺度 + 前景感知注意力）──→ 前景被加强、尺度被分开
 └─ TOOD 检测头（TAL 样本分配 + 分类/回归解耦）──→ 框
```

**三个要点：**

1. **MFAM 在 TOOD 之前**，所以它改的是"**特征质量**"，不是"样本分配"。它能让 TAL 选到**更好的点**（前景更突出）。
2. **单阶段的"密集预测"发生在 MFAM 之后**——这意味着**小目标的特征在 MFAM 处还有救**。如果是两阶段，proposal 早就定死了。
3. **训练时 TOOD 自己还有"两段式"**（前 4 epoch ATSS，之后 TAL）——这是**论文没写、但配置里写死**的复现要点。

## 9. 常见误解（6 条）

| 误解 | 纠正 |
|---|---|
| "单阶段 = 不用 NMS" | 错。FCOS / ATSS / TOOD **都要 NMS**。只有 DETR 系不用 |
| "anchor-free = 不用尺度先验" | 错。FCOS 靠 **level assignment**（按 stride 分层）承担了尺度先验的职责，只是换了个形式 |
| "Focal Loss 解决了正负失衡，所以 RetinaNet 就没这个问题了" | 错。它只压**损失权重**，没解决**样本分配**（小目标仍然可能一个正样本都没有） |
| "ATSS 就是按 IoU 取 top-k" | 不完全对。**候选是按"离 GT 中心的距离"选的**（保证候选在目标上），IoU 只用来**定阈值 τ**。顺序反了就不是 ATSS |
| "TOOD 只是把 ATSS 的 IoU 换成分数" | 不对。TOOD 换掉的是**评价标准**：从"几何中心度"换成"**分类与定位的综合对齐度**"，还额外做了分类/回归特征解耦 |
| "单阶段精度一定不如两阶段" | 历史上是；现在靠 Focal / ATSS / TAL 已经追平甚至反超，而且快得多。本文就是单阶段（TOOD） |

## 10. 自测题（先自己答，再展开）

> [!question]- Q1 · 单阶段和两阶段，除了"快慢"还有什么**本质**区别？
> **答：** 两阶段有一个**显式的候选筛选**环节（RPN），它把候选从 1.7 万压到 1000，于是"正负失衡"被采样人为拉平；单阶段没有这个筛选，只能靠**密集预测**，于是必须自己解决"谁是正样本"。
> **关键洞察：两阶段用"采样"解决失衡，单阶段用"样本分配规则"解决失衡。**

> [!question]- Q2 · Focal Loss 的 γ=2 具体把什么压下去了？α 又是干什么的？
> **答：** (1-p_t)^γ 压**已经学会的**样本（p=0.99 时降 10000 倍）；α_t 给正负类别不同的**固定**权重（正 0.25 / 负 0.75）。**注意 α 和 γ 是两回事：α 管类别比例，γ 管难易程度。**

> [!question]- Q3 · 为什么说"FCOS 去了 anchor，但没去掉 NMS"？
> **答：** 因为 FCOS 只是把"框的表示"从 anchor 模板换成逐点回归；**重复框**（同一个目标的多个点都预测了它）依然存在，仍要用 NMS 去重。要去掉 NMS，必须取消"每个位置独立预测"这个前提 —— 那是 DETR 的集合预测。

> [!question]- Q4 · ATSS 的第一步为什么**不能**用 IoU 选候选？
> **答：** 因为小目标的候选点 IoU 天生偏低，用 IoU 选会**一个候选都选不出来**（全是背景）。先按"离 GT 中心的距离"选，保证候选**一定落在目标上**；再用 IoU **统计**出这个目标自己的阈值 τ。**顺序：几何 → 统计 → 阈值。**

> [!question]- Q5 · TOOD 的对齐度里 β=6 是什么意思？为什么要取这么大？
> **答：** 对齐度 = `cls_score^α · loc_quality^β`，β=6 表示**"框准"的权重远大于"分类对"**。因为在检测里，框的位置错了，分类再对也没用（IoU 直接掉到阈值以下）。

> [!question]- Q6 · 本文为什么用单阶段的 TOOD，而不是两阶段的 Faster R-CNN？
> **答：** 三个理由：① **小目标友好**——TAL 按对齐度选样本，比固定 IoU 阈值更适合 UAV 的密集小车；② **速度**——单阶段单次前向；③ **可扩展**——MFAM 插在 FPN 与 TOOD 之间，能改特征而不动检测头。
> **再追问一句：** 本文 Table 2 里 Deformable DETR 是 51.5，而消融表里 TOOD baseline 只有 50.8 —— 这个选型其实是可以质疑的（见 [[13-第12讲-批判性评价与可做选题]]）。

> [!question]- Q7 · 用一句话把单阶段的四招串起来
> **答：** 密集预测带来正负失衡 → **Focal Loss** 压背景的损失权重 → **FCOS** 去掉 anchor 的手工先验 → **ATSS** 用自适应阈值代替固定 IoU → **TOOD** 再把评价标准换成"分类与定位对齐度" → **DETR** 干脆用最优匹配取消这个环节。

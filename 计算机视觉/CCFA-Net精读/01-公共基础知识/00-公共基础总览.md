# 📚 公共基础知识 · 总览

> [!note] 这是**公共基础知识**
> 这篇笔记与 CCFA-Net **没有绑定关系** —— 换任何论文、任何项目都用得上。
> 读 CCFA-Net 时它是「地基」；不读这篇论文，它照样是一篇独立的基础课。
> 底部还标了它在**方向知识脉络**里的位置，方便你把单点知识挂回整张地图。

## 一、先搞清楚：什么算"公共基础"，什么算"论文精读"

这是整个知识库最该先分清的一件事。

| | **公共基础轨**（本目录） | **论文精读轨** |
|---|---|---|
| 目录 | `01-公共基础知识/` | `02-CCFA-Net论文精读/` |
| 内容 | **通用技术概念**：卷积、padding、池化、ResNet、mAP… | **这一篇论文的具体内容**：CCDD、CFFM、MFAM、TOOD、Table 8… |
| 换论文会变吗 | ❌ **不会**（换任何论文都得会） | ✅ **会**（换论文全废） |
| 判断标准 | **"我在别的论文里也见过它"** → 公共基础 | **"只有这篇论文才这么设计"** → 论文精读 |
| 学习时机 | **先修**（地基） | 边读边补 |

> [!important] 判据就一条
> **如果一个概念只在这篇论文里出现、换个数据集/模型就没了 → 论文精读。**
> **如果它是一个"工具"，任何网络都能用 → 公共基础。**
>
> 比如：`3×3 卷积`是工具（公共）；`CCDD 里那个 256→48 的 3×3 卷积`是设计（论文）。

> [!tip] 这 14 篇的内在结构
> ```
> 【怎么算】     01 卷积 → 02 padding → 03 池化 → 04 感受野 → 05 上采样
> 【怎么看】     06 空间注意力 → 07 FPN
> 【怎么学】     08 激活函数 → 09 梯度下降/反向传播 → 10 损失函数
> 【长什么样】   11 ResNet → 12 检测与 mAP
> ```
> 上面三条线其实互相咬合：卷积(01)产生特征 → 激活(08)加非线性 → 损失(10)打分 → 反向传播(09)传梯度 → 梯度下降(09)更新权重 → **ResNet(11) 保证这个循环在深网络里不散架** → FPN(07) 把不同尺度的特征交给检测头(12) → 检测头到底属于哪一派、候选框从哪来(13)。

## 七、自测题

1. "公共基础"和"论文精读"最简的判据是什么？举一个正例、一个反例。
2. 为什么"3×3 卷积"是公共基础，而"CCDD 里那个 256→48 的 3×3 卷积"是论文精读？
3. 你正读到 CFFM 那篇讲，卡在"通道池化 vs 空间池化"，应该点开哪几篇？
4. 论文轨那 12 篇顶部为什么也要写「🔗 前置基础」？这不是重复吗？
5. 如果只剩 3 天，你读哪 5 篇？为什么是这 5 篇？

<details>
<summary>👉 自测答案</summary>

**1.** 判据：**换个论文/项目还成不成立**。
- 正例：卷积、padding、ResNet、mAP —— 换任何论文都得会 → 公共基础
- 反例：CCDD、CFFM、MFAM、TAL、λ=0.5 —— 换个数据集就不存在 → 论文精读

**2.** 因为**"3×3 卷积"是一个通用操作**（任何 CNN 都用），而**"256→48 且接 PixelShuffle"是这篇论文为去雾解码器专门设计的通道压缩比例**（48 = 256/4² 这个数字是算出来的：PixelShuffle(4) 要把 48 通道重排成 3 通道的全分辨率图）。前者是工具，后者是设计。

**3.** 打开 [[03-池化基础]]（通道池化 vs 空间池化）+ [[06-空间注意力图]]（CFFM 的空间注意力分支）+ [[01-卷积基础]]（7×7 Conv: 2→1 怎么来的）。

**4.** 不重复，作用相反：
- 论文轨的「前置基础」是**往下游走**（我现在读这篇，需要先懂什么）
- 基础轨的「本文用在哪」是**往上游走**（我学完这个基础，论文哪用到了它）

两条路径覆盖了不同的使用场景，合起来才是"双向可达"。少任何一条，你都只能从一个方向找。

**5.** 卷积（读懂所有数字）、ResNet（本文骨干 + 冻结编码器）、梯度下降与反向传播（联合学习的全部论证基础）、损失函数（`L = L_od + λ·L_dh` 枢纽公式）、检测与 mAP（读懂所有表格）。
理由：这 5 篇是**"不理解就完全读不下去"**的，而 padding/池化/感受野/上采样/注意力/FPN/激活函数属于**"不理解就暂时卡一下、查一下就通"**的。

</details>

## 18.1 它要解决什么问题

论文原文（Sec. 3.4 开头）把 UAV 雾天的两大痛点讲得很直白：

> *"targets in UAV scenarios often exhibit significant scale variations: small objects are easily obscured by haze, while large objects suffer from boundary blurring"*

拆成两个**互相矛盾**的需求：

| 目标 | 现象 | 需要的机制 |
|---|---|---|
| 小目标（远处的小车，几十像素） | 被雾吃掉纹理 | **大感受野**给上下文 + 高分辨率保留 |
| 大目标（近处的卡车） | 边界被雾糊掉 | **大感受野**把完整轮廓框住 |

> 🎯 **比喻**：无人机在 200 米高空拍地面，一辆车可能只有 20 像素，像素上的"车"和"塑料盖"没区别。
> 你不能一直用同一个镜头：看得远的广角镜看不清车，看得清的望远镜找不到车。
> **MFAM 的做法是：同时带上 3/5/7 三档镜头，各看各的，最后投票。**

## 18.2 它挂在网络的哪个位置（Algorithm 1）

论文 Algorithm 1（原文照抄）：

```
 7:  S2        ← Backbone_Layer1-2(I_hazy)      ← 冻结编码器
 9:  F_dehaze, I_rec ← CCDD(S2)                 ← 双出口
10:  F_fuse    ← CFFM(S2, F_dehaze)             ← 跨域融合
12:  {S3,S4,S5}← Backbone_Layer3-5(F_fuse)      ← 深层特征
14:  for k in {3,4,5}:
15:      P_k   ← MFAM(S_k)                      ← ★ MFAM 在这里
18:  B_hat, C_hat ← DetectHead({P3,P4,P5})
```

**三个必须记住的点：**

1. **MFAM 在最末端**，紧挨检测头，前面是 FPN 框架（论文表 12 写的是 "FPN-MFAM"）。
2. **MFAM 的输入是 F_fuse**（CFFM 融合后的特征），**不是**原始雾图特征 —— 也就是说它看到的是"已经被去雾引导过"的特征。
3. **S3/S4/S5 各挂一个独立实例**（三个 MFAM，参数不共享）：

| stage | stride | 特征图尺寸（800×1333 输入） |
|---|---|---|
| S3 | 8 | 100×167 |
| S4 | 16 | 50×84 |
| S5 | 32 | 25×42 |

> ⚠️ **批判**：Algorithm 1 写 `P_k ← MFAM(S_k)`，看起来 MFAM 直接产出金字塔特征；
> 但表 12 叫它 "FPN-MFAM"。**MFAM 到底在 FPN 之前还是之后，论文正文没说清**，复现时两种都试（本文按"MFAM → FPN"实现）。

## 18.3 组件①：多尺度深度可分离卷积（Eq.8）

$$
F_1 = f^{3\times3}_{dw}(F_{in}), \qquad
F_2 = f^{5\times5}_{dw}(F_{in}), \qquad
F_3 = f^{7\times7}_{dw}(F_{in})
$$

**depthwise（深度可分离）到底省在哪：**

| | 普通 Conv 3×3 (256→256) | DWConv 3×3 (groups=256) |
|---|---|---|
| 每个输出通道看几个输入通道 | 全部 256 个 | **只有 1 个** |
| 参数量 | 3×3×256×256 + 256 = **590,080** | 3×3×256×1 = **2,304** |
| 差多少 | — | **省 256 倍** |

> 🎯 **比喻**：普通卷积是"256 个侦探每人把 256 份材料全部读一遍"；
> 深度可分离是"每个侦探只读自己那一份材料"（空间相关性），最后再让 1×1 卷积去"横向交换信息"（通道相关性）。
> 论文最后正是用 1×1 卷积做这个交换（Eq.12）。

**论文明确写了三个参数：**
- **expansion ratio = 1**（通道数不变，不扩张）
- **dilation rate = 1**（不是空洞卷积，是实打实的大核）
- 三个分支**并行、互不交互**

**每个分支给感受野加多少（原图像素）：**

| stage | stride | 3×3 | 5×5 | 7×7 |
|---|---|---|---|---|
| S3 | 8 | +16 | +32 | +48 |
| S4 | 16 | +32 | +64 | +96 |
| S5 | 32 | +64 | +128 | +192 |

（计算：贡献 = (核大小 − 1) × 该 stage 的 stride，见 [[04-感受野深度理解]]）

> ⚠️ 注意：S5 上 7×7 只加 192 px，而 S5 本身理论 RF 已有 427 px ——
> **大核在小目标那一层（S3）其实"性价比"最高**：只加 48 px 就能把一个 91 px 的视野撑到 139 px。

## 18.4 组件②：轴向上下文建模（Eq.9–10）

$$
H_p = Pool_h(F_{in}) \in \mathbb{R}^{C\times1\times W}, \qquad
V_p = Pool_v(F_{in}) \in \mathbb{R}^{C\times H\times1}
$$

$$
F_g = H_p \oplus V_p
$$

**两个池化在 PyTorch 里怎么写：**

```python
self.pool_h = nn.AdaptiveAvgPool2d((1, None))   # (C,H,W) -> (C,1,W)  每列的纵向平均
self.pool_v = nn.AdaptiveAvgPool2d((None, 1))   # (C,H,W) -> (C,H,1)  每行的横向平均
```

**⊕ 是"广播相加"，不是拼接：**

- `H_p` 形状 (C,1,W) → 沿 **H** 方向复制 H 份
- `V_p` 形状 (C,H,1) → 沿 **W** 方向复制 W 份
- 相加 → (C,H,W)

> 🎯 **比喻**：H_p 是"每一列的纵向平均成绩单"（比如"第 5 列整条路的平均亮度"），
> V_p 是"每一行的横向平均成绩单"（"第 3 行的平均亮度"）。
> 两者相加 = **每个位置都同时知道"我这一整行"和"我这一整列"的整体情况**。
> 这就是为什么它叫**坐标（coordinate）**注意力：它保留了"行/列"这个空间坐标信息，
> 而不是像 SE 那样把空间维全压掉。

**为什么用"加"而不是"concat"？**
- concat 需要后续 1×1 卷积再融合，会多花参数；
- 加法直接、可解释：**F_g(i,j) = 该列的平均 + 该行的平均**。
- 代价：加法把两个方向的信息混在一起，不如 concat 可分离 —— 但省参数。

> 📌 **注意区分两种池化**（见 [[03-池化基础]]）：
> 本文这里池化的是**空间维的两个轴**（保留 C 和一个空间维），
> 而 CFFM 里的池化是**通道维**（得到 1 个通道）。两者形状与作用完全不同，别混。

## 18.5 组件③：条带卷积标定 → 前景显著图 δ（Eq.11）

$$
\delta_C(A) = \sigma\Big(f^{1\times k}\big(\mathrm{ReLU}(f^{k\times1}(F_g))\big)\Big), \qquad k = 11
$$

**逐层拆开：**

| 步骤 | 运算 | 形状变化 | 说明 |
|---|---|---|---|
| 1 | `f^{11×1}` | (C,H,W) → (C,H,W) | 竖条：沿**高度**聚合 11 行 |
| 2 | `ReLU` | 不变 | 引入非线性，去掉负值 |
| 3 | `f^{1×11}` | (C,H,W) → (C,H,W) | 横条：沿**宽度**聚合 11 列 |
| 4 | `Sigmoid` | 不变 | 压到 (0,1)，**成为权重** |

**关键：δ 的形状是 (C,H,W)，不是 (1,H,W)。**

> 这意味着：**每个通道都有一张独立的"哪里是前景"的热力图**。
> 对比 CBAM 的空间注意力只有 (1,H,W)（整张图共用一张）——
> **MFAM 的表达力更强，但参数量也高得多**（下面算账）。

**两个论文写明的设置：**

- **通道压缩比 r = 1** → 中间层通道数**不压缩**（256 → 256 → 256）。
  论文理由："avoiding information loss"（避免信息丢失）。
- **为什么是 11？** 论文**没解释**。合理推测：奇数保证 padding=5 时尺寸不变且中心对称。
  （对比：Coordinate Attention 原文用的是 7×7 / 1×7。）

> ⚠️ **批判**："11" 是一个**没有敏感性分析支撑的经验值**。审稿人一定会问：为什么不是 5、7、15？

## 18.6 组件④：多尺度融合 + 残差（Eq.12–13）

$$
F_{fuse} = f^{1\times1}\big([F_1 \odot \delta,\; F_2 \odot \delta,\; F_3 \odot \delta]\big)
$$

$$
F_{out} = F_{fuse} + F_{in}
$$

- `⊙` 是**逐元素相乘**：同一张 δ 同时调制三个尺度 → **前景在三个尺度上一起被点亮，背景在三个尺度上一起被压暗**。
- `[...]` 是**通道维拼接**：3 × 256 = 768。
- `f^{1×1}` 把 768 压回 256，并**完成通道间的信息交换**（深度可分离卷积不做这件事）。
- `+ F_in` 是**残差**：原始特征直接加回来，保证模块"只做增强、不破坏"。

> 🎯 **比喻**：三个放大镜拍到三张照片，先用同一张"标注了车在哪"的滤镜把每张照片里的车提亮、背景压暗，
> 然后把三张照片**叠在一起**（1×1 卷积 = 决定每个位置每个通道各取多少），
> 最后**把没滤镜的原图垫在底下**（残差），保证细节一点不丢。

## 18.7 参数账（本机实测，`work/practice/ccfa_modules.py`）

![[附件/MFAM参数分布.png]]

| 子模块 | 参数量 | 占比 |
|---|---|---|
| 条带卷积 11×1 + 1×11 | **1,441,792** | **86.9%** |
| 融合 1×1 Conv（768→256） | 196,864 | 11.9% |
| DWConv 7×7 | 12,544 | 0.8% |
| DWConv 5×5 | 6,400 | 0.4% |
| DWConv 3×3 | 2,304 | 0.1% |
| **单个 MFAM 实例合计** | **1,659,904** | 100% |
| **× 3 个实例（S3/S4/S5）** | **4,979,712** | **占整网 36.61M 的 13.6%** |

> [!warning] 这里有个**反直觉但很重要**的结论
> **"多尺度"其实非常便宜（三个 DWConv 加起来才 2.1 万），真正吃参数的是那条"注意力"支路（占 87%）。**
> 原因：条带卷积是**普通卷积**（256→256，groups=1），参数量 = 256×256×11 × 2。
> 如果把 r 从 1 改成 4（中间层压到 64 通道），这一项能降到 ~36 万，**省掉 75% 的参数**。
> 论文选择 r=1 换来的是"不压缩通道"，代价是 4,979,712 个参数。

## 18.8 δ 的"看得见的范围"（我实测的）

![[附件/δ依赖范围十字形.png]]

我写了一个小实验（`work/practice/erf_delta.py`）：取 δ 的中心格 `(12,12)` **反向传播**，
看输入特征图 24×24 里**哪些像素真的影响它**。结果：

- 有梯度的像素：**407 / 576**
- 精确等于：24×11 + 24×11 − 11×11 = **407** ✔

**为什么是十字形？**

1. `F_g` 来自**全局平均池化** → 所以 `H_p` 里的每个元素已经"看过整列"、`V_p` 里每个元素已经"看过整行"；
2. `11×1` 竖条把**上下 5 行**的 F_g 混在一起 → `1×11` 横条把**左右 5 列**混在一起。

所以 δ(i,j) 依赖的是：
- **横带**：第 i−5 ~ i+5 行的**整行**（所有列）
- **竖带**：第 j−5 ~ j+5 列的**整列**（所有行）

> 🎯 **比喻**：这就像站在十字路口的监控摄像头。
> 它不看"斜对面那个像素"，但**整条横马路和整条竖马路**的人流它都统计得到 ——
> **保留了方向信息（这点比 SE 强），又拿到了全局视野（这点比局部卷积强）**。
> 这正是"坐标/轴向注意力"三个字的含义。

## 18.9 血缘：这个模块不是从零发明的

> [!danger] 重要发现：论文**没有引用** Coordinate Attention
> 全文参考文献里搜 "Hou" / "coordinate" / "strip pooling" —— **零命中**。
> 但 MFAM 的 Eq.9–11 与 **Coordinate Attention**（Hou et al., *CVPR 2021*）
> 在结构上高度相似；条带卷积的思想更早见于 **Strip Pooling / SPNet**（Ho et al., *ICCV 2019*）。

**与 Coordinate Attention 的逐项差异：**

| 步骤 | Coordinate Attention (CA) | 本文 MFAM |
|---|---|---|
| 轴向池化后 | **Concat** → 1×1 Conv → BN → swish | **广播相加**（无 conv、无 BN） |
| 条带核 | 7×1 / 1×7 | **11×1 / 1×11** |
| 激活 | BN + h-swish | **ReLU** |
| 通道压缩比 | r = 16 | **r = 1** |
| 输出用途 | 与输入广播相乘（通道注意力式） | 作为**空间×通道显著图**去调制三个尺度分支 |
| 加回残差 | δ 内部 + 输入 | 模块末尾 `F_fuse + F_in` |

**三大注意力流派对比（务必分清，这是审稿高频考点）：**

| 模块 | 池化维度 | 输出形状 | 回答的问题 |
|---|---|---|---|
| **SE**（Hu et al., CVPR 2018） | 空间维 → 压成 1×1 | (C,1,1) | "**哪个通道**重要" |
| **CBAM**（Woo et al., ECCV 2018） | 通道维 + 空间维 | (1,H,W) | "**哪个位置**重要" |
| **Coordinate Attention**（Hou et al., CVPR 2021） | 两个轴各留一维 | (C,H,W) | "**哪个位置的哪个通道**重要" |
| **本文 MFAM 的 δ** | 同 CA | (C,H,W) | 同上，但用 11 长条 + 广播相加 + r=1 |

> 💡 **CFFM 用的是 CBAM 式空间注意力（99 参数），MFAM 用的是 CA 式坐标注意力（144 万参数）**——
> 同一个论文里两种注意力流派都用到了，别搞混。

## 18.11 批判性评价（8 条，请带着这些去读论文/做汇报）

1. **血缘未标注**：与 Coordinate Attention（CVPR 2021）高度相似却未引用，也未引用 Strip Pooling（ICCV 2019）。这是最硬的一条。
2. **参数代价与收益不匹配**：MFAM 花 13.6% 的参数（498 万）换来 +1.9 mAP；CFFM 花 **99 个参数**换来 +0.6。按"每百万参数的收益"算，CFFM 完胜。**但三个模块不独立，不能简单归因。**
3. **全文无方差**：所有提升在 0.5–1.9 mAP 之间，TOOD 类检测器单次训练波动常在 ±0.3–0.5，**没有 ±值就没法说这些提升是显著的**。
4. **r=1 不做通道压缩**：87% 参数压在两个条带卷积上，r=4 就能省 75%。
5. **核长度 11 无敏感性分析**：论文没解释为什么不是 5/7/15。
6. **FAAB 没有定义**：消融表里的 "FAAB (Foreground-Aware Attention Block)" 只在表格里出现，**正文从头到尾没有定义它的确切结构**，复现者只能靠猜。
7. **不报分尺度指标**：MFAM 的核心卖点是"尺度自适应"，但论文**只报 Car/Truck/Bus 的类别 AP，不报 AP_s / AP_m / AP_l**，无法直接证明它改善了尺度适应。
8. **MFAM 与 FPN 的先后顺序不清**：Algorithm 1 与 Table 12 表述不一致（见 18.2）。

> 📌 **如果这是你的选题方向**：第 1 条（血缘）、第 7 条（缺 AP_s/m/l）是最容易做出增量的两个口子——
> 比如做"MFAM + 真正报分尺度 AP"的对比，或者把 r 压到 4 做等参数效率对照。

## 18.12 复现：我按论文公式写的实现（可直接抄）

> ⚠️ 官方仓库 `CCFA-Net-main` **没有开源这三个核心模块**（`grep -rl 'MFAM\|CCDD\|CFFM'` 零命中，仓库实为 HazyDet 的 fork），
> 下面这份是**我照论文公式逐条实现并在本机跑通**的（`work/practice/ccfa_modules.py`）。

```python
import torch, torch.nn as nn

class StripAttention(nn.Module):
    """论文 Eq.9 / Eq.10 / Eq.11"""
    def __init__(self, channels=256, k=11):
        super().__init__()
        self.pool_h = nn.AdaptiveAvgPool2d((1, None))    # (C,H,W) -> (C,1,W)
        self.pool_v = nn.AdaptiveAvgPool2d((None, 1))    # (C,H,W) -> (C,H,1)
        self.conv_v = nn.Conv2d(channels, channels, (k, 1), padding=(k // 2, 0), bias=False)
        self.conv_h = nn.Conv2d(channels, channels, (1, k), padding=(0, k // 2), bias=False)
        self.act = nn.ReLU(inplace=True)

    def forward(self, x):
        fg = self.pool_h(x) + self.pool_v(x)              # 广播相加 -> (C,H,W)
        y = self.act(self.conv_v(fg))                     # 11×1 竖条
        y = self.conv_h(y)                                # 1×11 横条
        return torch.sigmoid(y)                           # δ (C,H,W) ∈ (0,1)


class MFAM(nn.Module):
    """论文 Eq.8 / Eq.12 / Eq.13"""
    def __init__(self, channels=256, kernels=(3, 5, 7), strip_k=11):
        super().__init__()
        self.dw_convs = nn.ModuleList([
            nn.Conv2d(channels, channels, k, padding=k // 2,
                      groups=channels, bias=False)        # groups=C -> 深度可分离
            for k in kernels
        ])
        self.attn = StripAttention(channels, strip_k)
        self.fuse = nn.Conv2d(channels * len(kernels), channels, 1)

    def forward(self, x):
        feats = [dw(x) for dw in self.dw_convs]           # F1, F2, F3
        delta = self.attn(x)                              # δ (C,H,W)
        feats = [f * delta for f in feats]                 # 同一个 δ 调制三个尺度
        out = self.fuse(torch.cat(feats, dim=1))         # (3C,H,W) -> (C,H,W)
        return out + x                                    # 残差
```

**自检要点：**

- `AdaptiveAvgPool2d((1, None))` 和 `((None, 1))` **千万别写反** —— 写反了形状仍能跑通，但语义全错（这是复现静默出错的典型）。
- `padding` 必须与核大小匹配：`(k//2, 0)` 和 `(0, k//2)`，否则输出尺寸会变。
- `groups=channels` 是 depthwise 的唯一开关，漏了它参数直接多 256 倍。

条带卷积参数量 ≈ 2×(64×256×11) + (64×256) ≈ 360,448 + 16,384 ≈ 37.7 万，
**加上融合层 19.7 万，总计约 57 万，比原来的 166 万省约 65%**。
三个 DWConv 分支本来就是逐通道独立运算，**与通道数无关，所以完全不受 r 影响**。

**5.** 残差在**最后一步**（Eq.13）。去掉后：(a) 原始特征信息被 1×1 卷积重写，细节可能丢失；

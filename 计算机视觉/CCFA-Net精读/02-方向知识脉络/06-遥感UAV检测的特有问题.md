## 6.1 为什么遥感/UAV 是"另一类"检测

| | COCO 自然图像 | UAV / 遥感图像 |
|---|---|---|
| 相机 | 地面/人眼视角 | **空中俯视** |
| 目标尺寸 | 中等 | **小**（车只占几十像素） |
| 目标密度 | 稀疏 | **密集**（停车场、路口） |
| 尺度变化 | 小 | **极大**（飞行高度变化） |
| 遮挡 | 常见 | **树冠遮挡、密集车辆互相挡** |
| 天气 | 多云晴天 | **雾霾是常态** |
| 视角 | 单一 | 训练是 UAV，部署可能地面监控 |

> [!important] 这张表就是本文的"问题清单"
> 本文声称解决三个 UAV 特性：**雾 / 低对比度**、**前景模糊**、**尺度剧烈变化**。
> 下面逐条看通用方法怎么应对，以及它们各自的边界。

---

## 6.2 问题一：小目标

### 难在哪

| 难点 | 原因 |
|---|---|
| **特征丢失** | 下采样几次后，小目标在特征图上只剩几个格子，甚至被背景淹没 |
| **定位极敏感** | 一个 20×20 的框偏移 5 像素，IoU 就从 0.8 掉到 0.4 |
| **正样本极少** | 每个特征图位置上只有极少数是小目标正样本 |

### 通用解法

| 方法 | 做法 |
|---|---|
| **FPN / 多尺度** | 在 P3(8)、P4(16)、P5(32) 都在检测，小目标靠高分辨率层（P3） |
| **SAHI** (WACV 2022) | 推理时把大图**切片**成重叠小块分别检测再合并 |
| **SSTD** (ACM MM 2019) | **空间-尺度分离**的 anchor 分配 |
| **ATSS / TOOD** | **动态**正样本分配（不靠固定 IoU 阈值） |
| **更深的浅层特征** | 本文用**冻结的 S2（stride 4）** 送进 CCDD，保留高分辨率纹理 |

> [!note] 本文的一个可改进点
> 论文**没有报告 AP_small / AP_medium / AP_large**（COCO 标准会拆开报）。
> 而 UAV 场景恰恰是**小目标为主** —— 所以"54.6 到底在小目标上表现如何"是**未知**的。
> **这是最容易补、也最该补的实验。**

---

## 6.3 问题二：尺度剧烈变化

**来源**：无人机飞行高度变化 → 同一个类别的像素尺寸跨数量级。

| 解法 | 做法 |
|---|---|
| **FPN** | 不同层对应不同尺度，**一个尺度对应一层** |
| **Anchor-free + 距离回归** | FCOS 式：每个位置直接预测到框边距离，**天然尺度无关**（因为距离是连续值） |
| **TridentNet** | 三个不同空洞率的分支 |
| **本文 MFAM** | 3/5/7 **三个卷积核**同时看，打破"一层=一个尺度" |

> 🎯 **比喻**
> FPN 像"**分档台**：小学生一个队、中学生一个队、大学生一个队"。
> 但如果同一个人从 1 米长到 2 米，**分档会失效**。
> MFAM 的多尺度核像"**同时按小/中/大三把尺子量**" —— 不需要分档。

---

## 6.4 问题三：密集与遮挡

| 解法 | 做法 |
|---|---|
| **NMS 调参** | 降低 IoU 阈值（但会误删密集车辆） |
| **NMS-free** | DETR 式集合预测，**一对一无需 NMS** |
| **RepPoints / FCOS** | 用点集合表示目标，天然适合密集 |
| **本文 TOOD 的 TAL** | 动态选正样本，避免密集场景里 NMS 误删 |

> [!important] 密集场景是 NMS 的重灾区
> 停车场里 20 辆车挨着，框之间 IoU 可能超过 0.5 → **NMS 会把挨着的车删掉**。
> 这就是 NMS-free 路线（DETR / RT-DETR）兴起的原因。

---

## 6.5 问题四：旋转框（遥感特有）

**为什么**：遥感图像里的车辆、船只**朝向任意**，用水平框（axis-aligned）会包含大量背景。

| 方法 | 年份 | 做法 |
|---|---|---|
| **R3Det** | ICCV 2019 | 旋转框 + 旋转 NMS |
| **S2A-Net** | CVPR 2020 | 先水平框再转旋转框，**渐进式** |
| **MMRotate / MMRot** | 2020 | 统一旋转检测框架 |
| **PSC / GWD** | 2021+ | 高斯/最优传输度量，**用高斯 Wasserstein 距离替代 IoU** |

> [!note] 本文为什么用水平框
> HazyDet 是**合成的**，标注是水平框；CCFA-Net 全程用**水平框 + 标准 TOOD**。
> 这是一个**明确的取舍**：模型简单、可复现，但在真实遥感旋转密集场景会吃亏。

---

## 6.6 问题五：跨视角 / 跨高度

| 现象 | 本文数据 |
|---|---|
| UAV 视角训练 → UAV 视角测试 | HazyDet 54.6、VisDrone-Hazy 42.6 |
| UAV 视角训练 → **地面视角**测试 | **DroneVehicle 27.7** |

**为什么会掉这么多？** 视角变了 → 目标外观、尺度、遮挡关系全变 → 域差距。

> 🎯 **比喻**
> 同一只猫，你从**正上方拍**和从**侧面拍**，猫的样子完全不同。
> 一个只见过俯视图的检测器，见了侧视图就"认不出来了"。

> [!important] 这是可以发论文的方向
> 本文的 **27.7（DroneVehicle，跨视角）** 是一个明确的弱项。
> 如果能做一个"视角鲁棒的 UAV 检测器"，就是一个有价值的贡献。

---

## 6.7 遥感特有的"数据工程"技巧

| 技巧 | 做法 | 代价 |
|---|---|---|
| **切片推理 (SAHI)** | 大图切小块分别检测 | 慢；边界可能重复检测 |
| **旋转增广** | 随机旋转图像 + 标注 | 只对旋转框有效 |
| **尺度增广** | 多尺度 resize +  Mosaic | 训练更慢 |
| **拷贝-粘贴增广** | 把小车"贴"到背景上 | 生成不真实的光照 |
| **长尾处理** | 类平衡采样、Focal Loss | 本文的 Truck 就是长尾 |

## 6.8 自测题

1. UAV 检测相对 COCO 有哪**四个**本质不同？（不限于我列的）
2. 为什么小目标对**定位**特别敏感？给一个数字例子。
3. FPN 和 MFAM 应对尺度变化的思路有什么本质区别？
4. **密集场景下 NMS 会出什么问题？**什么技术路线能绕开它？
5. 本文用了水平框而不是旋转框，这是什么取舍？在什么场景下会吃亏？
6. 本文跨视角到 DroneVehicle 掉到 27.7。**如果要在不改主干的前提下提升它，你会怎么设计？**

<details>
<summary>👉 自测答案</summary>

**1.** 四个本质不同：
- **相机在高空俯视**（视角、投影方式与自然图像完全不同）
- **目标极小**（几十像素）
- **尺度跨数量级**（飞行高度变化）
- **目标密集 + 相互遮挡**（停车场、路口）

补充两个：**天气干扰是常态（雾霾）**、**部署端视角可能不匹配（UAV 训练 → 地面监控）**。

**2.** 小目标的框本来就只有几十像素，**偏移几个像素**相对误差就很大。
例子：一个 20×20 的框，位置偏移 5 像素：
- 偏移 0：完全重合，IoU = 1.0
- 偏移 5：交集 15×20 = 300，并集 25×20 = 500，IoU = **0.6**
- 在 COCO 口径（阈值 0.75~0.95）下**直接判为未命中**。

**3.**
- **FPN**："**分档**"—— 每一层负责一个尺度范围，靠**层的深度**对应尺度
- **MFAM 多尺度卷积核**："**同时量三档**"—— 同一层里 3/5/7 三个感受野并行，再融合，靠**核的大小**对应尺度

前者是"层"级分工，后者是"核"级并行。

**4.** 密集场景里相邻目标的框 IoU 可能超过 NMS 阈值 → **NMS 会把挨着的车当成同一个目标删掉**（漏检）。
绕开路线：**NMS-free 的集合预测**（DETR / RT-DETR），用一对一匹配替代抑制。

**5.** 取舍：**用水平框换取模型简单、可直接复用标准 TOOD 生态、且 HazyDet 标注本身就是水平框**。
吃亏场景：**真实遥感中车辆/船只朝向任意**，水平框会包含大量背景 → IoU 被压低 → 在 COCO 口径（阈值高达 0.95）下判定为未命中 → **mAP 被系统性拉低**。
解法：R3Det / S2A-Net / GWD 等旋转检测路线。

**6.**（开放题，参考思路）
- **① 多尺度训练/推理增广**：训练时随机缩放，推理时 TTA 多尺度 —— 缓解尺度跨数量级
- **② 跨视角增广**：合成地面视角样本（或者用 DroneVehicle 做源域）
- **③ 显式域适应**：把 DroneVehicle 作为目标域做 UDA（本文完全没做）
- **④ 视角不变的特征**：用更浅、更通用的特征（本文的 S2 思路）而不是 S3/S4/S5 的高层语义
- **⑤ 最省事的一条**：把本文的隐式泛化思路和 [[03-域适应域泛化与测试时适应]] 里的 TTA 结合起来

</details>

# 第 1 讲：图像去雾的物理模型与暗通道先验（本文最大的知识空白）

如果你没学过去雾，这篇论文的"去雾"两个字就只是黑箱。补上这一块，后面 CCDD 的每一个设计你都能自己判断合理与否。

## 1.1 大气散射模型：雾霾在物理上干了什么

到达相机的光由两部分组成：
$$
I(x) = J(x) \cdot t(x) + A \cdot (1 - t(x))
$$

|符号|含义|直觉|
|---|---|---|
|$J(x)$|清晰图的辐射亮度|"本来应该看到的画面"|
|$t(x) \in [0,1]$|透射率（transmission）|"这个像素还有多少"自身光"存活"|
|$A$|大气光（airlight）|"空气自己发出来的光"，通常≈雾的亮度|
|$I(x)$|观测到的雾图|我们拿到的照片|

**这个式子告诉我们三件事：**

1. **雾 = 衰减 + 加白纱。** 原本的对比度被 $t$ 压缩，同时被 $A(1-t)$ 抬到一个共同的地板值上。所有像素都往"雾的亮度"聚拢 → **对比度塌缩**。
2. **对比度衰减与距离强相关。** 大气散射系数 $\beta$ 下，$t(x) = e^{-\beta d(x)}$，$d$ 是深度。所以：
    - **近处车** → $t \approx 0.95$ → 几乎不受影响
    - **远处车** → $t \approx 0.3$ → 对比度只剩 30%，边缘糊成一团

👉 **这就是为什么 UAV 场景雾霾特别致命**：无人机高空俯视，**画面里几乎全是"远处"的东西**。不像地面照片有近景"救场"。  
3. **非均匀雾 =逐像素的 $t$ 变化。** 真实雾的 $\beta$ 和 $d$ 都是空间的函数，所以 $t$ 是**一张图**，不是常数。这正是论文反复强调的 "non-uniform haze"。

> 🎯 **比喻**：$t$ 就是"透明度旋钮"。原图 J是一张画，每像素有自己的颜色。雾给每个像素加了一个**灰白色的遮罩**，遮罩浓度 = $1-t$。近处的像素遮罩薄（几乎能看穿），远处的遮罩厚。  
> **去雾算法要做的，就是估计出这张"遮罩浓度图" $t$，然后反解 J。**

## 1.2 暗通道先验（DCP）—— 去雾领域最重要的一个"物理直觉"

**He, Sun, Tang et al., "Single Image Haze Removal Using Dark Channel Prior", CVPR 2009**。这是必读的经典（TPAMI 有扩展版）。它的三条假设：

**假设 1（核心）**：在**无雾图像**的**局部块**中，至少有一个通道的像素值非常小（接近 0）。

\(\min_{y \in \Omega(x)} \min_{c \in \{r,g,b\}} J^c(y) \approx 0\)

> 🎯 **为什么成立？** 看任何一个户外场景的一小块：总有一片的某个颜色通道很暗。
> 
> - 一片草地 → 蓝色通道极暗
> - 一片天空 → 红色通道极暗
> - 一段公路 → 至少一个通道接近 0
> 
> **直觉**：自然界几乎不存在"三个通道都亮"的物体。暗通道是"总有东西很暗"的统计规律。

**假设 2**：**大气光 A 恰好等于局部块里最亮的像素**（常取全图 top-0.1% 亮像素的平均）。

**假设 3**：在**有雾图像**中，**暗通道主要由透射率 $t$ 决定**，而非图像本身内容。

$$
I^{\text{dark}}(x) = \min_c I^c(x) \approx t(x) \quad (\text{假设 } J^{\text{dark}} \approx 0)
$$

**推论（这就是 DCP 的公式来源）**：  
$$
t(x) = 1 - \omega \cdot \min_{y\in\Omega(x)}\left[\frac{\min_c I^c(y) - A^c}{1 - A^c}\right]
$$

其中 $\omega \approx 0.95$ 是"保留一点雾"的系数（纯粹为了视觉自然）。

> 🎯 **比喻**：假设你在浓雾里看一张画布，**最暗的那块颜料色**告诉你"这块地方雾最浓"。因为如果画布本身没有黑色颜料（暗通道先验成立），那看到的黑只能是雾遮的。**暗通道 = 雾的浓度计。**

## 1.3 DCP 的三个致命缺陷（这直接催生了后来的"学习式去雾"）

|缺陷|原因|后来的解法|
|---|---|---|
|**暗通道先验在天空区域失效**|明亮天空本来就无暗像素 → $t$ 被严重低估 → 天空出现"灰黑色块"|加色度/亮度的先验修正（Zhang et al. 2013 等）|
|**"$t$ 只由暗通道决定" 忽略了图像内容**|暗色物体本身也会产生低暗通道值 → **误判为浓雾**|用引导滤波/抠图（Guided Filter, He et al. 2013）细化 $t$|
|**依赖人工先验，对深度/内容耦合不鲁棒**|假设 $t$ 与内容无关，与真实物理不符|**深度学习去雾**：MSCNN → DehazeNet → FFA-Net → DehazeFormer|

**FFA-Net (CVPR 2020)** 是个性化的：直接在特征层做通道注意力，堆了 19 个 FFAs，作者极致地做"特征融合 + 通道注意力"。  
**DehazeFormer (TIP 2023)** 是个性化的：把去雾拆成 **"内容相关"** 和 **"域无关"** 两个并行分支——前者看图像内容（该保留什么），后者看域信息（雾的统计特性）。

> 🎯 **记住这个"双域"思想**——它是理解 CCFA-Net 的关键伏笔：  
> DehazeFormer 说："我既要知道**这张图里有什么**（内容域），也要知道**雾长什么样**（域信息），两个都得建模。"  
> CCFA-Net 说："我干脆**不要图**，我只要**特征**，而且我要**检测器来告诉我该关注什么**。"→ 把"内容相关"这一路，**外包给检测损失**去学。

## 1.4 合成雾是怎么造的（这直接决定 HazyDet 的性质）

**造雾 =挑一张清晰图 $J$ + 一张深度图 $d$ + 参数 $(\beta, A)$ → 用散射模型合成。**

\(I_{hazy}(x) = J(x)e^{-\beta d(x)} + A\left(1 - e^{-\beta d(x)}\right)\)

**三种典型深度图来源：**

1. **Monocular depth estimation**（如 MiDaS）估计单目深度
2. **数据集自带深度**（如 NYUv2、SUN RGB-D）
3. **语义分割 → 假设每类物体有固定深度**（Cars 远、树中等、路面前）

> 👉 **HazyDet（本文数据集）来自 Feng et al. 2024，名字里就带 "depth-cues"** —— 它**带深度线索**构造的合成雾基准。这是理解其数据性质的关键词。

**⚠️ 但合成雾与真实雾有本质差距，这才是全文最重要的一个数：**

||合成雾（HazyDet）|真实雾（RDDTS / DroneVehicle）|
|---|---|---|
|$t$ 的空间分布|由深度决定，**平滑连续**|非均匀、有**局部浓雾团**（如烟囱口飘出的雾）|
|大气光 $A$|全图统一或简单渐变|随高度/方位变化，**有颜色偏**（城市雾偏黄）|
|合成方式|无噪点、无雨滴、无运动模糊|叠加了**噪声、雨、模糊、低照度**|
|结果|**检测器 mAP 51.5%**|**检测器 mAP 25.9%**|

> 🎯 **这就是"合成→真实腰斩"的原因**。它和你在机器学习里学到的"train-test distribution shift"是同一回事，只是这里的 shift 来自**物理成像过程**，比"风格迁移"更根本。

**一个重要的研究直觉**（本文的 MFAM 正面处理了它）：  
真实雾是**非均匀**的 → 同一个图像的不同区域，可靠性差异极大 → **不能用一套全局参数处理全图** → 所以需要**空间自适应**的模块（CFFM 的逐像素门控就是为此）。

## 2.2 ⚠️ 论文的 Layer 编号 ≠ 标准 ResNet 编号（**这是个坑**）

论文 Algorithm 1 里写 `Freeze: frozen encoder (Layers 1–2)` 和 `Backbone_Layer3-5`。但 ResNet-50 只有 layer1–layer4，没有 layer5。**所以作者用的是自己的一套编号**。

**我用三条证据反推出他们的编号：**

|证据|原文|推断|
|---|---|---|
|① 通道数|"CFFM 的两个输入 **both with C = 256**"|S2 必须是 **layer1** 输出（layer2 是 512）|
|② Algorithm 1 行 10|"Fused Feat: **256 × H/4 × W/4**"|S2 stride = **4** → layer1 ✓ 与①一致|
|③ PixelShuffle 上采样因子|"**s = 4**，restores the spatial resolution"|S2 是 1/4 分辨率，×4 正好回到原图 ✓ 与①②一致|

**结论：作者的 "Layer1" = ResNet 的 stem（conv1+pool），"Layer2" = ResNet 的 layer1，"Layer3" = layer2，"Layer4" = layer3，"Layer5" = layer4。**

于是：

- 冻结编码器 = stem + layer1 → 输出 **S1**(stride2), **S2**(stride4, 256ch)
- Backbone Layer3-5 = layer2/3/4 → **S3**(stride8,512ch), **S4**(stride16,1024ch), **S5**(stride32,2048ch)
- 论文图里 S3/S4/S5 → MFAM → P3/P4/P5 → DetectHead，正好构成一个**标准的8/16/32 三尺度金字塔**

> 🎯 **教学点**：当你读论文遇到命名混乱时，**用通道数和 stride 反推**，而不是相信论文的命名。这是从"读懂"到"审稿"的分水岭。

## 2.4 PixelShuffle 的数学（很多人在这里卡住）

**PixelShuffle(r)**: 输入 $(B, C, H, W)$ → 输出 $(B, C/r^2, H\cdot r, W\cdot r)$

**原理**：把 $C$ 个通道重排成 $r\times r$ 的空间网格。  
设 $C = C' \cdot r^2$，则把通道索引写为 $c = c' \cdot r^2 + i\cdot r + j$（$i,j \in [0,r)$），输出图为：  
\(O[b, c', h\cdot r + i, w\cdot r + j] = I[b, c'\cdot r^2 + i\cdot r + j, h, w]\)

**用回本文**：要从 stride-4 的特征图恢复全分辨率 RGB：

- 需要 $C = 3 \times 4^2 = 48$ 通道 → 所以重建前的 3×3 卷积是 **256 → 48**
- PixelShuffle(4): $48 × 200 × 334$ → $3 × 800 × 1332$

> 🎯 **比喻**：PixelShuffle 像把 48 张"小特写"（每张 200×334）**按 4×4 的方式重新铺排**成一张大图（800×1332）。它不像双线性插值那样"编造"中间像素，而是**重新分配已有的信息**——所以比插值更能保住真实纹理。这也是 SR 领域（ESPCN/EDSR）用它替代反卷积的原因。

**⚠️ 实操细节**：$1333 \times 4 = 1332 \neq 1333$。**1333 不能被 32 整除**，这会在实现里造成 off-by-one。工程上更常见的是用 **1344×800** 或 **1280×800**。你在复现时会踩到这个坑，先记住。

## 2.5 用参数量反推 MFAM 的内部结构（一个漂亮的"逆推"练习）

论文只说 MFAM 里 "C = 256"，但没说 C=256 从哪来。**我们从表 7 的 36.61M 参数反推。**

**CCDD 参数量（精确）**：

- RFEB: $3 \times (3\times3\times256\times256 + 256) = 3 \times 590{,}080 = 1{,}770{,}240$；×2 块 = 3,540,480
- 重建卷积: $3\times3\times256\times48 + 48 = 110{,}640$
- **CCDD ≈ 3.65M**

**CFFM 参数量**：7×7 卷积，输入 2 通道输出 1 通道 → $7\times7\times2\times1 + 1 = \mathbf{99}$ 个参数。**几乎为零**（因为它是纯逐像素操作）。

**MFAM 参数量**：MFAM 作用在 S3/S4/S5 上，通道是 512/1024/2048。但论文说 "C = 256"、且输出 P3/P4/P5 是标准 FPN 的 256 通道 → **必然存在一个 1×1 投影把 backbone 通道降到 256**。按此假设：

|部分|参数量|
|---|---|
|投影 512→256, 1024→256, 2048→256|131K + 262K + 524K = 0.92M|
|DWC 3×3+5×5+7×7 (C=256)|256×(9+25+49) = 21.2K /层 × 3 = 0.06M|
|条带卷积 DWC 11×1 + 1×11|256×11×2 = 5.6K /层 × 3 = 0.017M|
|融合 1×1 Conv (768→256)|196.6K /层 × 3 = 0.59M|
|**MFAM 合计**|**≈ 1.59M**|

**总计预测**：基线（TOOD/FCOS R50 ≈ 32.11M）+ CCDD 3.65M + MFAM 1.59M + CFFM 0.0001M ≈ **37.35M**，论文报 **36.61M**。✅ **对得上（差 0.7M，在 TOOD head 与 FCOS head 的结构差异范围内）。**

> 🎯 **教学点**：**论文的参数表是可以被你自己验算的**。验算不通过时，不是论文错了，而是你的理解有偏差——**两种情况都是收获**。

# 第 3 讲：Lipschitz 不匹配到底在说什么（本文的理论卖点，也是最容易读糊的地方）

## 3.1 严格定义

函数 $f:\mathbb{R}^n\to\mathbb{R}^m$ 是 **$L$-Lipschitz** 的，若：  
\(\|f(x_1) - f(x_2)\|_2 \le L\|x_1 - x_2\|_2 \quad \forall x_1,x_2\)

**直觉**：把输入改动 $\delta$，输出最多改动 $L\delta$。$L$ 越小 → 函数越"温和/平滑"；$L$ 越大 → 越"敏感/陡峭"。

**网络里的常见 Lipschitz 常数：**

|层|Lipschitz 常数|
|---|---|
|线性/卷积（核 $K$）|$\|K\|_1$（1-D 核和），$\|K\|_2$（2-D）|
|ReLU|**1**（1-Lipschitz 且分段线性）|
|Sigmoid|≤ 1/4|
|BatchNorm|≤ 1/√... （训练时受 batch 统计影响，推理时是仿射变换）|
|残差块 $x + F(x)$|$\le 1 + \|F\|$|

**复合网络的 Lipschitz 常数是各层常数的乘积** → 层数越多、越"陡"，常数越大。

## 3.2 为什么"高 Lipschitz"对检测器是优点，而对去雾是缺点

**检测器必须高敏感。**  
一个好的检测器要区分"车"和"车旁边的墙面"。这两者在特征空间里的差别可能很小，但必须被放大成"是/不是"的确定判断。

> 🎯 **比喻**：检测器像**显微镜**。它的高倍放大能力（Lipschitz 大）正是它的价值所在——微小差异才能被看清。

**去雾必须低敏感（平滑）。**  
雾霾的物理本质就是**高频成分被大气散射抹平**。去雾算法要做的是把图像"抹平"→ 天然偏好**平滑映射**。

> 🎯 **比喻**：去雾像**磨砂玻璃**。它的低敏感（Lipschitz 小）是它的价值——把刺眼的噪点和锐利细节都磨掉。

## 3.3 冲突在哪里发生（论文的核心论点）

级联流水线：`I_hazy → [去雾器 L≈0.3] → Î → [检测器 L≈50]`

去雾器输出的微小伪影（振幅 $\epsilon$）经检测器放大后 → $50\epsilon$。  
而**真正有用的信号**（"这里有车"的轮廓）本身也被去雾器削弱了一部分。

**结果就是：信噪比被恶化。** 这就是论文说的 "minor artifacts introduced during dehazing may be amplified in the detection stage"。

## 3.4 CCDD 的"正则化"在数学上做了什么

论文原文：

> "CCDD leverages the inherent smooth mapping property of restoration to **suppress high frequency perturbations** that may interfere with detection objectives. This joint optimization introduces an **implicit smoothness prior** on intermediate feature transformations, **regularizing local sensitivity** in the representation space."

**翻译成人话**：

1. CCDD 是卷积 + ReLU 堆叠 → 天然**低频偏好**（ReLU 1-Lipschitz，不放大）
2. 把它**作为一条支路嵌入检测器的特征学习**（而不是串在前面）
3. 联合损失 $L_{od} + \lambda L_{dh}$ 会让这条支路的参数学成一种 **"低通滤波器"** 的角色
4. 结果：检测器拿到的中间特征，其**局部敏感度被驯服**了 → 伪影不再被放大

**类比**：以前是"用磨砂玻璃的照片直接上显微镜"。现在改成"**把磨砂玻璃当作显微镜的补光/滤镜层**用"——它的平滑性反而成了**保护层**，而不是干扰源。

## 3.5 ⚠️ 批判性阅读：这段论述其实**没有严格证明**

作为研究生，你必须意识到论文在这里是**定性的**：

|论文的说法|严格吗？|
|---|---|
|"检测器 Lipschitz 常数高"|⚠️ **未引用任何实测**。检测器是深度网络，整体 Lipschitz 常数通常无法精确计算（只有上界估计，如 Weng et al. 2018 的 spectral norm）。而且一个50 层网络的全 Lipschitz 常数**必然是天文数字**（指数级放大），"高 vs 低"的比较在数值上意义有限|
|"去雾器 Lipschitz 常数低"|⚠️ 更成问题：**去雾网络里也有深层卷积**，理论上的 Lipschitz 常数同样爆炸。论文没有给出任何证据说明"去雾网络的实际 Lipschitz 常数确实低"|
|"因此 CCDD 引入隐式平滑先验"|⚠️ **这是一个直觉，不是证明**。更诚实的说法是："CCDD 用卷积-ReLU 结构提供了一条平滑路径，并在训练中被去雾损失约束为输出**低对比度复原结果**，因此其输出相对于原始输入的**扰动幅度较小**"|

> 🎯 **这就是你能写进自己论文/审稿意见的东西**：  
> "本文以 Lipschitz 连续性解释任务冲突，这是一个有启发性的直觉，但缺乏对各分支实际敏感度的定量测量。**建议作者补充：分别测量去雾分支与检测分支的输入扰动响应（可用有限差分或 Jacobian范数估计），以验证'去雾分支确实降低了检测特征的局部敏感度'这一论断。**"

这正是**研究生该有的阅读姿态**：不是复述作者的论证，而是**判断论证的强度等级**。

# 第 4 讲：多任务损失与梯度冲突（论文没讲，但你写论文必须懂）

## 4.1 联合损失在做什么

\(L_{total} = L_{od} + \lambda\, L_{dh}\)

- $L_{od} = L_{reg} + L_{cls}$：框回归 + 分类
- $L_{dh} = L_{SSIM} + L_1 + L_{grad}$：结构 + 像素 + 梯度

**反传时**：  
\(\frac{\partial L_{total}}{\partial \theta_{shared}} = \frac{\partial L_{od}}{\partial \theta_{shared}} + \lambda\,\frac{\partial L_{dh}}{\partial \theta_{shared}}\)

**注意 CCDD 的参数只从 $L_{dh}$ 拿梯度**（除非有共享层）。所以：

> 🎯 **CCDD 本质上是一个"辅助任务"，它对检测器的影响是间接的**：通过约束共享的冻结编码器（虽然冻结了……）和通过 F_clean 影响 S2 的融合结果。

**这里有个值得追问的点**：既然冻结编码器（不更新），那 $L_{dh}$ 的梯度主要更新谁？→ 更新 **CCDD 自己的参数**（DFEM + 重建卷积）和 **CFFM**（因为 F_clean 流进 CFFM，F_fuse 再流进 backbone）。所以 **$L_{dh}$ 的实际作用是"通过改变 F_clean 的性质来影响检测"**——这是唯一的信息通道。

> 👉 **这是一个你可以自己做的消融**：`冻结 F_clean`（detach）后重新训练，测 mAP 变化。如果掉很多 → 说明 $L_{dh}$ 的梯度确实在塑造 F_clean；如果不掉 → 说明去雾监督是多余的（那 λ=0.5 的结论就要重新审视）。**论文没有做这个消融。**

## 4.2 梯度冲突（Gradient Conflict）

多任务学习的经典难题：两个任务的梯度向量 $g_1 = \nabla L_1$, $g_2 = \nabla L_2$ 可能方向相反。

**度量**：Task Affinity  
\(\text{Affinity} = \frac{g_1 \cdot g_2}{\|g_1\|\|g_2\|} \in [-1, 1]\)

- 接近 +1 → 两任务"同心协力"
- 接近 −1 → **严重冲突**（互相抵消）

**本文的隐含假设**：去雾和检测**应该是同心的**（都想要清晰的结构）。但论文的消融表 13 显示 λ 从 0.5 → 10 时性能下降，这就是**冲突的直接证据**：去雾损失权重太大 → 检测梯度被挤压。

## 4.3 应对梯度冲突的经典方法（**你做自己的论文时会用到**）

|方法|核心思想|出处|
|---|---|---|
|**Uncertainty Weighting**|给每个任务学一个不确定度 σ，自动定权重 $\frac{1}{σ^2}\exp(-L/σ^2)$|Kendall et al., CVPR 2018|
|**GradNorm**|按各任务的**梯度范数**动态调权，让它们"同步变好"|Chen et al., ICML 2018|
|**PCGrad**|梯度冲突时，把 $g_2$ 投影到 $g_1$ 的法平面上做修正|Yu et al., NeurIPS 2020|
|**MGDA / MGDA-UB**|求多任务最优的 Pareto 平衡点|Sener & Koltun, NeurIPS 2018|
|**Temporal Weighting / IMTL**|让困难任务权重随训练上升|综述：[https://arxiv.org/abs/2001.04138](https://arxiv.org/abs/2001.04138)|

> 🎯 **本论文用的是最朴素的做法**：手调固定 λ = 0.5。**这是可以被改进的地方**——用 GradNorm 或 Uncertainty Weighting 替代手工 λ，是一个成本低、故事清晰、实验好做的增量工作。**这就是"读论文 → 找选题"的典型路径。**

# 第 5 讲：评价指标精确计算 + 读表方法论 + 一个复现必查项

## 5.1 AP / mAP 的精确算法（很多研究生算错过）

**Step 1：按置信度排序 → 逐个匹配**  
把所有预测框按置信度从高到低排序。对每个预测框：

- 找**同类**、**IoU 最高**、且**尚未被匹配**的 GT 框
- 若该 GT 存在且 IoU ≥ 阈值 → **TP（真阳性）**，标记 GT 为已用
- 否则 → **FP（假阳性）**

**Step 2：构造 PR 曲线**  
以 Recall 为 x、Precision 为 y，累积 TP/FP 得到 PR 曲线。

**Step 3：AP 的两种算法（数值不同！）**

|方法|计算|特点|
|---|---|---|
|**VOC2007 / 11-point**|取 11 个固定 recall 点求精度均值|粗糙，**已淘汰**|
|**VOC 2010+ / COCO**|连续插值面积：$\text{AP} = \sum_m (r_m - r_{m-1}) p_{\text{interp}}(r_m)$|现在的标准|

**Step 4：mAP@IoU**  
\(\text{mAP} = \frac{1}{C}\sum_{c=1}^{C}\text{AP}_c \quad\text{（在指定 IoU 阈值上）}\)  
\(\text{mAP}_{@[.50:.95]} = \frac{1}{10}\sum_{t \in \{0.50,0.55,...,0.95\}}\text{mAP}_{@t}\)

**Step 5：COCO 面积范围**（论文没报，但 UAV 小目标很关键）

|面积|像素范围|无人机上的含义|
|---|---|---|
|small|< 32²|极小远景车|
|medium|32²–96²|中距离车|
|large|> 96²|近处大巴/卡车|

> ⚠️ **可质疑点 #1**：**论文只报了 [mAP@0.5](mailto:mAP@0.5):0.95，没报 AP_small / AP_medium / AP_large**。而论文自己强调 "scale variation" 是核心动机之一！**如果不报分尺度指标，读者无法验证 MFAM 是否真的改善了尺度适应能力。** 这是个**明显可以补的实验**（TOOD 框架里加 `use_area=true` 就能输出）。

## 5.2 PSNR 和 SSIM 的坑（去雾论文必踩）

**PSNR**：  
\(\text{PSNR} = 10\log_{10}\frac{MAX^2}{\text{MSE}}\)

- 只看**逐像素误差**，**对空间偏移极其不敏感**
- 一张图整体亮度偏了 5 个灰阶 → PSNR 大跌，但人眼看几乎一样
- 一张图被**平移 1 像素** → PSNR 大跌，但内容完全一样

> 🎯 **这就是去雾论文的经典争议**："**去雾指标涨了，检测指标跌了**" 往往就是 PSNR 和下游任务目标不一致的直接后果。

**SSIM (Wang et al. 2004)**：  
\(SSIM(x,y) = \frac{(2\mu_x\mu_y + C_1)(2\sigma_{xy} + C_2)}{(\mu_x^2+\mu_y^2+C_1)(\sigma_x^2+\sigma_y^2+C_2)}\)

三项分别对应：**亮度 l**、**对比度 c**、**结构 s**。

- 局部窗口（论文里用 11×11 高斯窗）
- $C_1=(0.01L)^2, C_2=(0.03L)^2$，$L=255$

> 🎯 **SSIM 的价值**：它对**结构失真**更敏感，对**整体亮度偏移**更宽容。所以本文 CCFA-Net 的 SSIM (0.8588) 最高而 PSNR (24.29) 略低于 DehazeFormer (24.88)，是一个**有意义的信号**：  
> **CCFA-Net 的复原结果在结构上更忠实，但逐像素没那么准。** 而对目标检测来说，**结构（边缘、形状）比逐像素亮度重要得多**。
> 
> 👉 **这正好为论文的核心论点提供了间接支持**：任务目标的差异 → 优化出的解不同 → 不应该用 PSNR 评判一个为检测服务的去雾分支。**论文没有把这层联系讲透，是一个可以自己补强的地方。**

**⚠️ 但要小心**：SSIM 也有问题——**它和 COCO 的 IoU 阈值没有直接关系**，SSIM 0.8588 到底对应多少检测收益？论文没有回答。

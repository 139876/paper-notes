## 1. 研究定位

### 1.1 研究题目

**面向雾天无人机小目标检测的可靠性引导跨场景域泛化研究**

英文暂定：

*Reliability-Guided Cross-Scene Domain Generalization for Hazy UAV Small-Object Detection*

若后续实验明确以 TDRE 动态路由为核心，可将题目进一步收敛为：

*Reliability-Aware Dynamic Routing Enhancement for Cross-Scene Generalization in Hazy UAV Small-Object Detection*

### 1.2 研究目标

针对雾天无人机图像中小目标纹理弱、目标尺度小、场景变化显著，以及图像增强可能引入不可靠细节等问题，研究一种**可靠性感知的动态增强与检测协同机制**，并验证其在严格未见场景中的泛化能力。

### 1.3 研究范式

- **任务范式：** 恶劣天气下的无人机小目标检测。
- **方法范式：** 检测导向的动态图像增强 / 动态路由。
- **核心机制候选：** 恢复可靠性估计与可靠性引导路由。
- **泛化范式：** 源域训练、未见目标域测试的 Domain Generalization（DG）。
- **实验原则：** 先复现、再诊断、后创新。

## 2. 研究背景与问题发现

### 2.1 雾天无人机小目标检测的困难

1. 雾霾造成对比度下降、边缘模糊和目标纹理衰减。
2. 无人机视角下目标通常尺寸较小，信息损失对检测影响更明显。
3. 不同地点、飞行高度、天气和成像条件造成场景分布偏移。
4. 图像增强能够改善可见性，但增强结果未必始终有利于下游检测。

### 2.2 核心研究观察

**图像恢复质量与检测收益并不必然一致。**

增强网络可能在部分区域恢复出不稳定纹理、伪边缘或过度锐化细节。对于小目标检测，这些不稳定信息可能影响分类、定位和误检率。

因此，研究不应只关注“增强得更清晰”，还应关注：

- 当前输入是否需要增强？
- 哪种增强专家更适合当前退化？
- 增强结果是否可靠？
- 增强结果是否真正帮助检测？
- 动态增强策略在未见场景中是否稳定？

## 3. 核心科学问题

### 问题一：动态增强如何避免不可靠恢复信息？

现有动态增强方法能够根据退化或天气条件选择增强策略，但天气类别或退化类型并不能完全代表增强结果的可靠程度。

**研究问题：** 能否将恢复可靠性引入动态路由，使模型不仅判断“当前是什么退化”，还判断“当前增强是否可信、是否值得使用”？

### 问题二：增强决策如何适应未见场景？

训练场景与测试场景可能在地点、背景、飞行高度、雾浓度和目标尺度上存在差异。动态路由可能学习到源域特有的天气或背景线索。

**研究问题：** 如何约束动态路由和增强特征，使其在未见场景中保持稳定，并提升小目标检测性能？

### 核心假设

> 如果动态增强过程能够利用恢复可靠性对专家选择、增强强度或增强特征使用进行约束，那么模型有望减少不可靠增强造成的检测损失，并提高未见场景下的检测稳定性。

该假设需要通过实验验证，不能在复现前视为已成立。

## 5. 拟议技术路线

### 5.1 总体流程

```text
雾天 UAV 图像
      │
      ▼
退化 / 特征表征
      │
      ▼
TDRE 动态增强框架（DR-MoE）
      │
      ├── 专家路由与增强输出
      │
      ▼
增强可靠性评估（拟议模块）
      │
      ├── 可靠性高：允许充分利用增强信息
      ├── 可靠性低：降低增强强度 / 调整路由 / 保留原始信息
      │
      ▼
检测导向特征与任务协同
      │
      ▼
UAV 小目标检测器
      │
      ▼
严格未见场景评估
```

### 5.2 创新候选一：可靠性感知动态路由

在 TDRE 的动态路由基础上，探索加入可靠性信号：

- **输入条件：** 当前图像 / 特征的退化表征。
- **路由条件：** 退化特征 + 恢复可靠性。
- **决策对象：** 专家选择、专家权重或增强强度（具体选择需通过实验确定）。
- **预期作用：** 减少不可靠增强分支对检测特征的干扰。

可靠性信号可从以下候选指标中研究：

1. 多次轻微增强扰动下的特征一致性；
2. 原始与增强特征的局部一致性；
3. 增强输出的预测稳定性；
4. 与检测误差 / 目标区域相关的可靠性校准。

不建议一开始将所有指标组合。先验证哪种可靠性度量与检测错误具有稳定关联。

其中「预测稳定性」「不确定性感知处理」的建模思路可参考 [[paper-notes/论文精读/6-新增待精读文献/03-UDN-不确定性驱动去雾|UDN · 不确定性驱动去雾]]，但需先验证其不确定性指标是否适用于 UAV 小目标检测。

### 5.3 创新候选二：检测导向的可靠性约束

借鉴 TDRE 的检测导向增强思想，进一步研究：

- 可靠性是否与检测损失或目标区域相关？
- 可靠性低的区域是否应降低增强贡献？
- 是否能避免背景增强对小目标检测造成干扰？

该模块可作为候选扩展。若可靠性引导路由本身已取得稳定收益，不必为了模块数量再增加复杂机制。

### 5.4 跨场景泛化策略

优先采用**源域训练、目标域完全未参与训练**的严格 DG 设置。

初期不同时引入多种泛化算法，先通过数据划分和诊断确认路由是否存在域偏移。如果发现明显的场景依赖，再考虑：

- 频域域不变特征学习；
- 源域间一致性约束；
- 类别 / 尺度条件的源域泛化；
- 路由分布稳定性正则。

这些是后续候选，不是当前必须同时实现的模块。

📎 数据集谱系与划分原则见 [[paper-notes/论文精读/0-公共基础知识/07-方向知识脉络/08-遥感基础与数据集谱系|遥感基础与数据集谱系]]；P0–P3 复现优先级与 8 周排期见 [[paper-notes/论文精读/UAV_Research_Plan_Refined_CCFA_TDRE|UAV_Research_Plan_Refined_CCFA_TDRE]]。

### 6.2 第二阶段：错误诊断

重点回答：

- TDRE 的增强是否在所有雾浓度下都有效？
- 哪些路由 / 专家选择容易失败？
- 远距离小目标是否更容易受增强伪特征影响？
- 增强可靠性是否与 FP、FN、定位误差或 AP_small 变化相关？
- 路由是否过度依赖背景、地点或飞行高度？

### 6.3 第三阶段：可靠性模块验证

建议进行以下消融：

| 实验 | 设置 | 验证目的 |
|---|---|---|
| A | TDRE 原始模型 | 动态增强基线 |
| B | TDRE + 普通路由调整 | 验证路由改动本身 |
| C | TDRE + 可靠性估计 | 验证可靠性信号 |
| D | TDRE + 可靠性感知路由 | 验证核心候选方法 |
| E | TDRE + 可靠性感知路由 + 泛化约束 | 验证跨场景增益是否来自泛化机制 |

### 6.4 评价指标

- mAP / AP50；
- AP_small（若数据集与评价工具支持）；
- Recall；
- FP / FN；
- 不同雾浓度下的性能；
- 不同目标尺度下的性能；
- 未见场景平均性能与最差域性能；
- 路由稳定性、专家利用率及可靠性校准指标（若模块实现）。

📎 完整指标口径（恢复可靠性分组、适用的校准误差、FPS / FLOPs / 参数量 / 推理延迟）见 [[paper-notes/论文精读/UAV_Research_Plan_Refined_CCFA_TDRE|UAV_Research_Plan_Refined_CCFA_TDRE]] 第 8 节「评价指标」。

### 6.5 严格 DG 数据协议

- 按地点、飞行高度、天气 / 雾浓度或数据采集序列划分域。
- 训练域与测试域应尽量避免相邻帧或近重复图像泄漏。
- 目标域不参与训练、伪标签生成、模型选择或超参数调优。
- 验证集仅来自源域，或来自预先指定的源域验证划分。
- 若使用目标域无标签数据进行适配，应明确标记为 Domain Adaptation（DA），不能称为严格 DG。
- 若数据集元信息不足以支持“未见地点 / 未见高度”等结论，应降低表述强度并说明限制。

## 7. 预期研究贡献（待实验验证）

1. **问题层面：** 分析动态增强在雾天 UAV 小目标检测中的可靠性问题，揭示增强质量与检测收益之间的不一致。
2. **方法层面：** 探索可靠性感知动态路由机制，使增强决策不仅依赖退化类型，还考虑增强信息的稳定性。
3. **泛化层面：** 在严格未见场景设置下评估动态增强路由的稳定性与检测收益。
4. **实验层面：** 建立 TDRE、CCFA-Net 与基础去雾检测方案之间的统一比较和诊断流程。

以上贡献是研究目标，不应在实验完成前写成已证实结论。

## 8. 研究计划与阶段安排

### 阶段一：复现与理解

- 阅读 TDRE 的网络结构、路由机制、损失函数和训练协议。
- 复现 [[paper-notes/论文精读/3-HazyDet精读/00-索引 MOC|HazyDet]] / [[paper-notes/论文精读/3-HazyDet精读/05-DeCoDet原理精读|DeCoDet]] 基础检测器。
- 复现 [[paper-notes/论文精读/1-CCFA-Net精读/00-索引 MOC|CCFA-Net]]，形成雾天 UAV 检测对照。
- 在统一数据划分和评价协议下运行 TDRE。

**阶段产出：** 可运行代码、基线结果表、模块结构笔记。

### 阶段二：问题诊断

- 对不同雾浓度、尺度和场景进行分组评估。
- 分析增强前后检测误差变化。
- 可视化专家路由分布与失败案例。
- 验证可靠性指标与检测错误是否相关。

**阶段产出：** 可靠性问题证据、错误案例、创新模块设计依据。

### 阶段三：方法设计

- 选择有效的可靠性指标。
- 设计可靠性对路由 / 增强强度的调节方式。
- 完成模块消融与稳定性分析。
- 若证据充分，再加入轻量跨场景泛化约束。

**阶段产出：** 方法原型、消融结果、初步论文框架。

### 阶段四：严格泛化评估与论文整理

- 固定源域训练与未见域测试协议。

## 9. 当前最重要的执行原则

**不要先假设可靠性模块一定有效，也不要立即把频域解耦、类别尺度建模和动态路由全部叠加。**

当前最合理的工作顺序是：

1. 复现 TDRE；
2. 复现 CCFA-Net 作为雾天 UAV 对照；
3. 找到 TDRE 在小目标 / 未见场景中的具体失败模式；
4. 验证可靠性指标是否能够预测增强失败；
5. 只有诊断证据支持时，才设计可靠性感知路由；
6. 最后验证其是否真正提升严格跨场景泛化。

**当前主线总结：**

> 以 TDRE 的动态增强与检测协同为方法基础，以 CCFA-Net 为雾天 UAV 检测基线，研究恢复可靠性如何影响动态路由决策，并通过严格未见场景实验验证可靠性感知增强对小目标检测泛化的作用。

# 图论算法速查 · 最短路与路径优化

> [!info] 这页解决什么
> 路径优化类问题的**算法工具箱**。核心是四件事：
> **① 怎么算两点之间最短距离（Dijkstra）→ ② 怎么定访问顺序（TSP）→
> ③ 规模大了怎么办（2-opt）→ ④ 怎么证明我算的是对的（Held–Karp 精确解）**。
>
> 实例见 [[paper-notes/图论综合应用报告/00-索引 MOC|图论综合应用报告]]。

---

## 一、先分清两个层次（最常见的理解错位）

| | **第一层：路网图** | **第二层：配送图** |
|---|---|---|
| 顶点 | 全部交叉口/路口（可几十上百个） | 只有必须访问的特殊点（少） |
| 边权 | 道路实际长度 | **第一层算出的最短路径长度** |
| 问题 | **最短路**（Dijkstra / Floyd） | **TSP**（NN / 2-opt / Held-Karp） |
| 求解 | 精确、无近似 | 规模敏感、需启发式 |

> [!important] 一句话抓住本质
> **"怎么走" 用最短路算 → "先去哪后去哪" 用 TSP 算 → 两者串联才是一套完整方案。**
>
> 直接在第一层做 TSP 是错的：$23! \approx 2.6\times10^{22}$。
> 先用最短路把 23 顶点**压缩**成 7 顶点的完全图，问题规模下降两个数量级。

### 一个直观类比
- **Dijkstra = 问「从 A 到 B 怎么走最近」**（每次问路，累加出全局地图）
- **TSP = 问「7 个快递点按什么顺序送最省腿」**（已经知道两两之间怎么走了）

## 二、Dijkstra：单源最短路

### 一句话
从起点出发，每次选**当前最近**的未确定顶点，把它固定下来，再更新邻居。

### 原理（人话版）
> 你在陌生城市找某地。你不会一次性规划全城路线，而是
> **"先走到目前确认最近的路口，再问那里的人最近的下一个路口"**。
> 每确定一个路口，就把它作为新的起点去更新别人的距离。

### 核心代码
```python
import heapq

def dijkstra(adj, src):
    dist = {v: float("inf") for v in adj}
    prev = {v: None for v in adj}
    dist[src] = 0.0
    pq = [(0.0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:          # 过期条目，跳过
            continue
        for v, w in adj[u].items():
            if d + w < dist[v]:  # 松弛成功
                dist[v] = d + w
                prev[v] = u
                heapq.heappush(pq, (dist[v], v))
    return dist, prev
```

### 复杂度与前提

| 项 | 值 |
|---|---|
| 时间（堆实现） | $O((|V|+|E|)\log|V|)$ |
| 空间 | $O(|V|)$ |
| **前提** | **所有边权非负**（有负权必须用 Bellman-Ford/SPFA） |

### 为什么"贪心"是对的
边权非负 ⇒ 当前距离最小的未确定顶点，最短路不可能再经过未确定的顶点变得更短。
（这正是 Dijkstra 全部正确性的支点。）

### Floyd–Warshall：全源最短路
适合**顶点很少**（<200）、且**要一次性拿到所有点对距离**的场景。
转移：$D^{(k)}[i][j] = \min\big(D^{(k-1)}[i][j],\ D^{(k-1)}[i][k] + D^{(k-1)}[k][j]\big)$，复杂度 $O(|V|^3)$。

> [!tip] 工程建议
> **Dijkstra 当主力，Floyd 当校验。** 实现一遍手写 Dijkstra，
> 再用 NetworkX 的 `single_source_dijkstra_path_length` 交叉验证，
> 偏差应该是 0 或浮点舍入量级 —— 这是论文里"算法实现可靠"最有说服力的证据。

## 三、TSP：访问顺序优化

### 问题定义
$n$ 个城市，找一条**恰好访问每个城市一次并回到起点**的回路，总长度最小。

### 数学模型（0-1 整数规划）
$$\min \sum_i \sum_j d_{ij} x_{ij}$$
$$\text{s.t.}\ \sum_j x_{ij}=1\ (\forall i);\quad \sum_i x_{ij}=1\ (\forall j);\quad \sum_i x_{ij}-\sum_i x_{ji}=0\ (\forall j);\quad x_{ij}\in\{0,1\}$$
子回路消除可用 Miller–Tucker–Zemlin 割变量约束。

### 求解方法全景

| 方法 | 复杂度 | 保证最优 | 适用规模 | 本质 |
|---|---|---|---|---|
| 暴力枚举 | $O(n!)$ | ✅ | $n\le8$ | 枚举所有排列 |
| **Held–Karp** | $O(2^n n^2)$ | ✅ | $n\le15\sim16$ | 状态压缩 DP |
| 最近邻 NN | $O(n^2)$ | ❌ | 任意 | 贪心构造 |
| **2-opt** | $O(k n^2)$ | ❌（局部最优） | 任意 | 局部搜索 |
| 多次重启 2-opt | 同上 | ❌ | 任意 | 工程最常用 |
| GA / ACO / SA | 视实现 | ❌ | 任意 | 元启发式 |

> [!important] 规模感（记牢这个数）
> Held–Karp 状态数 $2^{n-1}\times n$：n=7 → 448 个状态，瞬时；
> n=12 → 约 2.5 万状态，毫秒级；n=16 → 24 万，勉强；**n≥20 基本不可行**。
> 这就是"启发式不是偷懒，是数学上没别的办法"。

## 四、最近邻 NN：最朴素的贪心

```
order = [起点]; U = 其余未访问点
while U 非空:
    下一个 ← U 中距当前点最近者
    order.append(下一个); U.remove(下一个)
```

- **优点**：$O(n^2)$，极快，代码 5 行
- **缺点**：贪心不可回溯，**最后常常要跑一条长回头路**
- 实测：平均最优性损失约 **8%**（见报告实验三）

## 五、2-opt：性价比最高的改进

### 原理（人话版）
> 你已经画好一条环形路线。挑两条边，把它们**剪断、反向接上**。
> 如果总长度变短，就保留；否则换一对再试。

### 改进条件
对回路中两条边 $(i,i+1)$、$(j,j+1)$（$i,j$ 不相邻）：
$$\Delta = \big(d_{ij} + d_{i+1,j+1}\big) - \big(d_{i,i+1} + d_{j,j+1}\big)$$
$\Delta < 0$ ⇒ 改进。**每次剪断会反转一段路径**，所以实现上常用"反向重接"。

### 两种策略
| 策略 | 做法 | 特点 |
|---|---|---|
| first-improvement | 找到第一个改进就接受 | 快，质量略差 |
| **best-improvement** | 枚举所有对，取改进最好的 | 慢一点，质量更稳（本文用这个） |

### 关键工程技巧：多次随机重启
2-opt 对**初始解敏感**。做法：随机生成 N 个初始解，各跑一次 2-opt，取最优。
成本几乎为零，收益通常很明显（报告中 k=20 时相对单次 NN 缩短 20%+）。

### 性质
- **只能保证 2-opt 局部最优**，不保证全局最优
- 但实测：20 组随机实例上平均 Gap ≈ **0%**，20/20 达到精确最优

## 六、Held–Karp：精确解，用来"验明正身"

### 状态定义
$$dp[mask][j] = \text{从起点 0 出发、恰好访问 mask 中的点、最后停在 j 的最小代价}$$

### 转移
$$dp[mask\cup\{i\}][i] = \min_{j}\big(dp[mask][j] + d_{ji}\big)$$
答案：$\min_j\big(dp[FULL][j] + d_{j0}\big)$

### 用途：**不是**用来算大问题的，而是用来当"标准答案"
小规模实例上，Held–Karp 给出**理论上界**，于是可以定义：
$$\text{Gap} = \frac{L_{\text{启发式}} - L_{\text{最优}}}{L_{\text{最优}}}\times100\%$$

> [!tip] 写论文时的黄金三件套
> 1. **暴力枚举**校验 Held–Karp（偏差应为 0）→ 证明精确解实现正确
> 2. **NetworkX** 校验 Dijkstra / Floyd（偏差应为 0）→ 证明最短路实现正确
> 3. 报告 **Gap 曲线** → 证明启发式解质量
>
> 这三步做完，审稿人/老师挑不出算法实现的毛病。

## 七、一套可复用的"路径优化"流水线

```
① 数据采集        真实地图/路网 → nodes.csv + edges.csv（可测量、可核验）
② 建图            加权无向图，权重 = 实际行走长度（非直线距离！）
③ 距离压缩        对每个特殊点跑 Dijkstra → 距离矩阵 D
④ 优化顺序        NN → 2-opt →（多次重启）
⑤ 精确校验        小规模用 Held–Karp + 暴力枚举算 Gap
⑥ 鲁棒性         扰动实验：封闭道路 / 增减节点 / 改分布
⑦ 可视化 + 还原   把"访问顺序"还原成"真实路径段"
```

> [!important] 最容易被扣分的地方
> **权重不能用直线距离。** 真实配送员只能走路，用欧氏距离算出来的答案物理上不可执行。
> 这是"图论建模"和"拿数学题当作业"的分界线。

# 01 · bbox 边界框标注

> [!note] 这是**公共基础知识**
> 这篇笔记与 HazyDet **没有绑定关系** —— 换任何数据集、任何检测器都用得上。
> 它是"检测"这件事的地基：框长什么样、格式怎么换、框在流水线里到底干什么。

> [!tip] 一句话先说清
> **bbox = 用一个矩形框出目标的位置，标注形式就是 4 个数字。**
> 但这 4 个数字有**四种不同的读法**，搞错读法会得到完全不同的框 —— 这是本篇存在的全部理由。

---

## 1.1 一句话定义

> **bbox（bounding box，边界框）= 目标的外接矩形，用 4 个数表示它在图里的位置和大小。**

一个框只需要回答两个问题：

1. **它在哪** → 两个数（位置）
2. **它多大** → 两个数（尺寸）

⚠️ 注意：**"位置和尺寸"怎么编码，有好几种约定** —— 这是所有 bbox  bug 的源头。

---

## 1.2 四种坐标格式（最容易踩的坑）

| 格式 | 写法 | 含义 | 谁在用 |
|---|---|---|---|
| **`xyxy`** | `[x1, y1, x2, y2]` | 左上角 + **右下角** | mmdet 内部、TF Detection API、OpenCV |
| **`xywh`** | `[x, y, w, h]` | 左上角 + **宽高** | **COCO 官方**、YOLO 标签、Kaggle |
| **`xyxyn`** | `[x, y, w, h]`（再除以图宽/图高） | 同上，但归一化到 [0,1] | YOLO 训练标签 |
| **`cxcywh`** | `[cx, cy, w, h]` | **中心点** + 宽高 | 很多检测器内部、CenterNet |

### 同一组数字，四种读法，四个完全不同的框

以 `[100, 50, 180, 120]` 为例：

| 按什么读 | 框是 | 宽 × 高 | 面积 |
|---|---|---|---|
| `xywh` | (100,50) → (280,170) | 180 × 120 | 21600 |
| `xyxy` | (100,50) → (180,120) | 80 × 70 | 5600 |
| `cxcywh` | 中心 (100,50)，→ (10,-10) → (190,110) | 180 × 120 | 21600（**位置完全错了**） |
| `xyxyn` | 需要先知道图宽图高 | — | — |

> [!warning] 同一个数字串，**按 xywh 读和按 xyxy 读，面积差了近 4 倍**。
> 如果你把 COCO 的 `xywh` 直接当 `xyxy` 用（没转换），会得到一堆 `x2 < x1` 的**负面积框**。

### 🎯 比喻

> **xywh 像"说从这走多远、往这走多宽"（相对出发点的位移）；**
> **xyxy 像"报两个门牌号"（绝对坐标）。**
>
> 快递员拿着 `[100, 50, 180, 120]` 这张单子，
> 知道是"从 100,50 出发，运 180×120 的货"（xywh），
> 还是"送到 100,50 和 180,120 这两个门牌"（xyxy）—— 差一票就送错家。

---

## 1.3 格式之间怎么转

```python
# xywh  →  xyxy
x1, y1 = x, y
x2, y2 = x + w, y + h

# xyxy  →  xywh
w, h = x2 - x1, y2 - y1
x, y = x1, y1

# xyxy  →  cxcywh
cx, cy = (x1 + x2) / 2, (y1 + y2) / 2

# xywh  →  xyxyn   (img_w, img_h 为图像尺寸)
x, y, w, h = x/img_w, y/img_h, w/img_w, h/img_h
```

> [!important] **一句话记住**
> **COCO 的 JSON 里是 `xywh`；mmdet 内部是 `xyxy`。**
> 转换**几乎总是发生在"读标注"这一步**，而不是在模型里。
> 你自己写数据加载代码时，**先确认清楚输入是哪种、输出要哪种**。

## 1.4 bbox 在检测流水线里干三件事

| # | 环节 | bbox 在干什么 | 出错的后果 |
|---|---|---|---|
| ① | **标签分配** | 判断哪个特征点 / anchor 负责哪个目标（靠 IoU 阈值或 ATSS 之类的方法） | 正负样本全错 → 学不到任何东西 |
| ② | **回归目标** | 算出模型该预测什么（坐标 or 到四边的距离） | 损失目标错位 → 框永远对不齐 |
| ③ | **评测** | 按 IoU 阈值把预测框和真值框配对，累积成 AP | 指标失真，但**模型其实是好的** |

> [!tip] **为什么这三点要分开想**
> ① 和 ② 是**训练**用的，③ 是**测试**用的。
> 调试时看到"loss 正常但 mAP 是 0"，八成是 **③** 出问题（框的格式或坐标系），
> 模型其实没问题。反过来"loss 是 1.0 一直不动"，是 **①** 出问题。

## 1.5 两种回归范式：anchor-based vs anchor-free

| | **Anchor-based** | **Anchor-free / Point-based** |
|---|---|---|
| 代表 | Faster R-CNN、SSD、RetinaNet | **FCOS、ATSS、TOOD、CenterNet、YOLOv8** |
| 一个位置预测什么 | anchor 的**修正量** `(dx,dy,dw,dh)` | 它到框**四条边的距离** `(l,t,r,b)` |
| 框怎么还原 | anchor + 修正量 | 点 + 4 个距离 |
| 正样本怎么定 | IoU 阈值（>0.5 正、<0.4 负、中间忽略） | 点落在框内即可（FCOS）/ ATSS 自适应 |
| 优点 | 训练稳、成熟、精度高 | 无 anchor 超参、显存省、密集场景友好 |
| 缺点 | anchor 要手调、换分辨率要重调 | 早期小目标密集时容易漏 |

**FCOS 的 ltrb 定义**：

$$
(l,\,t,\,r,\,b)=\left(x-x_l,\;y-y_t,\;x_r-x,\;y_r-y\right)
$$

四边一确定，框就出来了 —— **不需要任何 anchor 模板**。

👉 展开见 [[paper-notes/论文精读/1-CCFA-Net精读/01-公共基础知识/14-单阶段检测与样本分配|14-单阶段检测与样本分配]] §3（FCOS）与 §4（ATSS）。

> [!note] **一个高频误解**
> **"去 anchor" ≠ "去 NMS"。**
> FCOS / ATSS / TOOD 都是 anchor-free，**推理时照样要 NMS 去重**。
> 要彻底去掉 NMS，得等 DETR 那一路。

## 1.6 IoU 家族

$$
\mathrm{IoU}=\frac{\lvert A\cap B\rvert}{\lvert A\cup B\rvert}
$$

| 损失 | 加了什么 | 解决的问题 |
|---|---|---|
| `IoULoss` | — | **两框完全不重叠时梯度为 0**，学不动 |
| `GIoULoss` | $-\dfrac{\lvert C\setminus(A\cup B)\rvert}{\lvert C\rvert}$，$C$ = 最小外接框 | 不重叠时也有梯度 |
| `DIoULoss` | 惩罚**中心点距离** | 收敛更快 |
| `CIoULoss` | 再加**宽高比**一致性 | 形状也对齐 |

👉 展开（含手算与"同一个数被用了 5 次"）见 [[paper-notes/论文精读/1-CCFA-Net精读/01-公共基础知识/12-目标检测基础与mAP|12-目标检测基础与mAP]] §12.3 / §12.3.2。

## 1.7 NMS（非极大值抑制）

同一个目标可能出好几个高分框（不同层、不同位置都看到了它）。
NMS 的做法很朴素：**按分数排序，IoU 超过阈值的只留分数最高的那个，其余删掉。**

- 阈值**太大** → 漏掉相邻的**真目标**（尤其密集小目标）
- 阈值**太小** → 同一个目标的重复框删不干净 → 假正例(FP)变多

> ⚠️ **NMS 是双刃剑**：它对**密集小目标场景**特别不友好。
> 这正是后来要用 TAL / NMS-free（DETR 一路）的原因。

👉 展开（含完整手算、TP/FP/FN 关系、三个变体）见 [[paper-notes/论文精读/1-CCFA-Net精读/01-公共基础知识/12-目标检测基础与mAP|12-目标检测基础与mAP]] §12.4。

## 1.8 bbox vs segmentation 有什么区别

| | **bbox** | **segmentation（mask）** |
|---|---|---|
| 存什么 | **4 个数** | 多边形坐标 / RLE 压缩像素 |
| 标注成本 | 低（拖个框） | 高（描轮廓） |
| 表达力 | 只有外接**矩形** | 精确到像素的轮廓 |
| 能表达"凹陷"吗 | ❌ 不能（细长物体、遮挡物全丢信息） | ✅ 能 |
| 典型任务 | 目标**检测** | 分割 / 实例分割 |
| 存储开销 | 极小 | 极大 |
| 能不能直接喂检测器 | ✅ 可以 | ❌ 得先转成框 |

> [!tip] **两者不是替代关系**
> 分割标注**可以推出** bbox（外接矩形），反过来不行。
> 所以数据集常常"只标框"（便宜）或者"只标掩码"（贵且精确）。
> 想在分割标注上做检测，就先取外接矩形 —— **这一步会丢掉掩码里 30%~50% 的信息**。

## 1.9 COCO JSON 里 bbox 到底怎么存

COCO 官方格式（`annotations` 数组里每个元素的字段）：

```json
{
  "id": 0,
  "image_id": 9114,
  "category_id": 0,
  "bbox": [54, 262, 13, 11],
  "area": 143,
  "iscrowd": 0,
  "segmentation": []
}
```

| 字段 | 含义 | 坑 |
|---|---|---|
| `bbox` | **`[x, y, width, height]`**（左上角 + 宽高） | ⚠️ **不是** xyxy！COCO 用 xywh |
| `area` | 框的**面积**（像素²） | 理论上 = `w*h` |
| `iscrowd` | 1 = 这是**密集区域**（crowd），不算错也不算对 | 1 的框在匹配时会被忽略 |
| `segmentation` | 多边形坐标 `[[x1,y1,x2,y2,...]]` 或 RLE | **可以为空数组** `[]` |
| `category_id` | 类别 id | 通常从 1 开始，且**不连续** |

> [!warning] **三个高频坑**
> 1. **`bbox` 是 xywh 不是 xyxy** —— 直接当 xyxy 用会得到负面积框。
> 2. **`category_id` 从 1 开始且不连续** —— 要自己建 `{category_id → 连续 label}` 的映射。
> 3. **`segmentation` 可能是空的** —— 并不意味着数据坏了，只说明这个数据集**只标了框**。

👉 展开（COCO 评测协议、面积分档、COCO vs VOC vs LVIS）见 [[paper-notes/论文精读/1-CCFA-Net精读/01-公共基础知识/15-COCO数据集与评测标准|15-COCO数据集与评测标准]]。

## 1.10 真实数据长什么样（HazyDet 实测，264,551 个框逐个校验）

> 用 HazyDet 的 `train/train_coco.json` 当样本，因为它同时具备三个极端特性：
> **密集、小目标、UAV 视角**。

### 规模与分布

| 项 | 实测值 |
|---|---|
| 图像 / 框 | 8000 张 / **264,551** 个 |
| 类别 | car **242,195 (91.5%)**、truck 11,626、bus 10,730 |
| 框宽 `w` | min **2px**，中位数 **58px**，p95 147px，max 983px |
| 框高 `h` | min **2px**，中位数 **50px**，p95 133px，max 704px |
| 面积 | 中位数 3366 px²，p95 14601 px²，max 355432 px² |
| **极小框** | 宽或高 **< 8px** 的 **6267 个（2.4%）** |
| **每图目标数** | 平均 **33.1** 个，中位 28，**最多 760 个** |
| 零框图 | **0 张**（每张图至少 1 个目标） |
| `iscrowd=1` | **0 个**（没有"密集区忽略"，所有框都是有效目标） |
| `segmentation` 非空 | **0%** |
| 格式校验 | 0 非法框 / 0 越界 / `area == w*h` **100% 吻合** → 确认是标准 COCO `xywh` |
| 分辨率 | **至少 5 种混杂**：4096×2160、1400×1050、1400×788、1920×1080、1360×765 |

### 📐 两个数字特别值得记住

**① "每图 33 个目标"决定了 NMS 和样本分配的参数**

框这么密 → 任意两个框都可能高度重叠 →
NMS 阈值、IoU 损失的正负样本比例、ATSS 的 `topk` 全都被这个密度推着走。
这正是论文（DeCoDet）要专门调 DCK 核宽 `K` 的原因：
**调制范围小了，相邻目标的特征会互相串味。**

**② "2.4% 的框小于 8px"决定了不能用小 stride 之外的层去接**

小目标在 FPN 里只能靠高分辨率层（stride 8）接住；
这也解释了为什么 UAV 小目标检测里 AP_small 通常远低于 AP_medium。

## 1.11 常见误解

| 误解 | 真相 |
|---|---|
| "bbox 就是 4 个坐标" | 是 4 个数，但**怎么解释这 4 个数有 4 种约定** |
| "COCO 的 bbox 是 xyxy" | 是 **xywh**（左上角 + 宽高） |
| "segmentation 字段有值 = 这个数据集是分割数据集" | 可能只是**导出时没填**；HazyDet 就全空 |
| "框越准说明模型越好" | 还要看**正负样本分配**和**NMS 阈值**，框本身准只是必要条件 |
| "anchor-free = 不用 NMS" | 照样要 NMS |
| "`area` 字段是分割掩码的面积" | 是**外接矩形**的面积，跟掩码无关 |

## 1.12 自测题

1. `[100, 50, 180, 120]` 按 `xywh` 和按 `xyxy` 读，面积各是多少？差几倍？
2. COCO JSON 里的 `bbox` 是哪种格式？mmdet 内部用哪种？在哪一步转换？
3. FCOS 里，一个特征点预测的 4 个数是什么？怎么还原成框？
4. 为什么说"去 anchor ≠ 去 NMS"？
5. `segmentation: []` 说明这个数据集是坏数据吗？
6. HazyDet 每张图平均 33 个框 —— 这对 NMS 阈值和 ATSS 的 `topk` 有什么影响？
7. "loss 正常但 mAP 是 0"，你怀疑哪个环节？

<details>
<summary>👉 自测答案</summary>

**1.** `xywh` → 180×120 = 21600；`xyxy` → 80×70 = 5600。**差 3.86 倍**。

**2.** COCO 是 **`xywh`**；mmdet 内部是 **`xyxy`**。
转换通常发生在**读标注**这一步（Dataset 的 `parse_data_info` 或 loading transform），
**不在模型里**。HazyDet 里发生在 `HazyDetDataset.parse_data_info`。

**3.** 预测的是到框**四条边的距离** `(l, t, r, b)`；
框 = `(x-l, y-t, x+r, y+b)`。所以模型**从不直接预测 xyxy**。

**4.** anchor-free 只解决了"用什么模板预测"，没解决"同一个目标出多个框怎么去重"。
去重仍然要靠 NMS（或 TAL / NMS-free 方法）。

**5.** 不说明。只说明**这个数据集只标了框、没标掩码**。
（HazyDet 确实 `segmentation` 100% 为空，但它有**深度图**这一路额外标注。）

**6.** 密度这么高 → 相邻框 IoU 容易超阈值 →
NMS 阈值调**大**会误删真目标、调**小**会留下重复框；
ATSS 的 `topk` 取小了会漏掉被密集邻居挤掉的目标。
所有这些参数都必须**按这个密度**来定，不能照搬 COCO 的经验值。

**7.** 怀疑 **③ 评测环节**：框的**格式或坐标系**错了
（模型预测的是 ltrb，解码时按 xyxy 用了；或者 COCO 的 xywh 没转成 xyxy）。
因为 loss 正常说明 ① 标签分配和 ② 回归目标都是对的。

</details>

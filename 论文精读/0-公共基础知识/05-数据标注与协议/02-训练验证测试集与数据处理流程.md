# 02 · 训练/验证/测试集与数据处理流程

> [!note] 这是**公共基础知识**
> 与 HazyDet **没有绑定关系** —— 换任何数据集、任何框架都用得上。

> [!tip] 一句话
> **一份数据切成三份（学 / 调 / 交），配两套处理流程（增强 / 固定）。**
> 两层拆分，缺一不可。

---

## 2.1 两层拆分，先看全景

```
第一层：数据怎么分
   ├── train   训练集   → 让模型"学"
   ├── val     验证集   → 让模型"调"
   └── test    测试集   → 让模型"交卷"

第二层：处理流程怎么分
   ├── train_pipeline   → 读图 → 读标注 → 缩放 → 补边 → ★随机增强★ → 打包
   └── test_pipeline    → 读图 → 缩放 → 读标注 → 打包      （★没有任何随机性★）
```

⚠️ **这两层是独立的**：切了三份数据，但**验证集也用 test_pipeline**；
用了 train_pipeline 的**只有 train_dataloader**。

---

## 2.2 🎯 学生考试类比

| 数据 | 考试类比 | 你拿它干嘛 | 能不能反复用 |
|---|---|---|---|
| **train** | **练习册**（后面附答案） | 照着答案学 | ✅ 想做几遍做几遍 |
| **val** | **模拟考**（有答案，但老师只收卷子不给解析） | 调超参、选 checkpoint、看有没有过拟合 | ⚠️ 可以考很多次，但**考太多次你就会"针对模拟考优化"** |
| **test** | **正式考卷**（答案封存） | 最终验收、跟别人比 | ❌ **只交一次** |

**三条由此推出的铁律：**

1. **练习册的题绝不能出现在考卷里** → 否则就是**数据泄漏**（模型"见过答案"）
2. **模拟考不能考太多次** → 你会不自觉地往"模拟考友好"的方向调参，
   这时验证集已经**被你的调参过程污染**了（学术上叫"验证集过拟合"），
   最终分数会偏乐观
3. **正式考卷只能交一次** → 每次看分数再回去改模型，等于拿考卷当模拟考

> [!warning] 最常见的翻车
> **"我看了 test 分数，然后改了下模型"** —— 这在实验记录里几乎看不见，
> 但在脑子里天天发生。**复现别人的数字时尤其要注意**：
> 论文报的 test mAP，如果作者中间反复用 test 调过参，那个数字是虚的。

---

## 2.3 为什么必须分三份（数据泄漏的三种形态）

| 泄漏形态 | 表现 | 后果 |
|---|---|---|
| **样本级泄漏** | 同一张图（或它的增强版）同时在 train 和 val | 指标虚高 |
| **配对级泄漏** | 原图在 train、它的**衍生图**（加噪/加雾/裁剪）在 val | 指标虚高，**且很难发现** |
| **时间级泄漏** | 用"未来"的数据预测"过去" | 离线有效、上线失效 |

⚠️ **配对级泄漏是遥感/UAV 场景的头号大坑**：
一个地点拍多张图、或一张清晰图合成出多张雾图 —— **它们高度相关**。
只要按"图像"随机切分而不是按"**场景/地点/序列**"切分，就一定会泄漏。

> 👉 **判断标准**：
> 如果两张图共享同一个物理场景 / 同一个物体 / 同一次拍摄，
> 它们**必须在同一个 split 里**，不能一个训练一个验证。

---

## 2.4 为什么训练要增强、推理不能增强

**"增强"的严格定义 = 引入随机性。**（不是"改了尺寸"就叫增强）

| 步骤 | 干什么 | 每张图一样吗 | 算增强吗 |
|---|---|---|---|
| `LoadImageFromFile` | 读图 | ✅ | ❌ 预处理 |
| `LoadAnnotations` / `LoadDualAnnotations` | 读标注（框 / 深度） | ✅ | ❌ 预处理 |
| `Resize` | 缩放到固定尺度 | ✅（同尺寸→同结果） | ❌ 预处理 |
| `Pad` | 补边到固定尺寸 | ✅ | ❌ 预处理 |
| **`RandomFlip`** | 随机左右翻转 | ❌ | ✅ **增强** |
| `ColorJitter` / `Mosaic` / `MixUp` / `RandomCrop` | 颜色扰动 / 拼图 / 混合 / 裁剪 | ❌ | ✅ **增强** |

**为什么训练要有随机性？**
- 同一个物体每次长得不一样，模型才能学到"本质特征"而不是"这张图的样子"
- 相当于"同一道题换几种问法"→ 泛化能力

**为什么推理绝对不能有随机性？**（三条硬理由）

1. **可复现**：同一张图跑两次必须给同一个结果，否则没法 debug、没法比较两个模型
2. **分布一致**：BN 的 `running_mean/var` 是按**训练分布**估的；
   推理时喂进去的分布必须和训练时同分布，否则统计量失配
3. **可比较**：不同模型要在**同一批预处理结果**上比，否则你不知道差距来自模型还是来自随机性

> [!important] **一句话**
> **训练 = 随机增强 + 学习；推理 = 固定处理 + 评估。**
> 推理阶段任何一处随机性，都会让你的实验数字变成"抛硬币"。

## 2.5 三个 split 在代码里的差别（往往不止 pipeline 一项）

> [!warning] 这是最容易被忽略的一层
> 大多数人以为 `train` 和 `val` 的区别**只有"pipeline 里有没有增强"**。
> 真实代码里通常还有 **4~5 处**差别，每一处都会影响指标。

| 项 | train | val | test | 影响 |
|---|---|---|---|---|
| **shuffle** | ✅ `True` | ❌ `False` | ❌ `False` | val/test 必须不打乱，否则指标有额外噪声 |
| **batch_size** | 2 | 1 | 1 | val 用 1 是为了让 BN 不更新 running stats |
| **filter_cfg** | ✅ 有 | ❌ **无** | ❌ **无** | ⚠️ 见下 |
| **随机增强** | ✅ | ❌ | ❌ | 见 §2.4 |
| **加载的标注** | bbox + 深度图 | bbox | bbox（推理时其实用不到） | 深度图只在训练期有意义 |
| **用途** | 学习 | 调参 / 选权重 | 最终验收 | — |

**🔹 HazyDet 里这三份数据具体长什么样**（`configs/_base_/datasets/hazydet_dual.py`）：

| Split | 标注文件 | 图片目录 | dataloader | 用途一句话 |
|---|---|---|---|---|
| **train** | `train/train_coco.json` | `train/hazy_images/` | `train_dataloader` | 让模型**学**（唯一用增强的那份） |
| **val** | `val/val_coco.json` | `val/hazy_images/` | `val_dataloader` | 调超参、看是否过拟合、选最佳权重 |
| **test** | `test/test_coco.json` | `test/hazy_images/` | `test_dataloader` | 最后一次**正式考试**（公平评估） |

> 🎯 **一句话记住这张表**
> **训练集 = 练习册（带答案）｜ 验证集 = 模拟考（老师只收卷子）｜ 测试集 = 正式考试（成绩一次定）**
>
> ⚠️ 但有个**代码层面的反直觉点**：
> **val 和 test 用的 pipeline 跟 train 完全不是一套** ——
> `train_pipeline` 有 `RandomFlip`（随机增强），`test_pipeline` **一个随机算子都没有**。
> 也就是说：**"用哪套 pipeline" 取决于是哪个 split，不取决于是训练还是推理。**

**⚠️ `filter_cfg` 这一行是真正的坑**：

```python
# train
filter_cfg=dict(filter_empty_gt=True, min_size=32)
# val / test —— 没有这一行
```

后果：
- **训练分布 ≠ 验证分布**（训练时"所有目标都 < 32px"的图被整张丢掉，验证时不丢）
- **AP_small 天然偏低**（验证集里的小目标图，模型压根没见过）
- **指标不可比**（你改了 `min_size`，数字和别人没法比）

👉 **报数字时必须写清楚 `min_size` 和训练集的过滤规则**，这是审稿人第一个抓的点。

## 2.6 常见误解

| 误解 | 真相 |
|---|---|
| "Resize / Pad 也算数据增强" | 算**预处理**。增强的判据是**有没有随机性** |
| "验证集可以随便看" | 看得越多，越容易把验证集过拟合。调参次数要有节制 |
| "test 集也能用来选模型" | 那它就不是测试集了，是第二个验证集 |
| "val 和 test 的区别只是文件多一个" | **它们是不同用途的独立数据集**，连 filter_cfg 都不同 |
| "推理时加点 TTA 提点" | TTA（测试时增强）会让结果**依赖随机性**，不可复现；要么固定种子要么不用 |
| "切 split 是随便切的" | 必须按**场景/序列/地点**切，不能按图像切 |

---

## 2.7 自测题

1. 怎么用一句话区分"预处理"和"数据增强"？
2. 为什么推理时不能有随机增强？说出**三条**硬理由。
3. `filter_cfg` 只在 train 有、val 没有，会造成什么后果？
4. 一份数据集里，同一个场景的 5 张图有 3 张在 train、2 张在 val，算不算泄漏？为什么？
5. 论文报了 test mAP = 52.0。你想再试一个新模块，怎么用 test/val 才算规范？
6. `RandomFlip` 放在 `Pad` 之前还是之后有区别吗？

<details>
<summary>👉 自测答案</summary>

**1.** **有没有随机性。** `Resize`/`Pad` 对每张图结果一样 → 预处理；
`RandomFlip`/`ColorJitter` 每张图可能不同 → 增强。

**2.** ① **可复现**（同一图两次跑出不同结果没法 debug、没法比模型）；
② **分布一致**（BN 的 running stats 按训练分布估，推理输入分布必须匹配）；
③ **可比较**（不同模型要在同一批预处理结果上比）。

**3.** ① **训练分布 ≠ 验证分布**（train 丢掉了"所有目标 < 32px"的整张图，val 不丢）；
② **AP_small 天然偏低**（模型没见过这类图）；③ **指标不可比**（改了 `min_size` 数字就没法和别人比）。

**4.** **算泄漏。** 同一物理场景高度相关，模型可能在 train 里已经"见过"这个场景，
val 里的 2 张只是换个角度/天气 → 模型是靠记忆而非泛化做对 → 指标虚高。
正确做法是**按场景/地点切 split**，同一场景的所有图放同一个 split。

**5.** **用 val 选模型 / 调参，用 test 只在最终定稿时跑一次。**
具体流程：调参期间只看 val → 方案定下来 → 最后跑一次 test 报数。
如果反复看 test 分数再改方案，test 就退化成了第二个 val。

**6.** **有区别，但通常不致命**，取决于后续算子是否对边界敏感：
- `Pad` 之后翻转：翻转的是"补了边的大画布"，**补边也在翻转范围内** →
  画面左右不对称（左边是真图+补边，右边是补边+真图），但对纯几何变换无影响
- `Flip` 之前 `Pad`：先翻转原图再补边 → 补边仍在两侧，**更自然**
关键不是顺序，而是：**图像和标注（框、深度图）必须一起翻转**，
否则框和图会错位。mmdet 的 `RandomFlip` 会同时翻转 `img` / `gt_bboxes` / `gt_masks` / `gt_seg_map`。

</details>

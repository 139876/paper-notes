# 03 · 标注文件与「真值（gt）」

> [!note] 这是**公共基础知识**
> 与具体数据集无关 —— 任何检测/分割/深度数据集都适用。

> [!tip] 一句话
> **标注文件 = 训练和评测的"标准答案卷"。**
> 没有它，损失函数无从计算、mAP 无从计算，整个流程第一步就卡死。
> 而 **`gt` 就是这份答案卷里的内容** —— 命名约定是：**来自标注的量 `gt_` 开头，来自模型的量叫 `pred` / `score`。**

---

## 3.1 标注文件的三层含义

| 层次 | 问题 | 答案 |
|---|---|---|
| **是什么** | 一个 JSON / 文本文件 | 里面是"每个目标在哪、是什么、离多远" |
| **干什么用** | 训练时算 loss，评测时算指标 | 同一份文件被用两次，扮演两个角色 |
| **划定了什么** | 任务边界 | **你标了什么，网络就学什么；没标的，网络当它不存在** |

---

## 3.2 COCO JSON = 三张表，靠 id 关联

```json
{
  "images":     [{"file_name": "004725.jpg", "height": 2160, "width": 4096, "id": 4725}],
  "annotations":[{"image_id": 4725, "bbox": [1, 606, 115, 73], "category_id": 0,
                  "id": 0, "iscrowd": 0, "segmentation": [], "area": 8395}],
  "categories": [{"id": 0, "name": "car"}, {"id": 1, "name": "truck"}, {"id": 2, "name": "bus"}]
}
```

| 表 | 记什么 | 一行代表 |
|---|---|---|
| `images` | 图像清单：`id ↔ 文件名 ↔ 尺寸` | **一张图** |
| `annotations` | `image_id` 挂回图上 + `bbox` + `category_id` | **一个目标** |
| `categories` | 类别字典：`id → 名字` | **一个类别** |

> ⚠️ `bbox: [1, 606, 115, 73]` 是 **xywh**（COCO 官方），不是 xyxy。

---

## 3.3 同一个文件，两个落点（最关键的一节）

### 落点 ① 训练时 → 变成 loss（**教具**）

```
标注文件 → parse_data_info → gt_bboxes / gt_labels → 分配正样本 → 算 loss → 反向传播
```

### 落点 ② 评测时 → 变成 mAP（**考卷答案**）

```python
val_evaluator = dict(type='CocoMetric', ann_file=data_root + 'val/val_coco.json')
```

`CocoMetric` 拿这份答案卷，和模型预测的框做 IoU 匹配 → 累积成 AP / mAP。

> 📌 **模型本身永远看不到答案。**
> 它只看图像，输出一堆预测框，然后跟答案卷**比** —— 差距就是 loss，命中程度就是 mAP。

### 🎯 一句话类比

| | 训练 | 评测 |
|---|---|---|
| 标注文件的角色 | **老师批改时的标准答案** | **考试卷的答案** |
| 模型的角色 | 照着答案学 | 自己答卷，隔天发下来对答案 |

---

## 3.4 gt / pred / loss：命名约定

$$\mathcal{L} = f\big(\underbrace{\hat{y}}_{\text{pred 预测}},\ \underbrace{y}_{\text{gt 真值}}\big)$$

| 侧 | 来源 | 命名 | 在哪产出 |
|---|---|---|---|
| **标注侧** | 标注文件 | `gt_xxx`、`label`、`target` | `parse_data_info` |
| **模型侧** | 网络输出 | `pred`、`xxx_score`、`logits` | head 的 `forward` |
| **损失** | 两者相减 | `loss_cls` / `loss_bbox` / `loss_centerness` | `loss_by_feat` |

> 🎯 **模型的整个一生只做一件事：把 pred 往 gt 靠。**
> 训练时用标注拉，评测时用标注打分，推理时没人管 ——
> **泛化能力 = "没有标准答案时你猜得准不准"。**

---

## 3.5 `gt_*` 全清单（mmdet 约定）

| 名字 | 是什么 |
|---|---|
| `gt_bboxes` | 真值框 |
| `gt_labels` | 真值类别 |
| `gt_ignore_flags` | 该框是否忽略（`iscrowd=1` → 1） |
| `gt_bboxes_ignore` | 明确要忽略的框 |
| `gt_masks` | 实例掩码 |
| `gt_sem_seg` | 语义分割图 |
| `gt_panoptic_seg` | 全景分割图 |
| `gt_seg_map` | **通用 seg map 通道**（⚠️ 内容由数据集自己定义，可能是深度图！） |

---

## 3.6 三个阶段里 gt 的三种命运

| 阶段 | 有 gt 吗 | 从哪来 | 干什么用 |
|---|---|---|---|
| **训练** | ✅ | 标注文件 | 算 loss、反向传播 |
| **评测** | ✅ | 标注文件（**同一份**） | 算 mAP |
| **推理**（真实场景） | ❌ | **不存在** | —— |

---

## 3.7 ⚠️ 三个必踩的坑

### 坑 ① `gt_seg_map` 里的 "seg" **不一定是分割**

`gt_seg_map` 是"通用 seg map 通道"，**内容由数据集自己定义**。
HazyDet 里它装的是**深度图**（`LoadDualAnnotations(with_seg=True)`），
而真正的掩码（`gt_masks`）**从来没被赋值**（`segmentation` 字段 100% 为空）。

> 看到 `gt_seg_map` 别以为是分割 —— **先去看数据集怎么填它。**

### 坑 ② "GT image" 和 "GT 标注" 是两回事

| 东西 | 是什么 | 身份 |
|---|---|---|
| `gt_bboxes` / `gt_labels` | 框和类别 | **标注答案** |
| `gt_clean`（某些数据集） | 真实/无退化的图像 | **真实图像**（ground truth **image**） |

> 在有配对图像的数据集里（清晰图 vs 加退化图），
> **"GT image" 专指未退化的那一张**，是某个重建分支的监督目标。
> **同一个词，两种含义，读代码时必须分清。**

### 坑 ③ gt 会跟着图像一起变换

GT 不是永远等于 JSON 里的原始数字。图像被 Resize / Flip / Pad，**GT 也必须同步变**：

```python
boxes_arr = np.array(boxes, dtype=np.float32).reshape(-1, 4) * scale_factor   # ← GT 被缩放了
```

评测时还要变回去（`boxes = det["boxes"] / sf`）。

> 🔴 **gt 的坐标系必须和 pred 严格对齐。**
> 一旦对不齐 → IoU 恒为 0 → `loss_bbox` 恒为 1.0 → **梯度直接死掉**。
> 这是复现检测代码时最隐蔽的一类 bug，症状是"loss 正常下降，但 mAP 恒为 0"。

---

## 3.8 相对深度的存储约定（通用）

很多数据集（尤其是单目深度估计的产物）**不给绝对米数**，只给相对深度。存法是：

| 部件 | 存什么 |
|---|---|
| 深度图（16-bit PNG） | **相对**深度，整数 0~65535，**每张图各自用满量程**（最远点 = 65535） |
| 标定文件（如 `max_depth.txt`） | 每张图的**绝对**最大深度（米），一行一条，带表头 |

反归一化公式：

$$
d_{\text{abs}}(x) = \frac{d_{\text{rel}}(x)}{65535} \cdot d_{\max}
$$

> 🎯 **为什么是"相对 + 每图标定"？**
> **主因：单目深度模型只能预测相对深度** —— 它能告诉你"这块比那块远 3 倍"，
> 但**预测不出绝对米数**（尺度未知）。所以必须另配一个绝对尺度的锚点。
> **次因：uint16 比 uint8 精度高得多**（65536 级 vs 256 级）。

> ⚠️ **副作用：跨图不可比。**
> 每张图各自归一化 → **"图 A 的远处"和"图 B 的远处"没有可比性**。
> 要做全局深度排序、跨图几何关系，**必须先反归一化**。
> **所以那个标定文件绝对不能丢。**

> ⚠️ **自己重算深度图时的两个坑**
> ① 归一化必须保证**最远点恰好 = 65535**，否则反归一化系统性偏；
> ② 归一化方式要和官方一致（min-max？还是别的？），否则 d_max 对不上。

---

## 3.9 💡 标注定义了任务的边界（最有价值的一节）

> **你标了什么，网络就学什么；你没标的，网络就当它不存在。**

| 标注里的实际情况 | 直接后果 |
|---|---|
| 掩码字段全空 | 网络**从未被训练**输出掩码 → 只能做检测，做不了分割 |
| 只有 N 个类别 | `num_classes=N`，不会去检测第 N+1 类 |
| 没有 ignore 标记 | 没有"密集忽略区"要处理 |
| 深度只在训练期可用 | 推理期拿不到深度这一路的信息 |

> 🎯 **对做研究的直接含义**：
> 你想加什么能力，先问一句 —— **"标注里有对应的答案吗？"**
> - 想加深度先验 → ✅ 有深度图（但**只在训练期**）
> - 想做前景分割 → ❌ 没有掩码，得**自己标上万张**
> - 想加新类别 → ❌ 类别表里没有
>
> **重新标注上万张图通常是不可行的** —— 这就是为什么很多新模块都被设计成
> **"不需要新标注"** 的形式（只在特征空间做事）。

## 3.10 ❓ 自测题

1. 一份标注文件在训练和评测时分别扮演什么角色？模型能看见它吗？
2. `gt_bboxes` 和 `pred_bboxes` 的命名差别代表什么约定？
3. 为什么"loss 正常下降但 mAP 恒为 0"？最可能的两类原因？
4. `gt_seg_map` 这个名字能保证它是分割图吗？
5. 为什么单目深度数据集要存"相对深度 + 每图 d_max"，而不是直接存米？
6. 一个数据集只标了 bbox、没标 mask，能对它做实例分割吗？为什么？

<details>
<summary>👉 自测答案</summary>

**1.** 训练时是**教具**（拉模型去拟合它），评测时是**考卷答案**（给评估器打分用）。
**模型两次都看不见** —— 它只输出预测，靠"预测 vs 答案"的差距学习、被打分。

**2.** `gt_` 前缀 = **标注侧**（Ground Truth，来自标注文件）；
`pred` / `score` = **模型侧**。看到 `gt_` 就该想"这是标准答案"，看到 `pred` 就该想"这是模型的猜测"。

**3.** ① **坐标系不对齐**（gt 没跟着图像同步 Resize/Flip/Pad，或解码时没还原回去）
→ IoU 恒为 0 → `loss_bbox` 恒为 1.0 → 回归分支梯度死掉；
② **损失函数在不相交时梯度消失**（如 `1 - IoU` 这种线性形式）→ 同样表现为 loss 卡住不降、mAP 为 0。
（诊断口诀：**看 `loss_bbox` 是不是恒等于 1.0**。）

**4.** **不能。** `gt_seg_map` 是"通用 seg map 通道"，**内容由数据集自定义**。
HazyDet 里它装的是**深度图**；要看数据集的加载代码才知道装的是什么。

**5.** **主因：单目深度模型只能给相对深度**（尺度未知，测不出米数），必须另配绝对尺度锚点；
**次因：uint16 比 uint8 精度高**（65536 级 vs 256 级）。
副作用是跨图不可比 —— 要跨图比较必须先反归一化。

**6.** **不能。** 网络**从未被训练**输出掩码 —— 没有掩码标注就没有掩码损失，
模型根本不知道像素级边界长什么样。强行做只能拿 bbox 裁出来的矩形当伪掩码，
那是"框退化成掩码"，不是分割。

</details>

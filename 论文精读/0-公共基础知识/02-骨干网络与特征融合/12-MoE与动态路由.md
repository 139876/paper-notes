# 公共基础 20 · MoE 与动态路由：混合专家到底在干什么

> [!tip] 🔗 这篇在知识地图上的位置
> - **方向层**（地图）：[[paper-notes/论文精读/0-公共基础知识/07-方向知识脉络/05-注意力机制谱系]] —— 门控本质上是一种"**粗粒度注意力**"
> - **本篇**（零件）：讲清楚 **MoE 的三个部件**、**稀疏 vs 稠密路由**、以及**训练时最经典的坑**
> - **论文层**（实例）：[[paper-notes/论文精读/5-TDRE精读/04-第3讲-DR-MoE动态路由专家]] 是第 5 篇里对 DR-MoE 的精讲
>
> **一句话**：MoE 就是一个"**让不同专家处理不同类型的输入**"的架构套路。
> 理解它，就理解了现代大模型里一半的"稀疏"设计。

---

## 1. 一句话定义

> [!abstract] MoE（Mixture of Experts，混合专家）
> 把一个网络拆成**若干个并行的"专家"子网络**，再加一个**路由器（router / gate）**，
> 由路由器决定**每个输入该送给哪几个专家**。
>
> **动机**：如果每个输入只需要动用一小部分参数，
> 那么**总参数量**可以很大，而**单次推理的计算量**保持很小。
> （"**稀疏激活**" —— 论文里常说 "activated parameters" 就是在说这个。）

> 🎯 **比喻**：
> 普通网络 = **一个全能专家**，什么病都看，但样样不精；
> MoE = **一个医院分诊台 + 一群专科医生**。
> 分诊台（路由器）看一眼症状，决定把你送到**内科 / 外科 / 皮肤科**。
> 医院买了 10 个专科医生（**总参数大**），但你每次只占用 1~2 个（**单次计算小**）。

## 2. 三个部件

```
输入 x
  │
  ▼
┌────────────────┐
│  路由器 Router  │  ← 通常就是一个很小的 MLP / 1×1 卷积
│  输出打分 w_1..w_N │
└────────────────┘
  │
  ├─► 专家 1 ──┐
  ├─► 专家 2 ──┼──► 加权求和 ──► 输出 y
  ├─► 专家 3 ──┤
  └─► 专家 N ──┘
```

### 2.1 路由器（Router / Gate）

最常见的写法是 **softmax + Top-k**：

$$
w = \operatorname{softmax}(W x), \qquad
\mathcal{E}(x) = \operatorname{TopK}\bigl( w,\, k \bigr)
$$

$$
y = \sum_{i \in \mathcal{E}(x)} w_i \cdot E_i(x)
$$

**关键点**：
- 路由器本身**很轻**（通常比专家小 1~2 个数量级），否则省下的算力全被路由器吃掉了。
- 路由器的输出维度 = 专家数 $N$。
- `TopK` 的 $k$ 就是"**每次激活几个专家**"。

> [!note] 路由器的输入不一定是原始 token
> 在 Transformer 里，路由器通常吃的是 **token 的隐状态**；
> 在图像里，通常吃的是**特征图的全局池化结果**（→ **图像级路由**）或**每个位置的特征**（→ **像素级路由**）。

### 2.2 专家（Expert）

每个专家就是一个**普通的小网络**（Transformer 里通常是 1~2 个 FFN block）。

> [!important] MoE **不会**让专家"自动分工"
> **专家的分工不是设计出来的，是训练涌现出来的。**
> 路由器学会"什么输入该给谁"，专家学会"成为某类输入的专家"。
> 但这个过程**很不稳定**（见第 4 节），需要人为干预。

### 2.3 负载均衡（Load Balancing）

路由器很容易**塌缩**（见下节），所以通常要加一个**辅助损失**强制专家被均匀使用：

$$
L_{aux} = N \sum_{i=1}^{N} f_i \cdot P_i
$$

- $f_i$：本 batch 中**被路由到专家 i 的 token 比例**
- $P_i$：本 batch 中**路由器给专家 i 的平均概率**
- 这个乘积在**均匀分配时最小**（=$1/N$）→ 最小化它就等于**逼路由器均匀分配**。

> 📌 这个损失是 MoE 训练里**最"工程"、最"经验"**的一块 —— 系数怎么调、要不要加，是各家 MoE 论文的"祖传代码"。

## 3. 稀疏 vs 稠密：最关键的一个区分

| | **稀疏路由**（经典 MoE） | **稠密路由**（全激活） |
|---|---|---|
| 激活专家数 | Top-k（k=1 或 2，**远小于 N**） | **全部 N 个** |
| 计算量 | 随 N **几乎不变** | 随 N **线性增长** |
| 典型例子 | Switch Transformer（k=1）、Mixtral（k=2） | TDRE 的 Top-3（N=3，k=3） |
| 风险 | **专家饥饿** | 无 |

> [!tip] 判断一个方法是"稀疏 MoE"还是"稠密 MoE"，只看一件事
> **每次前向，有多少比例的参数被真正计算了？**
> - < 10% → 稀疏（真 MoE，靠这个省算力）
> - 100% → 稠密（**不算"稀疏 MoE"**，只是"多专家 + 门控"）

### 3.1 ★ 稀疏路由的核心权衡

```
                    N 个专家，每个都很大
        ┌───────────────────────────────────────────┐
        │                                           │
   稀疏 │  每次只算 k 个 → 计算量 ≈ k 个专家         │
  路由 │  ★ 但：路由错了，被丢弃的专家信息就永久没了   │
        │  ★ 代价：token 可能被"丢"（token dropping） │
        │                                           │
  稠密 │  每次全算 → 计算量 = N 个专家               │
  路由 │  ★ 但：路由错了，其他专家的输出还在          │
        │  ★ 代价：省不下算力                       │
        └───────────────────────────────────────────┘
```

> [!important] 一句话总结这个权衡
> **稀疏路由 = 用"信息可能丢失"换"算力"；稠密路由 = 用"算力"换"信息不丢"。**
>
> **当专家很小的时候（TDRE 的场景：总共 2406 参数），显然是稠密更划算。**

## 4. MoE 训练的三大经典坑

### 坑 ① 专家塌缩（Expert Collapse）

**现象**：路由器**永远只选 1~2 个专家**，其他专家**从未被选中** → 参数浪费、效果退化。

**原因**：训练早期，某个专家恰好输出得好一点 → 路由器更倾向选它 → 它拿到更多梯度 →
**学得更好** → 更被选。这是一个**正反馈死循环**。

**对策**：负载均衡辅助损失（2.3 节）；路由器加**噪声**；限制每个专家的**容量**（capacity factor）。

### 坑 ② 负载不均导致的**通信瓶颈**

在**分布式训练**里，专家分布在不同 GPU 上 → 路由决定了 token 要"跑"到不同卡 →
**all-to-all 通信**是 MoE 训练最大的性能杀手。

> 📌 **这是 MoE 在工业界最大的工程痛点**，也是"MoE 很美但难训"的根本原因。

### 坑 ③ ★ 采样偏置导致的**隐性过拟合**

**如果训练数据的类别分布不均**，路由器会**按数据比例**退化：
占比高的类别 → 路由到它的专家 → 那个专家被训练得最好 → 更多样本被路由过去 → **正反馈**。

> [!important] 对策：**均匀采样**
> **强制每个 batch 里各类别/各专家的目标样本数量相同**，
> 路由器就**没有"躺赢"的选项**，必须学会真正的判别。
>
> 📌 这正是 TDRE 论文里的做法（阶段② batch = 16，四种天气各 4 张）：
> **"these 16 images are uniformly sampled from the four conditions"** ——
> **均匀采样是 MoE 训练的标准动作，不是可选项。**

## 5. 图像领域里的 MoE：三个层次

| 粒度 | 路由依据 | 例子 | 难点 |
|---|---|---|---|
| **样本级 / 图像级** | 整张图一个权重向量 | **TDRE**（全局池化后门控） | 简单，但一张图内多种退化无法处理 |
| **Token 级 / Patch 级** | 每个 patch 一个权重 | MoFormer、部分 CLIP 变体 | 需要"这个 patch 属于什么"的可学习依据 |
| **通道级** | 每个通道一组权重（**SE-Net 家族**） | [[paper-notes/论文精读/0-公共基础知识/07-方向知识脉络/05-注意力机制谱系\|SE / ECA]] | 通道没有语义先验 |

> [!tip] 一个重要的联系
> **SE-Net / ECA / CBAM 这类"注意力模块"，本质上是"通道级 / 空间级的 MoE"**：
> 它们用一个小网络算权重，然后**加权聚合**。
> 区别在于：注意力模块**没有"专家"**，只是给同一张特征图的不同位置/通道**加权**；
> 而 MoE 有**独立的子网络**，每个专家能学到**完全不同的映射**。
>
> 👉 详见 [[paper-notes/论文精读/0-公共基础知识/07-方向知识脉络/05-注意力机制谱系]]。

## 6. 回到 TDRE：它在这张图里的位置

```
MoE 通谱
  │
  ├── 稀疏路由（经典）
  │     ├── Switch Transformer  k=1
  │     ├── Mixtral             k=2
  │     └── 坑：专家饥饿、负载均衡、通信瓶颈
  │
  └── 稠密路由 + 图像级门控
        └── ★ TDRE 的 DR-MoE
              N = 3（雾 / 沙尘 / 低照），k = 3（Top-3 全激活）
              路由器输入 = 全局池化后的退化特征
              路由 = 有监督的 3 类分类（CE）
```

**TDRE 的三个"非典型"选择及其理由**：

| 选择 | 理由 |
|---|---|
| **稠密（Top-3 全激活）** | 专家极小（总 2406 参数），省算力没意义；全激活能**避免专家饥饿**、**门控错了有退路** |
| **图像级路由** | 退化是**整图级属性**，天然没有像素级标签；且参数能压到极致 |
| **路由有监督（CE）** | 退化类型是**已知**的（合成时就知道），所以**没有理由让路由器"自己发现"** —— 直接用标签教它最快 |

> [!important] 第三条是本篇最实用的一条经验
> **能用标签监督的，就别让模型自己学。**
> MoE 最难的部分是"**怎么让专家自动分工**"；
> 如果你的任务里**本来就有类别/条件标签**，**直接监督门控**能把这一大堆坑全部绕开。
>
> TDRE 就是这么干的 —— 沙尘图就打"沙尘"标签，门控立刻学会分类，
> 专家跟着各学各的。**这是"用工程手段绕过算法难题"的典范。**

## 7. 常见混淆辨析

| 混淆 | 澄清 |
|---|---|
| MoE = 参数多所以更强？ | ❌ MoE 的卖点是**总参数多、单次计算小**。**稀疏激活**才是关键 |
| MoE 一定比 dense 强？ | ❌ 训练不好会**比 dense 差**（专家塌缩）。MoE 更难训 |
| MoE 就是多分支 + 加权？ | ⚠️ **半对**。加权和只是形式，**关键在"由路由器决定权重"** |
| 门控 = 注意力？ | ⚠️ **像但不同**。注意力通常算"每个位置该关注谁"；门控算"这个输入该交给谁"。**都可以理解为加权聚合** |
| Top-3 routing = Top-3 稀疏？ | ⚠️ **看专家总数**。如果 N=3，Top-3 = 全激活 = **稠密**。TDRE 就是这种情况 |

## 8. 自测（5 题）

> [!question]- 第 1 题
> 一句话说清 MoE 相对普通稠密网络的**核心优势**和**核心代价**。
> **参考**：
> **优势**：**总参数量可以很大，而每次推理的计算量保持很小**（稀疏激活）。
> **代价**：① **训练更难**（专家塌缩、负载均衡、通信瓶颈）；② **路由决策本身有风险**（选错就丢信息，除非用稠密路由兜底）。

> [!question]- 第 2 题
> 为什么 TDRE 明明只有 3 个专家，却要用"Top-3 routing"这种**稠密**方式，而不是 Top-1 稀疏？
> **参考**：
> ① **算力不是瓶颈** —— 整个 DR-MoE 才 2406 参数，"省算力"这个 MoE 的原始动机在这里**完全不成立**；
> ② **避免专家饥饿** —— Top-1 时弱专家可能长期拿不到梯度，永远学不好；
> ③ **门控失败有退路** —— 稠密时另外两个专家的输出还在，Conv9 可以学着"从三个候选里挑"。
> **代价**（计算 ×3）在这个量级**可以忽略**。

> [!question]- 第 3 题
> 为什么 MoE 训练中要**均匀采样**各类别？如果按数据自然比例采样会发生什么？
> **参考**：
> 因为**路由器会按数据比例退化**。
> 占比高的类别 → 路由到对应专家 → 该专家拿到更多梯度 → 学得更好 → 拿到更多样本 → **正反馈**，
> 最终**专家塌缩**成"只服务多数类"。
> **均匀采样**（每 batch 各取固定数量）让路由器**没有"躺赢"的选项**，必须学会真正的判别。

> [!question]- 第 4 题
> 如果你的任务里**本来就有条件标签**（比如"这张图是雾/沙尘/低照"），你会让路由器**自己学**还是**用标签监督**？为什么？
> **参考**：
> **用标签监督**（TDRE 的做法）。
> MoE 最难的部分是"**让专家自动分工**"，要靠辅助损失、噪声、容量因子一堆技巧；
> 而条件标签**已经把答案给出来了**，直接用 CE 监督门控
> → 专家分工**自动达成**（因为各专家被路由到不同标签的样本，梯度自然分开），
> **上面那一堆坑全部绕开**。
> **经验**：**能用标签监督的，就别让模型自己学。**

> [!question]- 第 5 题
> SE-Net / ECA / CBAM 这些"注意力模块"和 MoE 是什么关系？
> **参考**：
> **形式上同源**：都是"算一组权重 → 加权聚合"。
> **本质不同**：注意力模块**没有独立的专家子网络** —— 只是给同一张特征图的不同通道/位置加权；
> MoE 的每个专家是**独立的小网络**，能学到**完全不同的映射**。
> 所以可以把注意力看成"**没有专家的 MoE**"，
> 把 MoE 看成"**带子网络的注意力**"。
> 更细的层次对照见本篇第 5 节。

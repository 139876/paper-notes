# 07 · 检测器三段式架构（Backbone → Neck → Head）

> [!abstract] 本讲要回答
> 1. 任意一个检测器，能不能拆成**三个可替换的零件**？
> 2. 这三个零件之间的**接口契约**是什么？改动时哪里必须同步改？
> 3. 一张**创新地图**：前辈的工作落在哪一层？我的四篇论文又落在哪一层？

> [!note] 和 [[06-ResNet与FPN通用结构及前辈工作综述]] 的分工
> 06 讲**具体的 ResNet 长什么样、FPN 长什么样**，以及前辈怎么改这两个零件；
> 本篇讲**更一般的抽象**：任何检测器 = 三个零件 + 一份接口契约 + 一张创新地图。
> 本篇是"读论文时的思维框架"，06 是"零件本身的内部细节"。

---

## 0. 一句话结论

> [!tip] 记住这一句就够了
> **检测器不是「一个模型」，而是三个可替换零件串起来的流水线。**
> Backbone 把像素变成特征，Neck 在多个尺度上各备一份特征，Head 在每个位置回答「有没有、在哪、有多大」。

---

## 1. 三个零件

```
输入图像  →  [ Backbone ]  →  [ Neck ]  →  [ Head ]  →  类别 + 框
```

| 部件 | 干什么 | 输入 | 输出 | 可换成 |
|---|---|---|---|---|
| **Backbone** | 「看图」：像素 → 特征 | RGB | C2~C5（多尺度、通道各异） | ResNet / Swin / ConvNeXt / RepVGG / EfficientNet |
| **Neck** | 「整理」：多尺度特征融合 | C2~C5 | P3~P7（**通道统一**） | FPN / PANet / BiFPN / ASFF / NAS-FPN |
| **Head** | 「下结论」：每个位置做判断 | P3~P7 | 类别 + 框（+辅助图） | FCOS / ATSS / VFNet / TOOD / RoI Head |

### 1.1 Backbone —— 「看图」

- **职责**：把像素变成「可判断的特征」
- **产出**：不同分辨率、不同通道数的特征图（C2~C5）
- **关键属性**：**零任务知识** —— 它只管提取，不管你检测什么
- **HazyDet 用的**：ResNet-50，`out_indices=(0,1,2,3)`，`frozen_stages=1`

### 1.2 Neck —— 「整理」

- **职责**：把多尺度特征融合成「尺度齐全、通道统一」的一份
- **产出**：P3~P7，每一级**通道数相同**（这样 Head 才能共享权重）
- **关键属性**：**零任务知识** —— FPN 不认识"车"，它只认识"尺度"
- **HazyDet 用的**：FPN，`out_channels=256`，`start_level=1`，`num_outs=5`

### 1.3 Head —— 「下结论」

- **职责**：在每个特征图位置上做判断：有没有目标？框在哪？多大？属于哪类？
- **产出**：类别 logits + 回归框（+ 可选的辅助图，如深度图）
- **关键属性**：**强任务知识** —— 换任务基本必须换 Head
- **HazyDet 用的**：`VFNetDeCoDetHead`，`num_classes=3`，`stacked_convs=3`

## 2. 接口契约（这才是能迁移的知识）

| 接口 | 硬约束 | 违反后果 | 详见 |
|---|---|---|---|
| Backbone → Neck | `in_channels` 必须对上（如 256/512/1024/2048） | 维度不匹配，**直接报错** | [[06-ResNet与FPN通用结构及前辈工作综述]] §2.4 |
| Neck → Head | **通道必须统一** | Head 无法在多尺度间共享权重，参数爆炸 | 同上 |
| Neck → Head | Head 的 `strides` 必须对应 Neck 输出的层级 | 框的尺度错位，AP 崩 | 本篇 §2.2 |

### 2.1 HazyDet 的具体数字

```python
backbone=dict(type='ResNet', depth=50, out_indices=(0,1,2,3), frozen_stages=1)
        # → C2(256) C3(512) C4(1024) C5(2048)
neck=dict(type='FPN', in_channels=[256,512,1024,2048], out_channels=256,
          start_level=1, num_outs=5)
        # → P3~P7，每级 256 通道
bbox_head=dict(type='VFNetDeCoDetHead', in_channels=256, feat_channels=256,
               stacked_convs=3, num_classes=3, strides=[8,16,32,64,128])
        # → 类别 + 框 + 深度图
```

### 2.2 strides 与层级是一一对应的

| 特征层 | 相对原图下采样倍数 | `strides` |
|---|---|---|
| P3 | 1/8 | 8 |
| P4 | 1/16 | 16 |
| P5 | 1/32 | 32 |
| P6 | 1/64 | 64 |
| P7 | 1/128 | 128 |

> [!warning] 最容易错的一处
> `strides` 写错不会报错，只会**安静地变差**：框的位置全错位，mAP 掉一大截。
> 复现别人的配置时，`num_outs` 和 `strides` 的长度必须一致。

### 2.3 口诀

> [!tip] 通道数的传递
> **一个模块的 `in_channels` = 上一个模块的 `out_channels`。**
> 通道数在 Neck 这一层被"统一"（FPN 的 `out_channels=256`），
> 正是为了让 **Head 能用同一套权重处理 P3~P7 五个尺度**。

## 3. 四种范式

| 范式 | 代表 | 特点 | 典型速度/精度 |
|---|---|---|---|
| 两阶段 | Faster R-CNN, Cascade R-CNN | 先出候选框再分类回归 | 准但慢 |
| 一阶段 anchor-free | FCOS, ATSS, VFNet, TOOD | 每个位置直接预测 | 快、可端到端，**HazyDet 走这条** |
| 一阶段 anchor-based | RetinaNet, SSD | 预设 anchor | 快，但 anchor 要调 |
| Transformer | DETR, Deformable DETR, DINO | 用 query 取代 anchor | 端到端，但训练成本高 |

> [!note] HazyDet 官方 baseline 为什么是 VFNet？
> VFNet 是 **anchor-free** 的一阶段检测器，且天然支持「多任务共享特征」——
> DeCoDet 要在同一个 head 上同时输出**类别 + 框 + 深度图**，anchor-free 的逐位置预测结构更适配。

## 4. 🔥 创新落在哪一层（选题地图）

> [!important] ⚠️ 先钉死这张表的「轴」——它经常被误读
> 这张表的轴是「**一篇论文改的是哪一层**」，
> **不是**「哪些方法是为雾天设计的」。
>
> Swin / ConvNeXt / FPN / ATSS **根本不知道"雾"是什么** —— 它们是**通用视觉技术**。
> 前辈工作的真正含义 = **把通用技术搬进具体问题域（高光谱 / 跨模态 / 雾天）并加以改造**。
>
> 所以读论文要问**两层**：
> 1. 它改的是**哪一层**？
> 2. 在**这个具体域里**，它被改成了什么样子？
>
> 下表因此加了第三列「高光谱侧前辈**已怎么融合改造**」——
> 这一列才是真正的「前辈工作」，第二列只是通用技术的名单。

| 层 | 通用视觉的代表技术 | 高光谱侧前辈**已怎么融合改造** | 雾天/无人机侧还剩什么空白 |
|---|---|---|---|
| **Backbone** | ResNeXt, Swin, ConvNeXt, EfficientNet, RepVGG | ⚠️ **高光谱没有直接搬 2D 单分支**，而是另起了一套谱系：**3D CNN**（光谱×空间双轴，如 Spectral-MSA 用 4×4×1 的 3D 卷积做 patch embedding）、**光谱-空间 Transformer / Mamba**（SpecDETR, ISPRS JPRS 2025）。原因：HSI 是百通道立方体，2D 单分支天然丢光谱维 | 把通用 2D 骨干改造成**光谱感知的 3D / 双分支** —— 你第 4 篇的 DBFDF 就落在这 |
| **Neck** | FPN, PANet, BiFPN, NAS-FPN, ASFF, DCNv2 | **注意力融合**是最典型的「通用模块搬运」：SCAFF = 自注意力分支 + 卷积分支再融合；多尺度则被改写成「多尺度 3D 卷积核产多尺度光谱嵌入」（LSDNet 式），而不是 FPN 式 2D 金字塔 | FPN 式金字塔在高光谱里不是最优解；**雾/深度相关的多尺度融合**仍然空白 |
| **Head** | ATSS, VFNet, TOOD | 早期是**逐像素二分类**（HTD）；近年才转向 patch / 滑窗 + 空间-光谱块。SpecDETR 明确批评 "per-pixel binary classification 忽略立方体结构" | 通用 anchor-free Head 尚未真正吃透高光谱结构 |
| **输入侧** | RGB-D, RGB-IR, 深度图, LiDAR | 🔥 **融合最彻底**：高光谱本身就是多通道输入，难点变成**如何降维 / 选带 / 伪彩化** | 多模态（高光谱 + 可见光 + 深度）互补仍稀疏 |
| **训练侧** | DA-Faster RCNN, 蒸馏 | 🔥 **分类侧已非常卷**：域融合对比学习、**DAMamba**（域不变原型对齐）、**CPDIC**（对抗域适应 + 校准原型 + 动态实例卷积）、DCPN（3D 残差 CNN + 双编码器解耦域不变/域特定）、原型驱动的域解耦对齐 | 🔥 **检测任务上的 DA 相对少** —— 绝大多数域适应工作做的是**分类** → **这就是你第 4 篇的机会点** |
| **数据侧** | 合成退化增强（雾/雨/雪）、配对数据集 | Houston/Pavia/Salinas 场景数据集 + **合成云遮挡增强**（把云遮挡加到机载高光谱数据，ACM 2025） | 云/雾遮挡 × 遮挡型小目标的联合设计；同域可参考 FoggyCityscapes |

> [!warning] 原表的 3 处不严谨（已修正）
> 1. **PDFT 不是「前辈工作」** —— 它是 **HazyDet 自己的 §4.2 方法**，也就是你正在读的目标论文。
> 2. **HazyDet 不是「前辈工作」** —— 它是**目标数据集**；同域真正的前辈数据集是 **FoggyCityscapes**。
> 3. **GIoU / VarifocalLoss 是损失函数**，不属于 Head **结构**层（严格归训练侧 / 损失设计）。
> 4. 「DA-Faster RCNN / PDFT / 蒸馏」混在一格，实为三个子方向：**对抗域适应 / 渐进式微调 / 知识蒸馏**。

> [!important] 用这张表读论文
> 先定位「这篇改的是哪一层」，再判断「它的贡献是真结构创新，还是换数据/换训练策略」。
> 两者在论文里长得一样，但**工作量与可复用性差一个量级**。

## 5. 我的四篇论文落在哪一层

| 论文 | 创新落点（已按张量流核对） | 具体机制 | 关键事实 |
|---|---|---|---|
| **CCFA-Net** | **输入侧 + Neck 侧** | CCDD 去雾分支（接在冻结编码器 S2 上）/ CFFM 跨域融合（S2 × F_clean）/ MFAM 改造 FPN（S3/S4/S5 → P3/P4/P5） | ⚠️ **DetectHead 是原版 TOOD，一行没改** —— 创新全在「特征怎么长出来」 |
| **Cross-Modal UAV** | **训练侧（蒸馏范式）** | CKD 范式 + SFI 选择性特征模仿 + API 自适应预测模仿 | 推理时**删掉红外相机 + 所有融合模块**，只留普通 RGB 单模态 |
| **HazyDet** | **数据侧 + Neck→Head 之间的深度调制 + Head 侧 + 训练侧** | 数据集 + 深度标注（地基）；MSDP（在 P_n 上生深度图）+ DCK（用深度造动态核调制特征）；DeCoDet head 多一条深度输出分支 + SIRLoss；PDFT | ⚠️ **DCK 不是 Head 结构**，是 Head 之前调制特征；Head 侧真正的改动只是「多一条深度输出分支」 |
| **跨域高光谱** | **Backbone 侧 + 训练侧** | DBFDF 双分支特征解耦 + JVC 联合变量一致性 + ASI 锚点结构不变性 | ✅ 这一条的标注本来就是准确的 |

> [!note] 一个规律（修正后）
> 你这四篇里**没有一篇是"纯 Neck 创新"**。
> 说明：**Neck 这层的通用红利已经被 FPN/PANet/BiFPN 吃得比较干净了**，
> 想发文章，优先去 **输入侧 / 训练侧 / 数据侧** 找空间。
>
> 更精确一点说：**四篇里有三篇的创新都发生在"检测头之前"**
> —— CCFA-Net 在特征融合、HazyDet 在深度调制、跨域高光谱在骨干解耦。
> 真正动到**检测头结构**的只有 HazyDet 的一条附属深度输出分支。
> 👉 **选题优先在"特征怎么长出来"这一段找空间**，而不是去改 head 的标签分配 —— 后者赛道最拥挤。
>
> 🔥 **对你第 4 篇特别有利的一条**：
> 高光谱的域适应工作**绝大多数做的是分类任务**，**检测任务上的跨域 DA 相对少**。
> 「跨域 + 高光谱 + 检测」目前是块没被占的地。

## 6. 本质：检测器到底在干什么

> [!tip] 一句话
> **检测器 = 在特征图上密集回答两个问题：这个位置有东西吗？它在哪、有多大？**
>
> - **Backbone** 负责"把像素变成可判断的特征"
> - **Neck** 负责"在多尺度上各备一份特征"
> - **Head** 负责"在每个位置做判断并给框"

所以任何检测器的差别，本质上都是：**"特征从哪来、准备在哪几个尺度上做判断、判断时用什么依据"** 这三件事的不同组合。

---

## 7. 读论文三问法

1. **Backbone 是什么？**
2. **Neck 是什么？**
3. **Head 是什么？**
4. 🔥 **这篇的创新落在哪一层？**

> [!warning] 第四问的警报
> 如果答案是「三段全都改了」，要警惕 ——
> 那通常意味着它其实是**数据/训练策略**的论文，而不是结构论文。
> 读的时候要把「结构贡献」和「实验条件优势」分开算账。

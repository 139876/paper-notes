## 一、先搞清楚：什么算「公共基础」，什么算「论文精读」

这是整个知识库最该先分清的一件事。

| | **公共基础轨**（本目录 `0-公共基础知识/`） | **论文精读轨**（`1-`/`2-`/`3-`/`4-` 四个目录） |
|---|---|---|
| 内容 | **通用技术概念**：卷积、padding、ResNet、mAP… | **这一篇论文的具体内容**：CCDD、MSDP、PDFT、Table 4… |
| 换论文会变吗 | ❌ **不会**（换任何论文都得会） | ✅ **会**（换论文全废） |
| 判断标准 | **"我在别的论文里也见过它"** | **"只有这篇论文才这么设计"** |
| 学习时机 | **先修**（地基） | 边读边补 |

> [!important] 判据就一条
> **如果一个概念只在这篇论文里出现、换个数据集/模型就没了 → 论文精读。**
> **如果它是一个"工具"，任何网络都能用 → 公共基础。**
>
> 比如：`3×3 卷积`是工具（公共）；`CCDD 里那个 256→48 的 3×3 卷积`是设计（论文）。

> [!note] 为什么公共知识要"提出来"而不是留在各篇论文下面
> 以前公共知识散在 3 个地方，同一个概念（ResNet、FPN、mAP）重复写了三遍，
> 结果是**改一处忘两处**。现在：
> - **公共知识只写一遍**（这里）
> - 但**每篇论文目录下都有一份「公共知识回顾」**，用**复述**的方式重复关键结论
>   （1-CCFA-Net精读/02-公共知识回顾、2-…/13-、3-…/08-、4-…/13-）
>
> 👉 **"提出来"是为了不重复维护，"重复一遍"是为了加深记忆。** 两者不矛盾。

## 四、🔥 四篇论文的「创新落点」地图

> [!tip] **检测器 = 在特征图上密集回答两个问题：这个位置有东西吗？它在哪、有多大？**
> **Backbone** 把像素变成"可判断的特征" → **Neck** 在多尺度上各备一份 → **Head** 逐位置下结论。

| 层 | 前辈工作（通用方法，不限于有雾场景） |
|---|---|
| **Backbone** | ResNeXt, Swin, ConvNeXt, EfficientNet, RepVGG |
| **Neck** | FPN, PANet, BiFPN, NAS-FPN, ASFF, DCNv2 |
| **Head** | ATSS, VFNet, TOOD, VarifocalLoss, GIoU |
| **输入侧** | RGB-D, RGB-IR, 深度图, LiDAR |
| **训练侧** | DA-Faster RCNN, PDFT, 蒸馏 |
| **数据侧** | HazyDet, FoggyCityscapes |

| 论文 | 创新落在哪一层 |
|---|---|
| **① CCFA-Net** | **Head 侧**（CCDD / CFFM / MFAM）+ 输入侧（去雾） |
| **② Cross-Modal UAV** | **输入侧 + 训练侧**（SFI / API 蒸馏） |
| **③ HazyDet** | **数据侧**（造数据 + 深度标注）+ **Head 侧**（DCK）+ **训练侧**（PDFT） |
| **④ 跨域高光谱** | **Backbone 侧**（DBFDF）+ **训练侧**（JVC / ASI） |
| **⑤ TDRE** | **输入侧（图像级前置）** —— 清晰天感知器 + DR-MoE + GT 掩码损失；**检测器一行没改** |

> ⚠️ **注意**：上表"前辈工作"指的是**通用技术**，不是"针对有雾环境提出的"。
> 前辈们是把这些通用方法**迁移/融合**到遥感、高光谱、小目标等**具体问题**上做创新。

1. "公共基础"和"论文精读"最简的判据是什么？举一个正例、一个反例。
2. 为什么"3×3 卷积"是公共基础，而"CCDD 里那个 256→48 的 3×3 卷积"是论文精读？
3. 你正读到 CFFM 那篇讲，卡在"通道池化 vs 空间池化"，应该点开哪几篇？
4. 论文轨那 12 篇顶部为什么也要写「🔗 前置基础」？这不是重复吗？
5. 如果只剩 3 天，你读哪 5 篇？为什么是这 5 篇？

<details>
<summary>👉 自测答案</summary>

**1.** 判据：**换个论文/项目还成不成立**。
- 正例：卷积、padding、ResNet、mAP —— 换任何论文都得会 → 公共基础
- 反例：CCDD、CFFM、MFAM、TAL、λ=0.5 —— 换个数据集就不存在 → 论文精读

**2.** 因为**"3×3 卷积"是一个通用操作**（任何 CNN 都用），而**"256→48 且接 PixelShuffle"是这篇论文为去雾解码器专门设计的通道压缩比例**（48 = 256/4² 这个数字是算出来的：PixelShuffle(4) 要把 48 通道重排成 3 通道的全分辨率图）。前者是工具，后者是设计。

**3.** 打开 `01-图像与卷积基础/03-池化基础`（通道池化 vs 空间池化）+ `01-图像与卷积基础/06-空间注意力图`（CFFM 的空间注意力分支）+ `01-图像与卷积基础/01-卷积基础`（7×7 Conv: 2→1 怎么来的）。

**4.** 不重复，作用相反：
- 论文轨的「前置基础」是**往下游走**（我现在读这篇，需要先懂什么）
- 基础轨的「本文用在哪」是**往上游走**（我学完这个基础，论文哪用到了它）

两条路径覆盖了不同的使用场景，合起来才是"双向可达"。少任何一条，你都只能从一个方向找。

**5.** 卷积（读懂所有数字）、ResNet（本文骨干 + 冻结编码器）、梯度下降与反向传播（联合学习的全部论证基础）、损失函数（`L = L_od + λ·L_dh` 枢纽公式）、检测与 mAP（读懂所有表格）。
理由：这 5 篇是**"不理解就完全读不下去"**的，而 padding/池化/感受野/上采样/注意力/FPN/激活函数属于**"不理解就暂时卡一下、查一下就通"**的。

## 1. 一句话定义

> [!abstract] 域泛化（Domain Generalization, DG）
> **训练时只用源域（source domain）的数据，测试时换到从未见过的目标域（target domain），希望性能不塌。**
> 目标域的数据在**训练期间一张都不能看**。

---

## 2. 为什么泛化会失败：模型在学「捷径」

模型在源域上训练时，**不仅学任务，还会顺手学一堆域特有的假线索（shortcut / spurious feature）**。

**经典例子**：训练集里所有斑马都在草原上 → 模型可能学到"草地 = 斑马"，而不是"斑马的纹理"。换到"斑马在沙地上"，模型直接崩。

**在你的雾天场景里，捷径具体长这样：**

| 域 | 模型可能学到的捷径线索 |
|---|---|
| 合成雾（HazyDet） | **全局均匀**的白雾、固定对比度衰减、无颜色偏 |
| 真实雾（RDDTS） | **非均匀**的局部雾、偏黄/偏灰、植被遮挡、雨雾混合 |

模型在合成雾上学到「均匀泛白 = 正常样本」这条捷径，换到真实雾就失效 —— 这就是 mAP 从 **54.6 掉到 28.7** 的机制。

> [!important] 所以域泛化的核心命题是
> **让模型学到的表征，只依赖任务真正需要的因素，而对域特有的统计特征不敏感。**

## 3. 域偏移的经典三分类（协变量 / 标签 / 概念）

> [!warning] 注意别和 paper-4 第 1 讲混淆
> [[paper-notes/论文精读/4-跨域高光谱精读/02-第1讲-域偏移三大来源与光谱分辨率]] 讲的"三大来源"是**高光谱特有**的（光谱分辨率不足等），和这里的**经典统计三分类**是两套东西。

| 类型 | 变了什么 | 通俗说 | 雾天例子 |
|---|---|---|---|
| **协变量偏移**（covariate shift） | p(x) 变，p(y\|x) 不变 | "**输入**的样子变了，但**正确答案的判法**没变" | 晴 → 雾。车还是车，只是看不清 |
| **标签偏移**（label shift） | p(y) 变 | "**答案的分布**变了" | 雾天里小轿车占比更高 |
| **概念偏移**（concept shift） | p(y\|x) 变 | "**正确答案的判法**变了" | 同一团模糊轮廓，合成雾里是车、真实雾里被当成杂物 |

> [!tip] 实战价值
> 域泛化能较好处理**协变量偏移**；对**概念偏移**无能为力（因为新域里"什么是车"的定义都变了）。
> **写论文时明确指出属于哪一类偏移，是审稿人很看重的严谨性。**

## 4. 三个必须懂的机制

### 4.1 MMD —— 把两个分布拉近（统计式对齐）

映射到再生核希尔伯特空间后，比较两个分布的**均值差**：

$$
\text{MMD}^2(\mathbb{P},\mathbb{Q}) = \mathbb{E}_{x,x'\sim\mathbb{P}}\big[k(x,x')\big] + \mathbb{E}_{y,y'\sim\mathbb{Q}}\big[k(y,y')\big] - 2\,\mathbb{E}_{x\sim\mathbb{P},\,y\sim\mathbb{Q}}\big[k(x,y)\big]
$$

**直觉**：在特征空间里，把源域和目标域的样本混在一起，**能不能用分类器分出谁来自哪个域** —— 分不出来，就说明分布对齐了。

**多核版本**（我们项目用的就是这个）：

$$
\text{MMD}^2 = \sum_k \beta_k\, \mathbb{E}\big[k(x,x')\big] + \sum_k \beta_k\, \mathbb{E}\big[k(y,y')\big] - 2\sum_k \beta_k\, \mathbb{E}\big[k(x,y)\big]
$$

> [!tip] 多核的好处
> 不同特征子空间用不同带宽的核，避免**单一核失效**（带宽太小分不开、太大看不出差异）。

### 4.2 GRL + 对抗 —— 让域判别器学不出来

这是 DANN（Domain-Adversarial Neural Network）的核心技巧：

```
特征 ──→ 域判别器 D ──→ 域标签（源域 / 目标域）
  │
  └──→ GRL ──→ 反向传播时梯度取反
```

**原理**：域判别器努力区分两个域，但 GRL 把编码器的梯度**取反**，于是编码器朝着"让域判别器分不出来"的方向更新。

> [!tip] 比喻
> 域判别器是**警察**，编码器是**小偷**。警察越努力抓，小偷越努力伪装成不像自己的人 —— 最后谁也认不出谁来自哪个域。

**手写版 GRL**（我们项目 `ccfa/losses/jvc.py` 就是这么写的）：

```python
class _GradientReversalFn(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, lambd):
        ctx.lambd = lambd
        return x.view_as(x)          # 前向：恒等映射

    @staticmethod
    def backward(ctx, grad_output):
        return -ctx.lambd * grad_output, None   # 反向：梯度取反
```

### 4.3 IRM —— 让最优解对所有域都一样

$$
\min_{\phi}\ \max_{\psi}\ \mathcal{R}_{\phi}^{e}(\psi)
\qquad \text{s.t.}\ \nabla_{\phi}\mathcal{R}_{\phi}^{e}(\psi) = 0,\ \ \forall\, e
$$

**要求**：存在一个分类器 psi，它**同时**在所有环境（域）里都是最优的 → 这个 psi 学到的就是"真规律"而不是"域捷径"。

> [!note] 实际很難训
> 约束是**等式**，梯度容易爆。实践中常用 **VREx** 之类的变体把等式约束换成不等式。**理解思想即可**，我们项目也没用 IRM。

## 5. 落到我们的项目：JVC / ASI / 特征记忆

### 5.1 ⚠️ 关键辨析：两篇论文里的「跨域」不是一回事

| | **论文 1（CCFA-Net）** 的 cross-domain | **论文 4（TGRS）** 的 cross-domain |
|---|---|---|
| "域"指什么 | **图像域**：雾图特征 ↔ 去雾图特征 | **数据集域**：合成雾 ↔ 真实雾（不同数据集） |
| 层次 | 特征级 | 分布级 |
| 手段 | CFFM 自适应门控融合 | JVC / ASI 显式约束不变性 |
| 类比 | "同一张图的两种版本" | "两个不同来源的数据集" |

**两者不冲突，可以叠加。** CFFM 解决的是"特征互补"，JVC/ASI 解决的是"分布对齐"。这也是**可做选题的地方**。

### 5.2 JVC（联合变量一致性）

**核心思想**：不要单独对齐特征（那会抹掉类别信息），要对齐 **(特征, 类别) 这个联合变量**。

```
联合变量 z = Embed(ROI特征, 类别标签)
   │
   ├── ① MMD 对齐两域的 z 分布        → 分布层面：两个域的联合分布一致
   ├── ② GRL + 域判别器                → 信息层面：z 里不含"来自哪个域"的信息
   └── ③ 标签分类头（守门员）           → 语义层面：z 仍然能分出类别
```

> [!important] 为什么必须有第 ③ 条
> 如果只让域判别器失效，编码器可能走极端：**把所有特征压成同一个向量**（域信息没了，类别信息也没了）。
> 所以要加一个**标签头**做守门员，保证联合变量仍然**对类别可分**。
> 这正是 "Joint Variable Consistency" 三个字的含义：**在保证类别可分的前提下，让域不可分。**

### 5.3 ASI（锚点结构不变性）

**核心思想**：特征的**内容**可以随域变，但特征的**结构关系**（谁和谁近、谁和谁远）应该跨域一致。

```
① 每个类的 ROI 特征 → Sinkhorn 软 k-means → K 个动态锚点（每类 K 个）
② 锚点图：C×K 个锚点之间的边，权重由锚点特征预测
③ 压缩跨类边（同类的锚点之间边权更强，跨类更弱）
④ 要求：源域和目标域的锚点图结构一致
```

> [!tip] 最漂亮的一点
> 锚点**内容**是动态的（跟着当前域的数据走），锚点**结构**要求跨域不变。
> 这避免了"强行把两个域的特征拉成一样"的粗暴做法 —— **保内容、锁结构**。

### 5.4 特征记忆（FeatureMemory）：为什么存特征不存图

JVC/ASI 要比较"当前域"和"**之前见过的域**"，但一个 epoch 里当前域的数据一直在变，怎么办？

**做法**：把历史域的 ROI 特征存进一个固定容量的缓冲池（`capacity=4096`，`feat_dim=256`，存 CPU，`detach()` 断掉梯度）。

```
当前 batch 的 ROI 特征 ──┐
                          ├──→ JVC / ASI 对比
特征记忆里的历史域特征 ──┘
```

> [!tip] 为什么存特征而不存原图
> 因为 JVC/ASI 只在**特征空间**做比较，不需要原始图像。
> 存特征 = 省显存、还能**跨 epoch** 持续提供对照样本。
> **这是典型的"工程 ↔ 方法"耦合设计**，写论文时要讲清楚。

## 6. 三个最常见的误解

| 误解 | 纠正 |
|---|---|
| "域泛化 = 让模型更强" | 目标是**换域不掉点**，不是源域指标更高。源域涨、目标域也涨，才是真本事 |
| "域泛化需要目标域数据" | 那是**域适应**。域泛化训练时**一张目标域图都不能看** |
| "域泛化能消除域间隙" | 只能**减小**。目标域的物理特性（如真实雾的非均匀性）无法从源域推断出来 |

## 7. 30 秒自测

1. 域适应和域泛化的**唯一关键区别**是什么？
2. 合成雾训练、真实雾测试属于协变量偏移还是概念偏移？为什么？
3. MMD 在优化的是什么量？多核的好处是什么？
4. GRL 的"梯度取反"实现了什么博弈？
5. JVC 为什么必须同时加**标签分类头**？
6. ASI 里"锚点内容动态、结构不变"这个设计，好处是什么？
7. FeatureMemory 存特征不存图，是为了解决什么问题？
8. 论文 1 的 CFFM 和论文 4 的 JVC，"跨域"分别指什么层次的域？能叠加吗？

<details>
<summary>👉 自测答案</summary>

**1.** 唯一区别是**训练期间能不能看到目标域数据**。域适应能看到（无标签也要用），域泛化**一张都看不到**，训练完直接部署。

**2.** 主要是**协变量偏移**。因为 HazyDet 与 RDDTS 的类别定义和标注标准一致（还是 car/truck/bus），变的是"图像长什么样"（雾的形态、颜色、均匀性），不是"答案怎么判"。若两域标注标准不一致，就掺进了概念偏移。

**3.** 优化的是**两个特征分布的差异**（在核空间里的均值差）。多核的好处是不同子空间用不同带宽，避免单一带宽在某些特征维度上失效。

**4.** 实现了**对抗博弈**：域判别器努力分出域，编码器借 GRL 让判别器分不出来 → 最终特征里不含域身份信息。

**5.** 防止编码器走极端 —— 只压域信息会把类别信息一起抹掉。标签头是"守门员"，保证联合变量仍然对类别可分。

**6.** 避免了"硬对齐"。强行把两域特征拉成一样会破坏簇结构；**保内容、锁结构**既保住了判别性，又让结构可跨域比较。

**7.** 因为 JVC/ASI 只在**特征空间**比较。存特征省显存，且能跨 epoch 提供稳定的对照样本（否则同一 batch 内的当前域特征每步都在变，没有稳定的"源域"可比）。

**8.** 论文 1 的 CFFM 是**图像域**（同一张图的雾版 vs 去雾版）之间的特征级融合；论文 4 的 JVC 是**数据集域**（合成雾 vs 真实雾）之间的分布级对齐。**层次不同、不冲突，可以叠加** —— 这正是"跨域特征融合 + 跨域不变性"联合框架的立论基础。

</details>

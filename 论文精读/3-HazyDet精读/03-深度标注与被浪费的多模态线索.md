# 03 · 深度标注与被浪费的多模态线索

> [!abstract] 本讲要回答
> 1. HazyDet 的深度标注**长什么样**？怎么从 PNG 还原成米？
> 2. 官方仓库那个带深度的 baseline（DeCoDet）**做了什么**？
> 3. **为什么这是本套笔记里最值钱的一块**——CCFA-Net 的缺口到底在哪？

## 1. 深度标注：怎么存的、怎么还原的

### 1.1 存储格式

| 项 | 内容 |
|---|---|
| 路径 | `Depth/normalized_depth_maps/`（**归一化**深度图） |
| 格式 | **16 位 PNG**（OpenCV 读时用 `flag='unchanged'`，否则会丢精度） |
| 值域 | 相对深度，整数 0 ~ 65535 |
| 每图最大值 | 存在 `Depth/max_depth.txt` 里，格式 `图像名 最大深度`（**带表头，跳过第一行**） |

### 1.2 还原成绝对深度（米）

代码在 `CCFANet/datasets/transforms/loading.py` 的 `LoadDualAnnotations._load_seg_map`：

```python
max_depth_map = {}
with open(max_depth_file, 'r') as f:
    for line in f.readlines()[1:]:        # 跳过表头
        parts = line.strip().split()
        if len(parts) == 2:
            image_name, max_depth = parts
            max_depth_map[image_name] = float(max_depth)

depth_map = mmcv.imfrombytes(img_bytes, flag='unchanged', backend='cv2').astype(np.float32)
max_depth = max_depth_map[image_name]

absolute_depth_map = depth_map / 65535.0 * max_depth   # 还原绝对深度
```

于是：

$$
d_{\text{abs}}(x) = \frac{d_{\text{rel}}(x)}{65535} \cdot d_{\max}
$$

> 🎯 **为什么要"归一化 + 每图单独存 max"？**
>
> 因为 **16 位 PNG 只能存整数**。如果直接存"米"，精度就浪费了。
> 所以做法是：**每张图用满 0~65535 的量程**（这样相对精度最高），
> 然后把"这张图的最大深度是多少米"单独记在 `max_depth.txt`。
>
> 类比：**温度计**。你不能直接在上面写"37.5 度"，得写刻度；
> 换算关系（刻度 ↔ 度）单独写在说明书里。
> `max_depth.txt` 就是那张"说明书"。

> ⚠️ **⚠️ 但这带来一个副作用（重要）**
> 因为**每张图各自归一化**，"这张图的最大深度"在**不同图之间不可比**。
> 也就是说：**你不能直接说"图 A 的远处比图 B 的远处更远"**。
> 如果你要做"全局深度排序"或"跨图几何关系"，**必须先反归一化**。
> 这也是为什么 `max_depth.txt` 这个文件**不能丢**。

### 1.3 深度图的读法（视觉化）

```
16-bit PNG 原始值            还原后的绝对深度
  0    65535                    0 m  --------->  d_max m
  ├──────────────┤                ├────────────┤
  近/浅            远/深
```

> 📌 **在 HazyDet 的语境下，深度图是"雾浓度图"**
>
> 回忆散射模型 `t(x) = e^(-beta·d(x))`：
> 深度图 = 雾的"浓度底图"。
> 有了它，你**可以精确地**为每个像素算出透射率，
> 也可以**逐像素验证**"雾到底把哪些目标破坏了"。
>
> 👉 **这是 HazyDet 最不可替代的价值**。别的雾天数据集给不了你这个。

## 2. 官方仓库的深度 baseline：DeCoDet

### 2.1 它的数据管线（`hazydet_dual.py`）

```python
train_pipeline = [
    dict(backend_args=None, type='LoadImageFromFile'),
    dict(
        imdecode_backend='pillow',
        type='LoadDualAnnotations',
        with_bbox=True,
        with_seg=True,                              # ← 加载深度
        max_depth_path=data_root+'Depth/max_depth.txt'),
    dict(keep_ratio=True, scale=(1333, 800), type='Resize'),
    dict(pad_val=dict(img=0, seg=255), size=(1333, 800), type='Pad'),  # ← 深度用 255 补
    dict(prob=0.5, type='RandomFlip'),
    dict(type='PackDetInputs'),
]
```

| 和单模态版的差别 | 单模态 `hazydet_det.py` | 双模态 `hazydet_dual.py` |
|---|---|---|
| 标注加载 | `LoadAnnotations(with_bbox=True)` | `LoadDualAnnotations(with_bbox=True, with_seg=True, max_depth_path=...)` |
| Resize 之后 | 直接 Pack | **多一步 `Pad`**，深度用 `255` 填充 |
| `data_prefix` | `dict(img=...)` | `dict(img=..., seg='Depth/normalized_depth_maps/')` |
| `data_root` | `/opt/data/private/fcf/HazyDet-365K/...` | `/opt/data/private/fcf/Public_dataset/HazyDet-365K/...` ⚠️ **路径还不一样！** |

> ⚠️ **三个容易漏掉的细节**
> 1. **多了一步 `Pad`**：因为深度图要跟图像**逐像素对齐**，缩放后必须补到固定尺寸。
> 2. **`seg=255` 是忽略值**：`Pad` 用 255 填深度图，而 `SIRLOSS` 的 `ignore_index=255` —— **两者必须对上**，
>    否则补出来的假深度会被当成真值监督，算出一个错误的 loss。
> 3. **两个 config 的 `data_root` 路径不一样**（`HazyDet-365K` vs `Public_dataset/HazyDet-365K`）。
>    这是官方仓库自己的不一致，你得自己确认哪个对。

### 2.2 DeCoDet 网络结构

`configs/DeCoDet/DeCoDet_r50_1x_hazydet.py`：

```python
model = dict(
    type='FCOS',
    backbone=dict(type='ResNet', depth=50, num_stages=4, out_indices=(0,1,2,3),
                  frozen_stages=1, norm_cfg=dict(type='BN', requires_grad=False),
                  norm_eval=True, style='caffe',
                  init_cfg=dict(type='Pretrained',
                                checkpoint='open-mmlab://detectron/resnet50_caffe')),
    neck=dict(type='FPN', in_channels=[256,512,1024,2048], out_channels=256,
              start_level=1, add_extra_convs='on_output', num_outs=5,
              relu_before_extra_convs=True),
    bbox_head=dict(
        type='FCOSDeCoDetHead',
        num_classes=3,
        mapping=True,
        condition_layers=1,
        con_kernel_size=7,
        group_channels=16,
        con_reduction_ratio=4,
        in_channels=256, stacked_convs=4, feat_channels=256,
        strides=[8, 16, 32, 64, 128],
        loss_cls=dict(type='FocalLoss', use_sigmoid=True,
                      gamma=2.0, alpha=0.25, loss_weight=1.0),
        loss_seg=dict(ignore_index=255, log=True, loss_weight=2.0,
                      smooth=True, type='SIRLOSS'),
        loss_bbox=dict(type='IoULoss', loss_weight=1.0),
        loss_centerness=dict(type='CrossEntropyLoss', use_sigmoid=True,
                             loss_weight=1.0)),
    test_cfg=dict(nms_pre=1000, min_bbox_size=0, score_thr=0.05,
                  nms=dict(type='nms', iou_threshold=0.5), max_per_img=100))
```

> 🎯 **一句话说清 DeCoDet 干了什么**
> **它在 FCOS 上加了一支"深度预测头"，并让深度特征反过来去调制分类和回归分支。**
> 不是"检测 + 深度"两个平行任务，而是**深度 → 检测**的**条件化**。

### 2.3 核心机制：深度条件化（DCK）

`CCFANet/models/dense_heads/fcos_DeCoDetHead.py`：

```python
def forward_single(self, x, scale, stride):
    cls_feat = x;  reg_feat = x;  seg_feat = x
    seg_feats = [seg_feat]
    for seg_layer in self.seg_convs:          # ① 深度分支逐层卷积
        seg_feat = seg_layer(seg_feat)
        seg_feats.append(seg_feat)

    for i, cls_layer in enumerate(self.cls_convs):   # ② 深度调制分类
        cls_feat_condi = self.cross_involution_cls(cls_feat, seg_feats[i+1])
        cls_feat = cls_feat + cls_feat_condi         # 残差式相加
        cls_feat = cls_layer(cls_feat)

    for i, reg_layer in enumerate(self.reg_convs):   # ③ 深度调制回归
        reg_feat_condi = self.cross_involution_reg(reg_feat, seg_feats[i+1])
        reg_feat = reg_feat_condi + reg_feat
        reg_feat = reg_layer(reg_feat)

    seg_score = self.conv_seg(seg_feats[-1])          # ④ 深度预测输出
    ...
    if self.mapping: seg_score = self.map(seg_score)  # ReLU
    else:            seg_score = self.absolute(seg_score)  # Sigmoid
```

数据流图：

```
            x (FPN 特征, 256ch)
            │
      ┌─────┴─────────────────────────────┐
      │                                   │
  seg_convs                          cls_convs / reg_convs
      │                                   │
  seg_feats[1..k]  ──── DCK 调制 ─────────┘
      │                                   │
  conv_seg → seg_score (深度预测)      conv_cls / conv_reg (检测输出)
```

| `DCKModule` 参数 | 值 | 含义 |
|---|---|---|
| `con_kernel_size` | 7 | 条件卷积核大小 |
| `group_channels` | 16 | 分组卷积的每组通道数（`groups = 256/16 = 16` 组） |
| `con_reduction_ratio` | 4 | 瓶颈压缩比（先降维再升维，省算力） |
| `condition_layers` | 1 | 条件化的层数 |

> 📌 **为什么要"分组 + 瓶颈"？**
> 因为 DCK 要根据深度特征**生成卷积核**（动态核）。
> 如果每个位置都要生成一个 7×7×256×256 的核，**开销爆炸**。
> 分组卷积 + 瓶颈压缩把参数量压下来了。
> 👉 这个思路在 CCFA-Net 的 **CFFM / MFAM** 里也有（注意力 + 通道压缩），是**通用工程技巧**。

### 2.4 SiLog 损失（本讲最该学的公式）

`CCFANet/models/losses/SIRloss.py`：

```python
valid_mask = ((label >= 0) & (label != ignore_index)).float()
if self.log:
    pred  = torch.log(torch.clamp(pred,  min=1e-6))
    label = torch.log(torch.clamp(label, min=1e-6))
if self.smooth:
    label = (1 - self.epsilon) * label + self.epsilon * pred

pred_valid  = pred  * valid_mask
label_valid = label * valid_mask
diff = pred_valid - label_valid
nvalid_pix = torch.sum(valid_mask)

depth_cost = (torch.sum(nvalid_pix * torch.sum(diff**2))
              - 0.5 * torch.sum(torch.sum(diff)**2)) \
             / torch.maximum(torch.sum(nvalid_pix**2), torch.tensor(1.0))

return self.loss_weight * depth_cost
```

翻译成公式。记有效像素数 `n`、逐像素对数误差 `d_i`：

$$
d_i = \log \hat{y}_i - \log y_i
$$

$$
L_{\text{SiLog}} = \frac{1}{n} \sum_{i=1}^{n} d_i^2 \;-\; \frac{\lambda}{2 n^2} \left( \sum_{i=1}^{n} d_i \right)^2
$$

代码里 `lambda = 0.5`（对应 `- 0.5 * ...` 那一项，且分母是 `n^2`）。

| 开关 | 作用 | 直观含义 |
|---|---|---|
| `log=True` | 在**对数空间**算误差 | 深度是乘性量，对数空间算误差 = **相对误差** |
| `smooth=True` (eps=0.1) | `label ← 0.9·label + 0.1·pred` | 把真值往预测方向拉一点，**抑制离群点** |
| `ignore_index=255` | 跳过填充区 | 和 `Pad` 的 `seg=255` 对应 |
| `loss_weight=2.0` | 深度损失权重 | **深度是辅助任务，权重不宜过大** |

> 🎯 **类比 · 为什么要在对数空间算误差？**
>
> 深度是**米**，量级可能差几十倍（近处 5 米，远处 200 米）。
> 如果在**线性空间**算平方误差：
> - 一个 200 米处错了 10 米 → 误差 100
> - 一个 5 米处错了 2.4 米 → 误差 5.76
>
> 看起来"远处错一点"更严重，其实**近处的 2.4 米错得离谱得多**（相对误差 48% vs 5%）。
>
> 取对数后：
> - `log(210) - log(200) = 0.0488`
> - `log(7.4) - log(5) = 0.392`
> **近处的错现在被正确地重罚了。** 这就是"scale-invariant"（尺度不变）的含义。

> 📐 **SiLog 的"不变"指的是什么不变？**
> 它对**全局尺度偏移**不变：
> 如果预测整体乘了个常数 `c`，对数误差只是**整体平移**一个常数 `log c`，
> 而第二项 `- (lambda/2n^2)(sum d)^2` **恰好把常数平移那一部分扣掉**。
> 👉 这就是为什么要减掉那一项。

> 📌 **注意 `smooth` 的细节**
> `label ← (1-eps)·label + eps·pred` 里，**真值被往预测方向拉**。
> 这是一种"标签平滑"的深度版，用来**降低对噪声/离群深度值的敏感度**。
> ⚠️ 但注意它是**有偏的**（真值被改了），eps=0.1 意味着 10% 的偏移。

## 3. 🔥 核心论点：CCFA-Net 把深度**浪费**了

### 3.1 事实核对

| 事实 | 证据 |
|---|---|
| HazyDet **有**深度标注 | `Depth/normalized_depth_maps/` + `max_depth.txt` |
| 官方仓库**有**深度 baseline | `configs/DeCoDet/DeCoDet_r50_1x_hazydet.py` + `FCOSDeCoDetHead` + `SIRLOSS` |
| CCFA-Net **完全没用深度** | 它的输入只有 RGB；它去雾靠的是 **DCP 暗通道先验** |
| 论文里的"深度"只是**背景知识** | 散射模型 `t = e^(-beta·d)` 用来**解释**为什么远处更糊，不是用来**建模**的 |

### 3.2 这为什么是个真缺口（不是"锦上添花"）

CCFA-Net 的核心论点是：**去雾子网络的 Lipschitz 常数低（平滑）↔ 检测子网络 Lipschitz 常数高（判别），两者不匹配会破坏整体稳定性**。
它的解法是 **CFFM（跨域特征融合）**—— 让雾域特征和净域特征**自适应互补**。

> ❓ **但是："净域"是什么？**
>
> CCFA-Net 的"净域"来自 CCDD 去雾分支的输出。
> 也就是说：**它用"猜出来的干净图"当参照系。**
>
> 🔥 **而 HazyDet 明明给了你真值深度图！**
> 深度图 = **精确的场景几何** = **比"猜出来的干净图"可靠得多的参照系**。

三个具体的、可落地的改进方向：

| # | 想法 | 为什么可能有效 | 难度 |
|---|---|---|---|
| **①** | 用**真值深度**（训练时）替换/辅助 CFFM 的"净域"参照 | 深度是无监督的**精确几何**，比去雾输出更可靠 | 低（数据现成） |
| **②** | 把**深度作为条件**调制检测分支（像 DeCoDet 那样） | 深度直接告诉你"这个位置的雾有多浓"，**前景/背景先验天然就有了** | 中 |
| **③** | 用深度构造**物理一致性约束**：预测的透射率 `t` 应与 `d` 单调相关 | 让去雾分支在**物理上**自洽，而不是只靠暗通道先验瞎猜 | 中高（要改 CCDD） |

> 🎯 **为什么 ② 特别对路 CCFA-Net 的痛点**
>
> CCFA-Net 的 MFAM 靠**注意力**去学"哪里是前景"，
> 而 **注意力必须从数据里学**——它不知道"远处的东西天然更该被关注"。
> 但**深度是白送的**：一个目标离相机 80 米，它一定比 10 米处的目标更模糊。
> 👉 **深度 = 免学费的前景/尺度先验。**

### 3.3 和第 2 篇（Cross-Modal UAV）的呼应

| | 第 2 篇 Cross-Modal UAV | 第 3 篇 HazyDet | CCFA-Net |
|---|---|---|---|
| 第二模态 | **IR 红外** | **Depth 深度** | ❌ 没用 |
| 怎么用 | **蒸馏**：IR 分支当老师教 RGB | 有真值，可直接监督 | —— |
| 部署时 | 只留 RGB（IR 全删） | —— | —— |
| 核心问题 | **模态鸿沟** | **模态被浪费** | **雾域净域不匹配** |

> [!tip] 关键洞察
> **第 2 篇和第 3 篇其实在讲同一件事的两面：**
> 第 2 篇说"**跨模态要用蒸馏来跨鸿沟**"，
> 第 3 篇说"**这里有一条现成的第二模态（深度），但没人用**"。
>
> 👉 **把 1 + 2 + 3 拼起来，就是一个完整的研究故事**：
> "在 UAV 雾天检测中，用**深度**作为跨域的**几何锚点**，
> 通过**蒸馏/条件化**把深度信息注入 RGB 检测器，
> 解决 CCFA-Net 的**净域参照不可靠**问题。"

## 4. ❓ 自测

1. 深度图为什么存成"16 位 PNG 相对值 + 每图单独存 max_depth"？这样做的副作用是什么？
2. SiLog 损失为什么要在对数空间算？`- (lambda/2n^2)(sum d)^2` 那一项在起什么作用？
3. `Pad` 时深度用 `255` 补、`SIRLOSS` 的 `ignore_index=255`，如果这两处对不上会怎样？
4. DeCoDet 的深度分支是**平行任务**还是**条件化**？证据在代码哪一行？
5. 用一句话说明"深度对 CCFA-Net 意味着什么机会"，并说出一个具体可行的做法。

<details>
<summary>👉 折叠答案</summary>

1. 因为 16 位 PNG 只能存整数，直接存"米"浪费精度；归一化后每张图用满量程，相对精度最高。副作用：**每张图各自归一化，跨图深度不可比**，必须先反归一化才能做全局几何分析。

2. 深度是乘性量，线性空间的平方误差会让"远处小误差"看起来更大，**相对误差完全失真**；取对数后误差变成相对误差量级。第二项的作用是**扣掉全局尺度平移**，让损失对"整体乘个常数"不敏感（这才是 scale-invariant）。

3. 补出来的 255 会被当成真值参与监督 —— 而 255 米显然荒谬 → 深度 loss 被污染，训练不稳定。**两处必须严格一致。**

4. **条件化**。证据：`cls_feat_condi = self.cross_involution_cls(cls_feat, seg_feats[i+1])`，然后 `cls_feat = cls_feat + cls_feat_condi`——深度特征被用来**生成卷积核调制分类分支**，而不是只算一个深度输出就完事。

5. 机会：**深度 = 免费的几何锚点**。CCFA-Net 的 CFFM 用"猜出来的净域特征"当参照系，这个参照本身是模糊的；真值深度是精确的场景几何，可靠得多。可行做法：训练时用真值深度构造一个"深度引导的净域分支"（或直接像 DeCoDet 那样把深度作为条件调制检测头），推理时是否保留深度则是一个"要不要多一个传感器"的取舍问题。

</details>

## 1. 合成雾是怎么造出来的

### 1.1 物理模型（你已经在 CCFA-Net 里学过）

$$
I(x) = J(x) \cdot t(x) + A \cdot \bigl(1 - t(x)\bigr), \qquad t(x) = e^{-\beta \cdot d(x)}
$$

| 符号 | 含义 | HazyDet 里对应什么 |
|---|---|---|
| `J(x)` | 清晰图（ground truth） | 无人机拍的原始清晰照片 |
| `I(x)` | 加雾图（input） | 模型真正看到的 |
| `A` | 大气光（全局常数） | 雾的"亮度基准"，通常是偏灰白 |
| `d(x)` | **深度** | 需要深度图 → 所以 HazyDet 要深度标注 |
| `beta` | 散射系数 | 雾的浓度参数 |

> 🎯 **类比 · 一杯水里看东西**
> 你透过一杯浑水看水底的硬币：
> - `t(x)` = 水有多清（近处的水底 `t` 大，看得清；远处的水底 `t` 小，看不清）
> - `A` = 水本身散射出来的灰白色
> - `d(x)` = 硬币有多深
>
> **关键洞察**：因为 `t` 依赖深度，**同一个画面里，近处和远处的"受雾程度"不一样**。
> 这就是为什么 UAV 图像特别吃亏 —— 同样的雾，地面近处的目标还能看清，远处山上的目标就糊了。

### 1.2 合成流程（一张图讲完）

```
 原始清晰无人机图  J  (8000 / 1000 / 2000 张)
        │
        ├─ ① 取深度图 d(x)  ──────────────┐
        │                                 │
        ├─ ② 采样大气光 A（全局常数）      │
        │                                 │
        └─ ③ 采样散射系数 beta ────────────┤
                                          ▼
                          I(x) = J(x)·t(x) + A·(1 - t(x)),  t(x)=e^(-beta·d(x))
                                          │
                                          ▼
                              加雾图 hazy_images/  ← 模型输入
                              清晰图（不进 pipeline，作为 GT 的来源）
```

> ⚠️ **三个重要事实（论文侧）**
> 1. **框只有一份**：检测框是从清晰图继承的，加雾不改变框。所以"加雾"这一步**不产生标注**，标注就是清晰图的标注。
> 2. **合成不等于真雾**：真实雾的 `beta` 是**随空间变化**的（有的地方雾浓、有的地方薄），而且有**体积散射**、**太阳眩光**、**去雾留下的光晕**。合成模型只有均匀 beta。
> 3. **这正是合成雾 → 真实雾掉 25.9 个点的原因**（CCFA-Net：HazyDet 54.6 → RDDTS 28.7）。

> 📐 **数字账 · 为什么合成雾"偏容易"**
> 合成雾里，**雾的浓度是你自己设的**，所以"远处的目标该糊成什么样"你心里有数。
> 检测器只要学会"按深度衰减"这一条规则就能拿高分。
> 真实雾里，浓度分布是未知的、随机的 —— 检测器必须**先估计雾在哪、有多浓**，再去处理。
> 👉 **所以在 HazyDet 上刷到 60 分，不代表能上真实雾。**

## 2. 标注文件：COCO JSON 格式

HazyDet 用的是**标准 COCO 格式**（这点很省事，现成的 `pycocotools` 直接能读）。

### 2.1 顶层结构

```
{
  "images":      [ ... ],   # 每张图一条
  "annotations": [ ... ],   # 每个框一条
  "categories":  [ ... ]    # 类别表
}
```

### 2.2 `images` 里有什么

```json
{
  "id": 1024,
  "file_name": "0001024.jpg",
  "height": 1080,
  "width": 1920
}
```

| 字段 | 含义 | 你要干什么 |
|---|---|---|
| `id` | 图像唯一 ID | 把它传给 mmdet 的 `img_id` |
| `file_name` | 文件名（**相对** `data_prefix.img`） | 拼路径用 |
| `height` / `width` | 图像尺寸 | **裁剪框、算面积**都要用 |

### 2.3 `annotations` 里有什么

```json
{
  "id": 881234,
  "image_id": 1024,
  "category_id": 1,
  "bbox": [640.5, 412.0, 96.3, 58.1],
  "area": 5595.0,
  "iscrowd": 0,
  "segmentation": []
}
```

| 字段 | 含义 | ⚠️ 陷阱 |
|---|---|---|
| `bbox` | **`[x, y, w, h]`** —— 左上角 x/y + 宽/高 | **不是** xyxy！COCO 用的是 xywh |
| `area` | 框面积 | 与 `w*h` 不一定严格相等 |
| `iscrowd` | 1 = 密集/群体区域 | mmdet 里会转成 `ignore_flag` |
| `segmentation` | 分割多边形 | HazyDet 里基本为空 |

### 2.4 `categories` —— **只有 3 类**

```json
[
  {"id": 1, "name": "car",   "supercategory": "vehicle"},
  {"id": 2, "name": "truck", "supercategory": "vehicle"},
  {"id": 3, "name": "bus",   "supercategory": "vehicle"}
]
```

> ⚠️ **cat_id 不等于 label**
> `category_id` 是 COCO 里的原始 ID（这里是 1/2/3），但 mmdet 内部要转成**从 0 开始的连续 label**：
>
> $$
> \text{bbox\_label} = \text{cat2label}[\text{category\_id}], \qquad \text{cat2label} = \{\,\text{cat\_id} \mapsto 0,1,2\,\}
> $$
>
> 所以 **car=0, truck=1, bus=2**。
> ⚠️ **但 COCO 标准数据集是 80 类，cat_id 和 label 差 1**（COCO 的 cat_id 从 1 开始但有空洞）。
> 这是新手最容易搞混的地方 —— 见第 04 讲的 `num_classes=80` 那个坑。

## 3. mmdet 读它时做了什么（**逐行看代码**）

官方仓库 `CCFANet/datasets/hazydet.py` 里的 `HazyDetDataset` 继承自 `CocoDataset`，只重写了一个方法：`parse_data_info`。

### 3.1 bbox 格式转换（必看）

```python
x1, y1, w, h = ann['bbox']          # COCO 的 xywh
...
bbox = [x1, y1, x1 + w, y1 + h]     # 转成 mmdet 的 xyxy
instance['bbox'] = bbox
```

> 🎯 **为什么必须转？**
> 因为 mmdet 内部统一用 **`[x1, y1, x2, y2]`**（左上 + 右下 两个角点）。
> 而 COCO 官方格式用 **`[x, y, w, h]`**（左上 + 宽高）。
> 两种表示混用 = **框整体错位**，而且错位方式很隐蔽：
>
> 假设真框是 xywh = `[100, 100, 50, 40]`（即 x:100~150, y:100~140）
> 如果直接当 xyxy 用 → x2=50, y2=40 → **框变成了 x:100~50, y:100~40**，**面积为负** → 被丢弃。

### 3.2 六条丢弃规则（**会悄悄改变你的指标**）

```python
if ann.get('ignore', False):        continue   # ① 显式忽略
inter_w = max(0, min(x1+w, W) - max(x1, 0))
inter_h = max(0, min(y1+h, H) - max(y1, 0))
if inter_w * inter_h == 0:          continue   # ② 裁剪到图外后面积为 0
if ann['area'] <= 0 or w < 1 or h < 1: continue # ③ 面积/尺寸非法
if ann['category_id'] not in self.cat_ids: continue # ④ 不属于 car/truck/bus
```

第 5、6 条是**标记**而非丢弃：

```python
instance['ignore_flag'] = 1 if ann.get('iscrowd', False) else 0
instance['bbox_label'] = self.cat2label[ann['category_id']]
```

| 字段 | 含义 | 谁会用到它 |
|---|---|---|
| `ignore_flag` | 1 = 这块是"密集区域"，**不算错也不算对** | 样本分配（ATSS / TAL）会跳过它 |
| `bbox_label` | 0/1/2 = car/truck/bus | 分类损失 |

> ⚠️ **最容易被忽略的第 2 条**
> 规则 ② 是**把框裁到图像范围内**再算面积。
> 也就是说**贴边的框会被缩小**。
> 这在 UAV 数据里很常见（车被画面边缘切一半），
> 而**小目标恰恰是 UAV 检测的命门** —— 缩小 20% 对小目标 IoU 的影响远超大目标。

## 4. 数据是怎么分目录的

配置 `configs/_base_/datasets/hazydet_det.py`：

```
data_root = '/opt/data/private/fcf/HazyDet-365K/data/HazyDet365K/'
```

```
HazyDet365K/
├── train/
│   ├── hazy_images/     ← 加雾图（模型输入）
│   ├── clear_images/    ← 清晰图（可选，用于对比实验）
│   └── train_coco.json
├── val/
│   ├── hazy_images/
│   └── val_coco.json
├── test/
│   ├── hazy_images/
│   └── test_coco.json
└── Depth/
    ├── normalized_depth_maps/
    └── max_depth.txt
```

| Split | 图片目录 | 标注文件 | `data_prefix.img` |
|---|---|---|---|
| Train | `train/hazy_images/` | `train/train_coco.json` | ✅ |
| Val | `val/hazy_images/` | `val/val_coco.json` | ✅ |
| Test | `test/hazy_images/` | `test/test_coco.json` | ✅ |

> ⚠️ **`data_root` 是硬编码的绝对路径** —— 这是复现第一道坎，见 [[04-复现必查项与坑]]。

### 4.1 数据加载 pipeline

```python
train_pipeline = [
    dict(type='LoadImageFromFile'),
    dict(type='LoadAnnotations', with_bbox=True),
    dict(type='Resize', scale=(1333, 800), keep_ratio=True),
    dict(type='RandomFlip', prob=0.5),
    dict(type='PackDetInputs')
]
```

| 步骤 | 做什么 | 你要理解的点 |
|---|---|---|
| `LoadImageFromFile` | 读图 | |
| `LoadAnnotations` | 读框 | bbox 已转成 xyxy |
| `Resize(1333, 800, keep_ratio=True)` | 缩放到**短边 800**，长边不超过 1333，**保持长宽比** | `keep_ratio=True` 保证车不会被压扁 |
| `RandomFlip(0.5)` | 水平翻转 | 唯一的数据增强 |
| `PackDetInputs` | 打包成 batch | |

> 📐 **数字账 · 为什么要 1333×800**
> COCO 的标准输入尺寸就是 1333（长）× 800（短）。
> 无人机图像通常是 1920×1080（16:9）。缩到短边 800 → 长边约 1422 > 1333，
> 于是长边被压到 1333，最终约 **1333×750**。
>
> ⚠️ **对小目标的影响**：一个 20 像素宽的车，缩放后只剩约 14 像素。
> 这就是为什么 UAV 检测普遍要用 **FPN + 多尺度**——单尺度下小目标特征就没了。
> 👉 参见 [[paper-notes/论文精读/1-CCFA-Net精读/01-公共基础知识/07-FPN特征金字塔|FPN 特征金字塔]]。

### 4.2 `filter_cfg`：训练和验证**不一样**（⚠️ 坑）

```python
# 训练集
filter_cfg=dict(filter_empty_gt=True, min_size=32)
# 验证 / 测试集
# 没有 filter_cfg !!!
```

| 参数 | 含义 |
|---|---|
| `filter_empty_gt=True` | 丢掉**一个框都没有**的图 |
| `min_size=32` | 丢掉**所有框的最小边都 < 32 像素**的图 |

> ⚠️ **⚠️ 关键坑：训练和验证的过滤规则不一致**
>
> - **训练时**：极小目标（<32px）的图被**整张丢掉**
> - **验证时**：**不过滤**，所有图都评
>
> 这意味着：
> 1. **训练分布 ≠ 验证分布**（训练集里"没有极小目标的图"）
> 2. 你在验证集上看到的 AP_small 会**低于**训练分布下的表现
> 3. **如果你换数据集或改 `min_size`，指标不可比**
>
> 👉 这条在第 04 讲会再强调一次，因为它**直接影响你能否复现论文数字**。

## 5. ❓ 自测

1. 为什么 HazyDet 需要深度图才能合成雾？换个不用深度的数据集行不行？
2. COCO 的 `bbox` 是 xywh，mmdet 是 xyxy。如果忘了转换，会出现什么现象？
3. `iscrowd=1` 的框为什么不直接丢掉，而是标成 `ignore_flag=1`？
4. `filter_cfg` 里 `min_size=32` 过滤掉的是"小目标"还是"小图像"？它为什么只加在训练集上？
5. 为什么合成雾数据集上训好的模型，到真实雾上会掉 25.9 个点？

<details>
<summary>👉 折叠答案</summary>

1. 因为物理模型里 `t(x) = e^(-beta·d(x))`，**透射率必须靠深度才能算**。不用深度也行，但只能做"全图统一浓度"的假雾 —— 那就不是物理合成了，而且没法研究"距离-对比度"关系。

2. **框整体错位**：把 `[x, y, w, h]` 当 `[x1,y1,x2,y2]` 用，框会缩成 `[x, y, w, h]` 那个小矩形，右下角坐标错成 w 和 h。典型现象是**框变得极小且位置怪**；面积变负时会被规则 ② 丢掉，表现为"**标注大量消失 / 训练学不到东西**"。

3. 因为 `iscrowd=1` 表示"密集的一群人/一片车"，它**既不能算漏检（那儿确实有东西）也不能算误检（框得对）**。丢掉 → 变成漏检，惩罚模型；算作正常正样本 → 强迫模型学一个根本学不会的目标。标成 ignore 让样本分配跳过它，评测时也不惩罚。

4. **过滤的是"小图像"**（准确说是"所有目标都太小的图"，不是过滤掉图里的小目标）。`min_size=32` 说的是**每个框的最短边**，一张图里只要有一个框 ≥32px，图就留下。只加在训练集是因为**评测必须用完整数据**（过滤掉等于改考卷），而训练时可以为了训练效率丢掉"全是小目标、几乎学不到东西"的图。

5. 三个原因：① 合成雾的 `beta` **空间均匀**，真实雾有浓淡变化，检测器要先估计雾分布；② 真实雾有**体积散射/光晕/眩光**，合成模型没有；③ 合成雾的母图是清晰图，**标注本身没有噪声**，真实雾（尤其夜间）标注质量会掉。

</details>

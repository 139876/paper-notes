# 📑 HazyDet · 总索引

> [!info] 这是**第 3 篇（数据篇）**

## 📌 论文信息

| 项 | 内容 |
|---|---|
| 标题 | HazyDet: Open-Source Benchmark for Drone-View Object Detection With Depth Cues in Hazy Scenes |
| 作者 | Chenjie Feng, Zhaoyi Chen, Xiaoming Li, Chunyang Wang, Jin Yang, Ming-Ming Cheng, Yimian Dai, Qiang Fu |
| 出处 | arXiv:2409.19833（2024），后收录于 ISPRS JPRS |
| 代码仓库 | `https://github.com/GrokCV/HazyDet`（论文标注 `https://github.com/YimianDai/open-HazyDet`） |
| 任务 | 无人机视角 **雾天** 目标检测（水平框，3 类） |
| 特殊之处 | **带深度标注** —— 这是它区别于所有其他雾天检测数据集的地方 |
| 类别 | Car / Truck / Bus（**只有 3 类**） |
| 规模 | Train 8000 / Val 1000 / Test 2000 = **11000 对**（8:1:2） |
| 在阅读清单中的位置 | [[paper-notes/论文精读/00-总索引-四篇论文|第 3 篇]] · **数据** 篇 |

**一句话总结**

> HazyDet 做了一件很朴素但很关键的事：**把"雾天无人机看车"这件事从玩具变成了标准题**。
> 它用同一批清晰无人机图像**合成**出配对的雾天图像（所以每个目标有精确的框），
> 再额外附上**深度图**——于是"雾的浓度到底跟距离什么关系"第一次可以被**验证**，
> 而不是只能靠公式脑补。

## 📊 核心数字速查（务必背下来）

### 数据规模（CCFA-Net 原文 Table 1）

| Split | 图像数 | Car | Truck | Bus | 目标总数 |
|---|---|---|---|---|---|
| Train | 8000 | 242,195 | 11,626 | 10,690 | **264,511** |
| Val | 1000 | 31,562 | 1,508 | 1,490 | **34,560** |
| Test | 2000 | 60,026 | 2,553 | 2,743 | **65,322** |
| **合计** | **11000** | 333,783 | 25,687 | 24,923 | **364,393** |
| RDDTS（真实雾） | 600 | 18,220 | 521 | 555 | **19,296** |

> 📐 **数字账 · 类分布极度不均衡**
> 三个 split 里 Car 都占了 **91%** 以上（264,511 / 364,393 ≈ 72.6%… 不对，按 split 算：Train 里 Car 占 91.6%）。
> Truck 和 Bus 各自只有 **4.4%** 和 **4.0%**。
> 👉 这直接解释了 CCFA-Net 论文里 **Truck 的 AP（37.5）远低于 Car（62.2）** —— 不是模型差，是样本少 + 难。

### 与 CCFA-Net 主结果的对应

| 项 | 数值 | 出处 |
|---|---|---|
| CCFA-Net 在 HazyDet-Test 的 mAP | **54.6** | CCFA-Net Table 2 |
| 分类别 AP | Car 62.2 / Truck 37.5 / Bus 64.2 | 同上 |
| TOOD baseline（不含 CCFA-Net） | 50.8 | CCFA-Net Table 8 消融 |
| CCFA-Net 在 RDDTS（真实雾）上的 mAP | **28.7** | CCFA-Net Table 2 |

> ⚠️ **注意这个断崖**：合成雾 54.6 → 真实雾 28.7，**掉了 25.9 个点**。
> 这是**你未来选题的富矿**：合成雾到真实雾的域间隙（domain gap），比"在合成雾上再涨 0.5"有价值得多。

## ⚡ 三句话抓住这一篇

1. **它是一份"配对"数据集**：清晰图 ↔ 合成雾图 一一对应，所以检测框在两张图上完全一致，可以逐像素研究"雾把什么破坏了"。
2. **它带深度**：HazyDet 是少见的**有深度真值**的雾天检测数据集，这让它成为"雾—距离关系"这类研究的**唯一硬地基**。
3. **它只被用了一半**：CCFA-Net **只吃 RGB，完全没用深度** —— 这不是缺陷，是**留给你的接口**。

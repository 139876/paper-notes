## D.3 🔴 坑 ①：IoU 损失写错语义 → **回归分支彻底死锁**

**位置**：`/Users/yoyo/Documents/Codex/2026-11-08/ban/outputs/CCFA-Net-repro/ccfa/losses/detection.py:38`

```python
def iou_loss(pred, target, mode: str = "linear") -> torch.Tensor:
    ious = bbox_overlaps(pred, target)
    if mode == "log":
        return -ious.log()
    return 1.0 - ious          # ← 实际走的是这条
```

**症状**：整个 suite 6 个实验的 mAP 全部在 **1e-6 ~ 1e-7**（等于 0）；
`loss_bbox` **恒等于 1.00000**，从 step 0 到 step 150 一动不动。

### 单图过拟合对照实验（实测）

| 损失 | loss_bbox 轨迹 | max IoU(预测, GT) |
|---|---|---|
| A. `1 - IoU`（当前实现） | 0.99999 → **1.00000 不动** | **0.0217** |
| B. `-log(IoU)`（不加 clamp） | 13.79 → **nan** | — |
| C. **GIoU** | 1.839 → 0.993 → **0.9636 在降** | **0.2519**（↑11.6×） |

### 为什么 A 会死锁

1. 回归头输出的是**无约束**的 ltrb，初始值 ≈ N(0, 0.01) → 预测框常是**退化/翻转**的
2. 退化框与 GT 框**完全不相交** → `IoU ≡ 0`（精确的 0，不是"很小"）
3. `1 - IoU` 对不相交的框**梯度恒为 0**（IoU 是分段常数）→ **永远学不动**
4. `loss_bbox` 卡在 1.0，分类损失照常下降 → **看起来"在训练"，其实回归分支是死的**

### 为什么 C（GIoU）能救

GIoU 引入「**包围框面积**」这一项：

$$
\text{GIoU} = \text{IoU} - \frac{|C \setminus (A \cup B)|}{|C|}
$$

两个框**完全不相交**时，第二项仍然有非零梯度 → 框能被"拉"向彼此。

### 这不是抄近路 —— 官方 config 本来就用 GIoU

| 配置 | loss_bbox |
|---|---|
| `configs/fcos/fcos_r50_fpn_1x_hazydet.py:48` | `IoULoss(loss_weight=1.0)` |
| `configs/DeCoDet/DeCoDet_r50_1x_hazydet.py:67` | `IoULoss(loss_weight=1.0)` |
| **`configs/vfnet/DeCoDet_vfnet_r50_fpn_1x_hazydet.py:64`**（**论文 Table 4 对应的就是这版**） | **`GIoULoss(loss_weight=1.5)`** |

> ⚠️ **为什么 mmdet 那个 `IoULoss` 用 linear 也没事？**
> 因为 mmdet 的 `IoULoss` 默认 **`iou_mode='log'`**，不是 linear。
> 两种模式的**梯度尺度完全不同**：
> - `log` 模式：$-\log(\text{IoU})$，梯度里带 $1/\text{IoU}$ 因子 → **把微小的重叠放大成可用的梯度**
> - `linear` 模式：$1-\text{IoU}$，梯度 ∝ $\partial\text{IoU}/\partial x$ → 不相交时**直接归零**
>
> 👉 **教训**：移植损失函数时，**必须连"默认参数"一起移植**。
> 只抄公式不抄默认值 = 静默改变优化动力学。

### 修法（三选一）

| 方案 | 改法 | 评价 |
|---|---|---|
| ✅ **改用 GIoU** | 实现 GIoU，config 换 `GIoULoss` | **最推荐**：和论文 Table 4 的官方 config 一致，且不重叠时有梯度 |
| 改用 mmdet 语义 | `loss = -bbox_overlaps(p,t).clamp(min=1e-6).log()` | 需注意 nan（实测不加 clamp 会 nan） |
| 加约束 | `ltrb = F.softplus(raw)` 保证 l,t,r,b > 0 | 能避免负边，但改变了 FCOS 语义 |

## D.4 🔴 坑 ②：水平翻转把框坐标写反了

**位置**：`/Users/yoyo/Documents/Codex/2026-11-08/ban/outputs/CCFA-Net-repro/ccfa/data/hazydet.py:207`

```python
if flip:
    resized = np.ascontiguousarray(resized[:, ::-1])
    ...
    boxes_arr[:, 0] = new_w - boxes_arr[:, 2]      # 第一步对
    boxes_arr[:, 2] = new_w - boxes_arr[:, 0]      # ← 第二步用了【已被改写的 x1】
```

**实测**（`new_w = 640`，原框 `[100, 50, 200, 90]`）：

| 实现 | 结果 | 宽度 |
|---|---|---|
| 当前 | `[440, 50, 200, 90]` | **-240** ❌ |
| 正确 | `[440, 50, 540, 90]` | 100 ✅ |

**后果**：`flip_prob=0.5` → **一半训练图的框宽度为负**
→ `_assign` 里 `r > 0` 不成立 → 这些图**零正样本**，
而且分类分支被喂了错位的监督信号。

**正确写法**（同时交换并镜像）：

```python
boxes_arr[:, [0, 2]] = new_w - boxes_arr[:, [2, 0]]
```

> 🎯 **这类 bug 的通用形态**：
> **"就地修改" + "后面又读了被修改的值"**。
> 正确写法要用**同时赋值**（`a[:, [0,2]] = ...`），一次性从旧值算出新值。

## D.5 坑 ③：`use_seg` / `use_dck` 是耦合的

**位置**：`/Users/yoyo/Documents/Codex/2026-11-08/ban/outputs/CCFA-Net-repro/ccfa/modeling/fcos.py:165`

```python
self.use_dck = use_dck and use_seg     # ← 复现里加了这层保护
```

原因：`seg_feats` 只有在 `use_seg=True` 时才会累积到 ≥2 个元素；
若 `use_dck=True` 而 `use_seg=False`，`seg_feats[j+1]` 会 **IndexError**。

> 📌 官方 `FCOSDeCoDetHead` 里深度分支是**常驻**的（`_init_seg_convs()` 无条件调用），
> 所以没有这层显式保护；复现里加它是**等价且更安全**的写法。

## D.7 🎓 复现纪律：**先写"预期输出"，再写实现**

> [!important] 一条能省两周的规矩
> `loss_bbox` 恒等于 1.0000 这种信号，**在你写完 3150 行后的第 5 分钟就该被发现**，
> 而不是跑完整个 suite 才发现。

**具体做法**：每写一个损失/算子，先写一个 20 行的小单测，断言**几个你确定的值**：

```python
# tests/test_iou_loss.py —— 三个 case 就够
def test_iou_loss():
    # ① 完全重合 → IoU = 1 → loss = 0
    box = torch.tensor([[0., 0., 10., 10.]])
    assert abs(loss_bbox(box, box).item() - 0.0) < 1e-6
    # ② 部分重合 → loss 必须 < 1（线性模式）
    # ③ 完全不相交 → 线性模式 loss = 1 且【梯度为 0】← 这就是死锁的根源
    a = torch.tensor([[0., 0., 1., 1.]], requires_grad=True)
    b = torch.tensor([[50., 50., 51., 51.]])
    loss = loss_bbox(a, b); loss.backward()
    assert loss.item() > 0.9
    assert a.grad.abs().sum() < 1e-6, "线性 IoU 在不相交时梯度为 0 —— 会死锁"
```

**推广**：任何"预测 vs 标签"的算子，都要有这类
**「极端输入 → 预期数值」** 的断言。

## D.8 ❓ 自测题

1. 怎么用一句话判断一个官方仓库"是否真的提供了论文的代码"？
2. 为什么 `loss_bbox` 恒等于 1.0 是"回归分支死锁"的信号，而不是"模型还没收敛"？
3. `1 - IoU` 和 `-log(IoU)` 在框不相交时的梯度行为有什么本质区别？
4. 水平翻转写框时，为什么"先改 x1 再改 x2"会出错？
5. 为什么说"移植损失函数时必须连默认参数一起移植"？

<details>
<summary>👉 自测答案</summary>

**1.** **逐文件 diff**：把作者仓库和它声称的来源仓库（README、import、包名、model-index）
做逐文件比对。本例中 `CCFA-Net-official` 与 `GrokCV/HazyDet` **差异 0 行**，
且 `setup.py` 的 `name` 都没改、`model-index.yml` 为空、git log 只有 1 个 commit
→ 说明它是**改名后的副本**，不含论文方法。

**2.** 因为 `1 - IoU` 的 loss 值**恰好等于 1** 意味着 **IoU 恒等于 0**，
即预测框与 GT 框**完全不相交**；而此时该损失的**梯度恒为 0**（IoU 是分段常数），
所以它**永远不会变**。收敛中的模型 loss 会波动下降，不会精确地卡在 1.00000。

**3.** `1 - IoU` 的梯度 ∝ ∂IoU/∂x，不相交时 **IoU 恒为 0 且梯度为 0** → 死锁；
`-log(IoU)` 的梯度 ∝ (1/IoU)·∂IoU/∂x，**把"微小重叠"放大成可用梯度** → 能爬出平台期。
（但必须 `clamp(min=eps)` 防止 `log(0)` 产生 inf/nan。）

**4.** 因为**就地修改**——第一步已经把 `x1` 改成了 `new_w - x2_old`，
第二步再读 `x1` 拿到的是**已经被改过的值**，于是 `x2 = new_w - (new_w - x2_old) = x2_old`，
最终 `x2` 没被镜像、`x1` 却被镜像 → 框宽变成负数。
正确写法是**同时赋值**：`boxes[:, [0,2]] = new_w - boxes[:, [2,0]]`。

**5.** 因为**默认值本身就是语义的一部分**。
mmdet 的 `IoULoss` 默认 `iou_mode='log'`，只抄公式不抄默认值，
就等于把优化动力学从"放大梯度"改成了"梯度归零" —— **静默改变、且不报错**。

</details>

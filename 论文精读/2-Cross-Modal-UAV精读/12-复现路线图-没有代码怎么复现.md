# 🧭 复现路线图：没有代码怎么复现

> [!question] 这篇问题最要命
> **这篇论文没有官方代码。** 全文没有 GitHub 链接，也没有 Data Availability 声明，只在 Implementation Details 里写了一句 "The pytorch library is used for code implementation"。
> 那是不是就没法复现了？

**不是。** 这一讲把"没有代码"这件事拆开，并给出可执行的路线。

---

## 一、先纠正一个认知

> [!important] 复现 ≠ 拿到作者代码
> **复现 = 你自己把论文的公式翻译成代码 + 用论文给的超参训练 + 复现出论文的数字。**

很多同学以为"复现"是"跑作者的仓库"。那只是**抄作业**，而且：
- 大部分 CV 论文**不放代码**（期刊尤其如此，TVT/TGRS 的放码率远低于 CVPR/ICCV）；
- 即使放了，你也只是在验证别人的实现，**没有获得任何能力**；
- 答辩问"你哪里贡献了什么"时，答案是零。

> 🎯 **类比**
> 论文给的是**乐谱**，不是**录音**。
> 音符（公式、超参、数据集）全都在；**节拍（对齐方式）、力度（损失尺度）、配器（接哪一层）**要你自己定。
> 复现 = 把这首曲子**演奏出来**，并让听众（论文里的数字）认出它。

## 三、分级复现：必须按顺序做

```
Level 0  基线 Oriented R-CNN 在 DroneVehicle 上      → mAP 56.1   ← 90% 的人死在这
Level 1  基线 + SFI                                 → mAP 59.2
Level 2  基线 + API                                 → mAP 57.5
Level 3  基线 + SFI + API（完整模型）                → mAP 60.7
Level 4  消融：π₁ 扫描 {0, 0.3, 1.0}、w_ciou 消融
Level 5  对照组：IR+RGB 双检测器输出级融合            → mAP 63.2
```

> [!warning] Level 0 是全部工作的门槛
> 如果基线本身没跑到 56.1，后面所有数字都没有意义。
> 很多"复现失败"的真实原因**不是模块写错，而是基线没对齐**：
> - 旋转框的评测口径（多边形 IoU vs 轴对齐 IoU）
> - 数据划分（DroneVehicle 官方 test 无标签，原验证集被并入测试集）
> - anchor 尺寸 / stride / FPN 层设置
> - 评测脚本（官方 `eval/DroneVehicleEval.py`）

### 为什么要一级一级来

| 直接做 Level 3 的后果 |
|---|
| mAP 只有 58，差 2.7 |
| 不知道是 SFI 写错、API 写错，还是基线弱 |
| 三天改三个地方，最后不知道哪个改动有效 |

> 🎯 **类比**
> 做菜复刻时，第一步不是"同时炒三个菜"，而是先把**盐**的量做对——
> 先炒一盘最简单的青菜，看看火候对不对。

## 四、三条技术路线

| 路线 | 做法 | 工作量 | 风险 | 推荐 |
|---|---|---|---|---|
| **A. mmrotate 魔改** | 用 mmrotate 现成的 Oriented R-CNN config，把 SFI / API 写成自定义模块接进去 | 小（~2 天） | 中（mmcv-full 要编译） | ✅ **首选** |
| **B. 纯 PyTorch 从零写** | 自己写 Rotated RPN / RoIAlign(rotated) / rotated NMS / 多边形 IoU | 数千行 | 极高 | ❌ 第一篇别做 |
| **C. 抄别人 CKD 开源项目** | 找一个 cross-modal KD 开源仓库当骨架 | 中 | 中 | 🟡 备选 |

### 路线 A 具体怎么走

1. **数据集注册**：官方仓库 `SunYM2020/UA-CMDet` 里**已经写好了** `mmdet/datasets/DroneVehicle.py`、`two_stream_DroneVehicle.py`、`rotate_aug.py`
2. **基线配置**：拿 mmrotate 的 `configs/oriented_rcnn/oriented_rcnn_r50_fpn_1x_dota_le90.py`，把 `img_size` 改成 840×712、数据集换成 DroneVehicle
3. **加两个模块**：写 SFI / API 的 `forward`，把 backbone 的 `feats` 和 RPN/RoI head 的 `dets/scores` 接出来
4. **改 loss**：`L_total = L_det + L_f + L_cls + L_loc`

### ⚠️ Mac 上的硬约束

- `mmcv-full` **只提供 Linux x86_64 的预编译轮子**，macOS / Apple Silicon 没有；
- `mmrotate` 依赖的 `roi_align_rotated` / `psroi_align_rotated` / `poly_nms` 都是 **CUDA 扩展**，没 CUDA 编不过；
- **完整的 mmrotate 训练必须在 Linux GPU 机器上跑。**

> [!tip] 但有 workaround
> 本仓库用**纯 PyTorch** 重写了多边形 IoU（Sutherland–Hodgman 凸多边形裁剪 + 鞋带公式），
> 已用**蒙特卡洛**交叉验证（误差 < 0.02），
> 所以 **API 模块的几何部分在 Mac 上就能跑通、就能验证**。

## 五、你必须自己决定的 6 个"自由度"

论文没写的地方 —— 这既是**风险**，也是**你未来发论文的选题空间**。

| # | 自由度 | 论文给了什么 | 你要定什么 | 默认 |
|---|---|---|---|---|
| 1 | **SFI 接 FPN 哪几层？** | 没说 | P2/P3/P4/P5 选哪些 | `P4`（`M` 是 `(H·W)×(H·W)`，P2 会爆显存） |
| 2 | **Eq.(2) 分母的 L1 归一化** | 只说"L1 normalization" | 全局标量？逐位置向量？ | 逐行/逐列（`l1_rowcol`），另备 `l2_cos` / `l1_global` |
| 3 | **M 要不要 clamp / softmax？** | 没说 | 相似度是否截断到 [0,1] | clamp（ReLU 特征非负，余弦天然 ∈[0,1]） |
| 4 | **Eq.(4) 的矩阵方向** | 公式**本身不对称** | 字面照抄？还是对称化？ | `paper`（字面） / `sym`（对称化） |
| 5 | **`w_ciou` 的归约粒度** | Eq.(6) 逐目标，Eq.(7) 外套 `1/N Σ` | 逐目标加权后求均值？ | 逐目标加权后取均值 |
| 6 | **老师/学生检测框怎么配对？** | 没说 | 贪心 IoU？匈牙利？阈值？ | 贪心 IoU，阈值 0.5 |

### ⚠️ 自由度 #1 的显存红线

`M` 是 `(H·W)×(H·W)` 的矩阵。输入 840×712：

| FPN 层 | 特征图 | H·W | `M` 的显存(fp32) | 能用吗 |
|---|---|---|---|---|
| P2 | 210×178 | 37 380 | ≈ 5.6 GB | ❌ |
| P3 | 105×89 | 9 345 | ≈ 350 MB | 🟡 |
| P4 | 52×44 | 2 288 | ≈ 21 MB | ✅ |
| P5 | 26×22 | 572 | ≈ 1.3 MB | ✅ |

→ **SFI 只能接 P4/P5**，或者先做空间池化。

## 八、关键公式回顾（复现时要一字不差抄的）

**总损失**（Eq.14）：

$$
L = L_f + L_{cls} + L_{loc}
$$

**SFI**（Eq.2–5）：

$$
M = \frac{F_{IR} \cdot F_{RGB}}{\|F_{IR}\|_1 \|F_{RGB}\|_1},
\qquad
\bar{M} = 1 - M
$$

$$
F^{com}_{IR} = M \cdot F_{IR}, \quad F^{res}_{IR} = \bar{M} \cdot F_{IR}
$$

$$
L_f = \pi_1 \|F^{com}_{IR} - F^{com}_{RGB}\|_2^2 + \pi_2 \|F^{res}_{IR} - F^{res}_{RGB}\|_2^2
$$

**API**（Eq.6–13）：

$$
w_{ciou} = \frac{Area(D_{RGB} \cap D_{IR})}{Area(D_{RGB} \cup D_{IR})}
$$

$$
L_{KL} = w_{ciou} \cdot \frac{1}{N}\sum_{i=1}^{N}\sum_{k=1}^{K} p^{k}_{IR}\log\frac{p^{k}_{IR}}{p^{k}_{RGB}}
$$

$$
L_{cls} = \rho L_{KL} + (1-\rho)L_{CE}, \qquad \rho = 0.7
$$

$$
L_{loc} = \lambda L^{ts}_{loc} + (1-\lambda)L^{sl}_{loc}, \qquad \lambda = 0.5
$$

> [!note] 论文**没有**的东西
> - **temperature**：全文 0 次，KL 用原始 softmax。复现时先 T=1，并把它列为消融项。
> - 老师是**已在 IR 图像上训练好的 Oriented R-CNN**（Section III-A），IR 标注来自 DroneVehicle 的 IR 标注文件。

## 九、复现时的三个"数字对齐"陷阱

1. **消融的基线要对齐**
   论文的 `π₁` 扫描（58.54 / 59.21 / 58.29）比完整模型 60.7 低 → 该消融是在**只加 SFI**的配置下做的。复现时基线不同，数字自然对不上。

2. **DroneVehicle 的 test 集没有公开标签**
   论文说"把原验证集并入测试集"。你需要确认自己用的划分与论文一致，否则 mAP 不可比。

3. **旋转框评测口径**
   必须用**多边形 IoU**（顶点级），不能用轴对齐 IoU。论文明确"follow the work [7]"（DroneVehicle 原论文）。

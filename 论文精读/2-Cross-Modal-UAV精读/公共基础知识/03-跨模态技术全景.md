## 20.1 先把"模态"这个词落到实处

**模态（modality）= 信息的记录方式 / 感知通道。**

同一个物理场景，可以被多种设备"记录"，每种记录方式得到的就是一种模态。

> 🎯 **统一比喻：一场演出，多台摄像机**
> 同一个晚上、同一场露天演出，导演手里有好几台设备。
> 每台设备拍到的东西不一样，但拍的是**同一场戏**。

| 设备 | 模态 | 拍到了什么 | 拍不到什么 |
|---|---|---|---|
| 普通摄像机 | 可见光 RGB | 颜色、纹理、细节、车牌号 | 黑暗、浓雾、逆光、遮挡 |
| 热成像仪 | 红外 IR | 谁在发热、人体轮廓、活物 | 颜色纹理细节；怕阳光直射 |
| 激光雷达 | 深度 LiDAR | 精确的三维几何距离 | 纹理、语义（认不出"这是车"） |
| 麦克风 | 音频 | 引擎声、说话声 | 一切画面信息 |
| 节目单 / 字幕 | 文本 | 语义、类别、属性 | 一切物理细节 |
| 多光谱/高光谱卫星 | 光谱 | 地物材质、含水量 | 空间分辨率低 |

**关键观察：没有任何一种模态是"全能"的。**
每一台摄像机都既**拍到了别人拍不到的**，又**拍不到别人拍得到的**。
→ 跨模态技术存在的全部理由就在这一句里。

## 20.2 什么是"跨模态"？—— 难点是"模态鸿沟"

**跨模态（cross-modal）**：让**两个及以上不同模态**的信息互相理解、互相补充的技术。

术语辨析（常被混用）：

| 术语 | 强调点 | 一句话 |
|---|---|---|
| **多模态（multi-modal）** | "**用**了多种模态" | 描述**系统配置** |
| **跨模态（cross-modal）** | "在模态**之间**做对齐/迁移/翻译" | 描述**技术动作** |

> 本文标题里的 "Cross-Modal" 就是后者：
> 它关心的不是"我有两个模态"，而是"**两个模态之间怎么对齐**"。

### ⚠️ 核心障碍：模态鸿沟（modality gap）

同一个语义概念（"这是一辆车"），在**不同模态的特征空间里位置完全不同**。

```
红外特征空间                     可见光特征空间
   ● 人 (热的)                      ● 人 (有皮肤纹理)
   ● 车 (有热源)      ← 鸿沟 →      ● 车 (有轮胎轮廓)
   ● 动物 (热的)                    ● 猫 (有毛发)
```

强行把两个空间拉近，就是**翻译不同语言的人脑神经活动**——两边都学乱。

详见 [[paper-notes/论文精读/2-Cross-Modal-UAV精读/02-第1讲-知识蒸馏与模态鸿沟]] §1.3。

## 20.3 ★ 跨模态技术全景：四个方向

这是本篇最重要的**地图**。所有跨模态论文都落在下面四格里之一。

```
                    跨 模 态 技 术 全 景
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
   【对齐 / 翻译】      【共享表征】        【融合】          【迁移 / 蒸馏】
   Alignment/Translation  Shared Rep.      Fusion           Transfer/Distill
        │                   │                   │                   │
   "把 A 翻译成 B"      "让 A、B 在同一本      "让 A、B 的信息       "让 A 的知识"
                        词典里指向同一页"      合起来做决策"        教会 B"
        │                   │                   │                   │
  RGB→Depth 估计      CLIP / 对比学习      多光谱融合检测        ★ 本文 CKD
  IR→伪RGB 生成      跨模态检索            IR+RGB 融合检测       ★ 本文 SFI + API
  模态间配准          零样本分类            模态缺失问题
```

### 方向 ① 对齐 / 翻译（Alignment & Translation）

**做什么**：把 A 模态的表示**搬到 B 模态的空间**里去。

- 例：输入红外图，生成一张"伪可见光图"，直接喂给普通 RGB 检测器
- 例：输入 RGB 图，预测出**深度图**（depth estimation）
- 例：把 CT 图翻译成 MRI 风格（医学影像）

> **风险**：翻译会**丢信息**，还会**幻觉**（编造出原图没有的东西）。

### 方向 ② 共享表征（Shared Representation）

**做什么**：学一个**公共语义空间**，让不同模态里同一个概念的向量落到一起。

- 旗舰代表：**CLIP** —— 用海量图文对训练，让"图片"和"文字"用同一套向量表示
- 核心技术：**对比学习**（contrastive learning）
- 好处：训练时用多模态，**推理时可以只用其中一个模态**

### 方向 ③ 融合（Fusion）

**做什么**：把多个模态的信息**合成一个决策**。

- 例：早期 UAV 检测的主流做法 —— IR + RGB 双分支，最后 concat 特征再检测
- 例：多光谱遥感（论文四的相关方向）、医学影像多模态诊断
- **致命短板**：推理要**所有模态都在场**，算力和传感器成本翻倍；
  缺一个模态系统就崩（**模态缺失问题**，missing modality）

### 方向 ④ 迁移 / 蒸馏（Transfer & Distillation）★ 本文的家

**做什么**：**让一个模态的模型，去教另一个模态的模型。**

- 跨模态知识蒸馏（cross-modal distillation, CKD）
- 本文就是这一类：**冻结的 IR 检测器 = 老师，RGB 检测器 = 学生**
- **最大优势**：训练时用尽所有模态，**部署时只留最便宜的那个**

> 💡 **一句话记住四格的关系**
> **翻译**是"换个说法"，**表征**是"编本词典"，**融合**是"一起开会做决定"，
> **蒸馏**是"老师只教一个人，然后把老师撤走"。

## 20.4 ★ 在哪一层做对齐？三大层级（技术手段）

方向④（尤其本文）内部还要再分：**你在网络的哪一层，让两个模态"对齐"？**

| 层级 | 做法 | 代表 | 优点 | 缺点 |
|---|---|---|---|---|
| **输入级** input-level | 直接生成/翻译图像 | IR→伪RGB、RGB→Depth | 现有单模态模型直接能用 | 翻译会丢信息、易幻觉；像素级开销大 |
| **特征级** feature-level | 对齐中间特征图 | **本文 SFI** | 保留结构信息，比输入级更省 | 特征空间语义未必对齐（鸿沟仍在） |
| **输出级** output-level | 对齐预测分布/框 | **本文 API** | 与下游任务目标直接一致 | 丢掉了中间信息，对齐粒度粗 |

```
输入级:   IR图 ──[生成网络]──► 伪RGB图 ──► 现有检测器
                              （翻译即幻觉来源）

特征级:   IR图 ──► f_IR(·) ──┐
                    │       ├──► 特征对齐损失 ──► RGB分支
           RGB图 ──► f_RGB(·)┘               ★ 本文 SFI

输出级:   IR检测器 ──► 框+类别分布 ──┐
                                      ├──► KL / 蒸馏损失
           RGB检测器 ──► 框+类别分布 ─┘        ★ 本文 API
```

> 🎯 **比喻**
> - **输入级**：给色盲画家配一支能"看见颜色"的翻译笔（他看到的还是翻译后的画面）
> - **特征级**：让两人**各自描述**同一张桌子，然后逐句对齐他们的"草稿"
> - **输出级**：只比对两人**最后写出的那一个词**（"桌子" vs "table" 必须对上）
>
> 对齐的层越深，信息越少但越直接；越浅，信息越多但越容易幻觉。

## 20.5 必须认识的名词（词汇表）

| 名词 | 含义 | 一句话 |
|---|---|---|
| **模态鸿沟** modality gap | 不同模态的特征空间天然不重合 | 跨模态的头号敌人 |
| **域对齐** domain alignment | 把两个**同构**分布（都是图像）拉近 | 典型方法：**CORAL**（协方差对齐）、**MMD**（最大均值差异） |
| **对比学习** contrastive learning | 让"配对样本"靠近、"不配对样本"远离 | CLIP 的核心；正样本=同语义跨模态，负样本=不同语义 |
| **语义一致性** semantic consistency | 两种模态对同一对象的**语义判断**应该一致 | 本文 API 的 KL 项就在做这件事 |
| **一致性正则** consistency regularization | 对同一场景的不同模态视图，强制输出一致 | 扰动 + 一致性损失的范式 |
| **模态缺失** missing modality | 部署/使用时某个模态拿不到 | 融合路线的死穴；蒸馏路线的天然优势 |
| **共性 / 残差特征** | 两模态都有的 vs 某模态独有的 | 本文 SFI 的核心洞察（见 §20.7） |
| **跨模态蒸馏** CKD | 用一个模态的模型教另一个模态 | 本文所属方向 |

> ⚠️ **域对齐 vs 跨模态**：域对齐（DA）假设"两个域**同构**"（都是 RGB 图，只是风格不同），
> 跨模态处理的是"**根本不同构**"（RGB vs IR）。DA 的方法不能直接搬到跨模态上。

## 20.6 ★ 跨模态 vs 传统 KD：差在哪？

传统知识蒸馏和本文的跨模态蒸馏，外表都是"老师教学生"，但**知识的来源完全不同**。

| | 传统 KD | 本文 CKD（跨模态蒸馏） |
|---|---|---|
| 老师 vs 学生 | **大 vs 小**（容量差） | **完全同构**（结构一样大） |
| 知识来源 | 模型的**容量 / 深度 / 训练数据量** | **模态差异**（IR 能看见 RGB 看不见的东西） |
| 学生缺什么 | 容量 | **感知通道** |
| 老师为什么会错 | 老师通常**更准** | **老师也会错**（夜间 RGB 看不见的目标 IR 能看见 → 训练集标注数差 3 万个） |
| 部署省什么 | 参数量 / 算力 | **一整套传感器**（红外相机 + 融合模块） |
| 代表作 | Hinton 2015 | 本文 |

> 🎯 **比喻**
> 传统 KD 是"**博士生教小学生**"——老师脑子里多的是**知识量**。
> 跨模态 KD 是"**你闭上一只眼，用另一只眼当老师**"——老师脑子里多的是**视角**。
> 学生结构一点没变，但**世界变大了**。

## 20.7 论文二在地图上的坐标

```
                    跨模态技术全景
                            │
   【对齐/翻译】  【共享表征】  【融合】    【迁移/蒸馏】
                                       ┌──────┴──────┐
                                       │             │
                                   特征级 SFI     输出级 API
                                  （共性/残差）  （逐目标 IoU 加权 KL）
                                       └──────┬──────┘
                                              │
                                    本文 CKD（方向④）
```

**本文的三个"不寻常"（= 你的可做选题）**

| # | 不寻常之处 | 为什么重要 |
|---|---|---|
| 1 | **老师不是更大的模型，是另一个模态** | 传统 KD 的全部直觉都要重写：老师的"知识"来自**视角**而非容量 |
| 2 | **全文没有温度 T**（"temperature" 出现 0 次） | 通行做法都强调温度是蒸馏的灵魂，本文却直接扔掉 → **可以做个"加温度会不会更好"的实验** |
| 3 | **部署时删掉整个红外分支** | 它不是压缩模型，是**部署时的模态裁剪**；省下的是一套硬件 |

## 20.8 一张表记住"什么场景用哪条路"

| 你的处境 | 该走哪条路 | 理由 |
|---|---|---|
| 缺数据、缺标注 | **跨模态蒸馏** | 借另一个模态的现成模型当老师 |
| 算力/传感器受限 | **跨模态蒸馏**（本文） | 部署只留便宜的模态 |
| 想做跨模态检索 / 零样本 | **共享表征**（CLIP 式） | 要的是公共语义空间 |
| 传感器齐全、追求极致精度 | **融合** | 信息用得最全 |
| 想复用现有单模态模型、不想改结构 | **输入级翻译** | 代价是幻觉风险 |

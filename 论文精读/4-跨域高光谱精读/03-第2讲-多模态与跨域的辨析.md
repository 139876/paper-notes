# 03 · 第 2 讲：多模态与跨域的辨析

> [!abstract] 本讲要回答
> "多模态""跨域""多任务"经常被混着用。分不清，论文里就会写出"我们通过跨模态对齐解决域偏移"这种外行话。

---

## 1️⃣ 多模态是什么

**多模态 = 同时处理两种及以上"模态"的信息，并且需要把它们对齐、融合起来做判断。**

"模态"= 信息的载体形式 / 通道：

| 模态 | 记录的形式 | 例子 |
|---|---|---|
| 可见光 RGB | 3 通道像素 | 手机照片 |
| 红外 / 热红外 | 辐射强度 | 夜间搜救、夜间驾驶 |
| 深度 | 距离值 | 结构光、ToF、激光雷达 |
| **光谱（高光谱）** | 每像素一条连续曲线 | HSI 遥感分类 |
| 文本 | 符号序列 | 说明书、报告、字幕 |
| 声音 | 波形 / 频谱 | 语音、机械异常声 |
| 雷达 | 回波 | SAR、毫米波雷达 |

> **类比**：医生看一个人，同时看**脸色**（视觉）、**听呼吸**（听觉）、**摸脉搏**（触觉）、**读化验单**（文本）。单看一项容易误判，合起来才敢下诊断——这就是多模态的直觉。

### 为什么需要：单模态信息不完整

以雾天无人机检测为例：

- 只有 RGB：雾把对比度洗白，小车和背景糊在一起 → 检测器失效
- 加上**深度**：雾霾中近处物体仍有深度线索 → 车能被定位
- 加上**红外 / 雾密度图**：可以判断"这块区域的可信度"，让网络决定信不信 RGB

> 多模态的价值 = **互补 + 互为校验**，而不是简单堆叠。

---

## 2️⃣ 三类多模态任务

1. **融合型（Fusion）**：各模态编码后拼接再分类（RGB + 深度分割）
2. **对齐 / 检索型**：文字搜图、雷达信号配图像
3. **翻译 / 生成型**：RGB→深度估计、红外→可见光重建、文本→图像

---

## 3️⃣ 关键技术难点

| 环节 | 问题 | 常见手段 |
|---|---|---|
| 对齐 | 两种模态说的是不是同一处东西 | 注意力对齐、对比学习、时空戳同步 |
| 融合 | 谁更可信、怎么加权 | 早融合 / 晚融合 / 门控·注意力融合 |
| 缺失模态 | 部署时某个传感器缺了 | 模态 dropout、缺失感知注意力 |
| 分布差异 | 模态间"鸿沟"远大于域间差距 | 共享嵌入、蒸馏、对抗 |

---

## 4️⃣ ⚠️ 三个概念的正交关系（重点）

| 概念 | 变了什么 | 本库里的例子 |
|---|---|---|
| **多模态** | 换的是**信息通道**（RGB↔红外↔文本） | Cross-Modal Object Detection via UAV |
| **跨域（DG/UDA）** | 换的是**同一模态的采集条件**（晴↔雾、机载↔卫星、传感器 A↔B） | CCFA-Net、HazyDet |
| **多任务** | 换的是**预测目标**（分类+检测+分割） | 多任务损失类工作 |

### 本文（跨域高光谱）属于哪一类？

> [!important] 判定
> 本文是**跨域**，**不是多模态**。
> 高光谱数据本身是**单一模态**（HSI 立方体），跨的是源域 / 目标域。
>
> 但高光谱的域偏移有个特殊之处：**它是连续的光谱形状变化**（传感器响应、照度），而不是整幅图的风格变化。
> 正因如此，"把扰动显式建模成随机变量"（JVC）才格外自然——光谱抖动本来就是物理上真实存在的连续变量。

### 一句话判别法

> **换传感器种类 = 多模态；换同种传感器的采集条件 = 跨域。**
> RGB → 红外 是多模态；RGB(晴天) → RGB(雾天) 是跨域。

---

## 5️⃣ 自测

自动驾驶用「摄像头 RGB + 毫米波雷达 + 激光雷达」检测行人：

1. 这属于多模态还是跨域？
2. 若把摄像头换成另一款分辨率不同的摄像头，还算多模态吗？
3. 雾天摄像头失效、雷达仍可用，多模态系统应该怎么"用"这个信息？

> 第③问的答案就是多模态的核心：**不是把模态拼起来，而是学会在什么条件下该信哪一个**。
> 这与本课题的 ASI 是同一类问题——**在不可靠时靠一个可靠参照系来锚定判断**。

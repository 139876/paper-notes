## 9.1 一句话定位

**在多个源域上联合训练一个「双分支解耦 → 逐层跨域耦合 → 深层约束对齐 → 逐像素分类」的流水线，在从未见过的目标域上零样本分类。**

### ⚠️ 先纠正两个最容易读错的地方

| 误读 | 事实 |
|---|---|
| ❌ 「训练时也用目标域数据做对齐」 | ✅ **这是 DG 不是 UDA**。看图：红框 Training 里**只有** `D^o_s1`、`D^o_s2` 两个源域，`D^o_t` 出现在 Test 框。训练时目标域数据**一个像素都没有** |
| ❌ 「末端是检测头，有 anchor box」 | ✅ 末端是 **BCE Classifier**（逐像素二分类头）+ 输出**分类图**。这是**高光谱逐像素分类**，不是检测。图里的 "anchor" 是**特征空间的聚类中心**，和检测器的 anchor box 没关系 |

> [!warning] 跨论文串台提醒
> 这张图和你前 3 篇（CCFA-Net / Cross-Modal UAV / HazyDet 全是**目标检测**）**不是一类任务**。
> HazyDet 里的 bbox、anchor、IoU、NMS 那套**在这里一个都用不上**，别往里套。

## 9.3 逐块走图（Training 上半部分）

### ① 输入：两个源域

`D^o_s1`（上图，街区密集）和 `D^o_s2`（下图，农田/植被）。
上标 `o` 大概是 *original*（原始数据，区别于增强后的视图）。
**两个域必须同时在场** —— 因为后面所有约束都是"跨域"的。

### ② Preprocessing：`SA` → `AEM` / `IFEM` 双分叉

```
D^o_s1 ─┐
        ├─► SA (❄️ 冻结) ─┬─► AEM  ─┐
D^o_s2 ─┘                 └─► IFEM ─┴─► [蓝色主干块]
```

- **SA**：预处理阶段的**固定算子**（❄️ 不更新）。
  结合它只在训练分支出现、测试分支的 Preprocessing 是一整块，**大概率是光谱域的数据增强/标准化**类算子（❓ 全称待正文核对）。
- **SA 之后分两叉** —— 这是全文"**解耦**"二字的落点：

| 分支 | 模块 | 干什么 | 属于 |
|---|---|---|---|
| 上叉 | **AEM**（Attribute Enhancement Module，属性增强模块） | 把"这个域独有的属性"（光照基调、传感器响应、噪声水平）**强化**出来 | **intra-DUEB** 域内特性分支 |
| 下叉 | **IFEM**（Domain Feature Enhancement Module，域特征增强模块） | 把"各域共有的东西"**强化**出来 | **inter-DCEB** 域间共性分支 |

> [!question]- 为什么"域特有信息"要专门提出来，而不是直接扔掉？
> 因为要"求共性"必须有**参照物**。只有把各域的特有部分**显式化**，才能通过**相减**把共性抠出来。
> 域特有信息在这里是**原料**，不是垃圾。
> 详见 [[07-第6讲-DBFDF双分支骨干网络]]。

> [!warning] 图上一处标注瑕疵
> 蓝色主干块也标了 "IFEM"，和下面那个半圆重名。
> 合理读法是「AEM / IFEM 两路处理完汇合进 DBFDF 主干」，蓝色块的标签大概率是**标注复用或笔误**（❓ 待正文核对）。

### ③ DBFDF Backbone：4 层 × COS 节点 + SDP 约束

```
 f^1_s1 (黄) ─┐                                    ┌─► f^4_s1 (双圈)
              ├─► [COS] ──SDP──► [COS] ──SDP──► ... ┤
 f^1_s2 (绿) ─┘        ▲                           └─► f^4_s2 (双圈)
                       └── SDP ──┘
```

- **两级双流**：每个源域各走一路，逐层产出 `f¹…f⁴`（4 个 stage = 论文里的 4 层骨干）。
- **COS 节点（棕色，4 个）**：每一级都有一个 COS，**同时接收两个域同层的特征** → 这一级发生**跨域耦合**（这就是 DBFDF 的 "Fusion"）。耦合后的结果沿蓝色横箭头**继续往下传**。
- **SDP 标签（深蓝）**：挂在**相邻两级之间**的横箭头上 → **SDP 约束作用在层间过渡处**，而不是只作用在最后一层。这就是 "Progressive（渐进式）" 的字面含义。
- **最右侧双圈**：`f^4_s1`、`f^4_s2` 被**单独取出来**，送进 Feature Refinement 做对齐。

> [!warning] COS 的精确定义待补
> 从颜色对应看，它和总损失里的 `λ_cos·L_cos`（余弦相似度约束）大概率是同一套东西：既做特征融合，又同时贡献一个约束项。
> 但"是否即笔记里说的隐式卷积 + 相减"❓**正文未获取，待核对**。

### ④ Feature Refinement：`MLP → ASI + JVC`

```
g(f^4_s1) (黄)  ←┐
                  ├─ ASI（灰，结构）
g(f^4_s2) (绿)  ←┘└─ JVC（红，分布）
       ↓
   BCE Classifier
```

- **MLP**（灰色楔形）：一个**投影层**，把 `f^4` 映射成 `g(f^4)`。
  为什么要投影？因为 JVC 要在低维空间估密度（高维密度估计会崩），ASI 的锚点也要在这个空间里算。
- **ASI**（灰框）：作用在**这一对** `g(f^4_s1)`、`g(f^4_s2)` 之间 —— **保结构**。
- **JVC**（红框 + 红色虚弧）：同样作用在这一对上 —— **保分布**。
- 灰色虚线连接两个圆 = 两个域的特征被**摆到一起**比较；红色弧 = JVC 额外牵的那根线。

### ⑤ BCE Classifier

逐像素出每个类别的 logit → 右侧一列浅色小方块 = **每个类别一张概率图** → 取 argmax → 得到**分类图**（Test 行那张黑底彩色图）。

## 9.4 Test 分支（红框下半部分）

```
D^o_t → Preprocessing → DBFDF Backbone → Feature Refinement → BCE → 分类图
```

| 环节 | Training | Test |
|---|---|---|
| 输入 | 两个源域 `D^o_s1, D^o_s2` | 一个**没见过的** `D^o_t` |
| Preprocessing | 分叉成 AEM / IFEM | 单块，不分叉 |
| COS | 双域特征逐层耦合 | 单域，**无跨域耦合** |
| ASI / JVC | 算约束、进损失 | **不施加**，纯前向 |
| 损失 | `L_cls + λ_jvc L_JVC + λ_asi L_ASI + λ_cos L_cos + λ_sdp L_SDP` | 无 |
| 输出 | 两个域的 logits | 目标域**分类图** |

> [!question]- 为什么测试时 Preprocessing 不分叉？
> 因为**解耦的前提是有两个域可以互相对照** —— 只有一个域时，无从"减"出共性。
> 所以推理阶段只保留融合后的域不变主干。

## 9.5 右侧绿框：两个原理面板的公式拆解

### JVC · MI Minimization（红）

**图**：左边两个椭圆（橙 = Domain 1，绿 = Domain 2）**部分重叠但各自成团**；箭头右边 → 变成**一个椭圆、橙绿点混在一起**。

> **白话**：让"从特征里认出这是哪个域"这件事变得**不可能**。

$$
\frac{1}{n}\sum_{i=1}^{n} q\big(g(f_i), y_i, l_i; \beta\big) \;-\; \frac{1}{n^{2}}\sum_{i,j=1}^{n} \exp\Big(q\big(g(f_i), y_i, l_i; \beta\big) - 1\Big)
$$

| 符号 | 是什么 |
|---|---|
| `g(f_i)` | MLP 投影后的特征 |
| `y_i` | **类别标签** ← 关键：JVC 对齐的是 (特征, 标签) **联合变量** |
| `l_i` | **域标签**（Domain 1 / 2） |
| `q(·; β)` | **变分分布** `q`（用 β 参数化的一个小网络，估计联合分布） |
| 第一项 | `E_p[log q(Z,D)]` —— 变分分布在真实样本上的平均对数密度（越高说明越贴合真实联合分布） |
| 第二项 | 用**所有样本对**做指数平均，作为惩罚项（对数均值指数型下界） |
| 整体 | 这是 `I(Z;D)` 的**变分下界**，最小化它 ⇒ **MI 最小** ⇒ `Z ⊥ D`（特征与域独立） |

**为什么必须把标签 `y` 也塞进联合变量？**
> 两所学校学生考同一场卷子。只对齐"学生特征"（身高发型笔迹）→ 可能把爱看漫画的和爱看小说的对到一起；对齐"特征 + 答案"这个**对子**，才真的对齐了"谁擅长什么"。只对齐 `p(x)`，两个域的类别簇会**互相错位**。

**工程好处**：下界优化后化为**凸问题** → L-BFGS 求解（据专利 CN202610642401：映射到联合变量空间 → KDE+离散化估分布 → 改写成变分下界 → 凸问题 → L-BFGS）。

详见 [[05-第4讲-JVC联合变量一致性]]。

### ASI · Dynamic Anchor Graph（灰）

**图**：左边每类散成一个一个**小簇**（4 种标记 = 4 个**动态簇锚点**，图例 Cluster 1~4）；箭头右边 → 每个类**收拢成紧凑的一团**，并显出中心点。

$$
\frac{1}{2}\sum_{j=1}^{n_S}\sum_{u}\sum_{z} w^{j}_{a,u,z}\big\| a_{u s_j} - a_{z s_j} \big\|_2^2
$$

| 符号 | 是什么 |
|---|---|
| `u, z` | 两个锚点编号（`u` = 源锚点，`z` = 目标锚点） |
| `s_j` | 第 `j` 个源域 |
| `a_{u s_j}` | **锚点 u** 在源域 s_j 中所"吸附"的样本特征（以 `u` 为中心的那一簇） |
| `w^j_{a,u,z}` | **锚图权重**，由锚点间相似度给出（**压缩表示**过的邻接矩阵） |
| 整体 | 把两个域里**同一锚点所吸附的特征拉近** ⇒ 跨域**几何结构**不变 |

**两个设计**（详见 [[06-第5讲-ASI锚点结构不变性]]）：
- **动态簇锚点**：每轮特征更新后重新 k-means，簇中心 = 新锚点。**打移动靶** —— 靶心跟着靶走。代价：k-means 不可微（stop-gradient），训练变慢。
- **压缩锚图学习**：`K×K` 稠密邻接矩阵参数爆炸 + 会**图结构退化**（所有边权学成一样 = 废图）。压缩表示保住结构又省显存。

## 9.6 三模块怎么协作（这篇论文的真正内核）

> [!important] 一句话
> **DBFDF 负责"分得干净"，JVC 负责"长得一样"，ASI 负责"骨架不塌"。**

```
       多源域特征
            │
    ┌───────┴────────┐
    │                │
 intra-DUEB      inter-DCEB
 域内特性(AEM)    域间共性(IFM+IFEM)
    │                │
    └───────┬────────┘
            │  逐元素相减融合 → 域不变特征
            │
    ┌───────┴────────┐
    │                │
  JVC 约束        ASI 约束
 (分布对齐+MI)    (几何结构不变)
    │                │
    └───────┬────────┘
            ↓  BCE 分类损失 → 端到端训练
```

**核心矛盾（摘要批的就是这个）**：
> **对齐越狠 → 可分性越差。**
> 现有 DG 方法只做"隐式卷积 + 相减"式的**局部两两对齐**；两两减一减只保证"差得对"，**不保证"整体齐"**，也不保证对齐后**类别簇的形状没被拉塌**。
> 本文用 **JVC** 补上**全局分布约束**，用 **ASI** 补上**几何结构保护**。

**一个微妙点**（很多人读不懂会以为论文自相矛盾）：本文自己的骨干**也用隐式卷积 + 相减**，但摘要批评的正是这个。

| | 现有方法 | 本文 |
|---|---|---|
| "卷积+相减"的角色 | 当**对齐手段**（两两减完就宣称对齐了）→ 局部、缺全局约束 | 当**骨干里的特征分离机制**（借相减把共性抠出来），**另外**再用 JVC 在分布层面补全局约束 |
| 结果 | 只保证"差得对" | 既保证"差得对"，又保证"整体齐"+"骨架不塌" |

**同一件工具，用在不同位置、承担不同角色** —— 这正说明三者**互补且缺一不可**。

## 9.9 自测题

> [!question]- 1. 这张图里能一眼看出是 DG 还是 UDA？靠哪个部分？
> **答案**：靠 **Training 框的输入**。Training 框里只有 `D^o_s1`、`D^o_s2` 两个源域，**`D^o_t` 只出现在 Test 框**。
> UDA 的 Training 框里一定会出现**无标签目标域**的数据流。DG 则是目标域彻底不见。
> 补充：JVC 的公式里也**没有 `t` 的上标**，说明对齐发生在**多源域之间**。

> [!question]- 2. 为什么测试时 Preprocessing 不分叉成 AEM/IFEM？
> **答案**：**解耦的前提是有两个域可以互相对照**。只有一个域时，"相减去掉域特有"这个操作无从执行（没有第二个域当参照），所以推理阶段只走融合后的域不变主干。

> [!question]- 3. `f^4_s1` 和 `f^4_s2` 为什么画成双圈？
> **答案**：表示这两个是**被单独取出**、要送进下一级 Feature Refinement 去对齐的特征（而不是继续往下传）。普通的单圈表示中间层特征。

> [!question]- 4. SDP 标签为什么挂在 COS 块**之间**而不是块上？
> **答案**：因为 SDP 是**层间**的约束 —— 它约束的是"从第 i 级传到第 i+1 级"这个**过渡**上的相似性差异要渐进一致，而不是只约束某一层内部的特征。
> 这也呼应了 SDP 的全称 **Similarity Difference Progressive**。

> [!question]- 5. 图上"anchor"和检测里的 anchor box 是一回事吗？
> **答案**：**完全不是**。这里的 anchor 是**特征空间里通过 k-means 选出的簇中心**，用来定义"几何结构"的参照系（谁挨着谁）。
> 检测里的 anchor box 是**预定义的矩形框模板**。一个是聚类中心，一个是先验框。

> [!question]- 6. 读陌生论文架构图的通用套路是什么？
> **答案**：① **先看图例**（❄️🔥、框的颜色分别代表什么）→ ② **只看输入和输出**（这张图：HSI 立方体进，一张分类图出 → **分类任务**）→ ③ **数一数有几条数据流**（两条流 = 有两域 / 有两条分支）→ ④ **找彩色标签块**（这里 COS / SDP / ASI / JVC 是关键模块）→ ⑤ **看虚线框的颜色**（红色 = 训练/测试边界，绿 = 原理示意图）→ ⑥ **把每个块翻译成一句话**（COS = 同层跨域耦合，SDP = 层间渐进约束，ASI = 跨域结构拉近，JVC = 联合分布对齐）。

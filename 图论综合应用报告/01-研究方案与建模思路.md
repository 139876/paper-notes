## 一、最终研究设定

| 项 | 取值 | 为什么 |
|---|---|---|
| **题目** | 基于图论的重庆大学虎溪校区快递配送路径优化研究 | 自选题 + 真实场景 + 图论主线 |
| **配送起点** | 竹园北区快递服务站（S00） | 2025-05 正式启用；原博士生公寓临时点已停用 |
| **配送点** | 竹园/松园/梅园/兰园/菊园/荷园 6 个组团入口 | 学校官方公布的 6 个宿舍组团（35 幢） |
| **配送员** | 1 名 | 课程报告控制规模，不引入 VRP |
| **模式** | 完成全部配送后**返回起点**（闭合巡回） | 快递员必须回到站点 |
| **目标** | 最小化**总步行距离** | 单一目标最清晰 |

### 明确**不做**的事（防止跑偏）
- ❌ 多配送员协同 / 车辆载重 → 那是 VRP，超出课程范围
- ❌ 强化学习 / 实时交通预测 → 偏离图论本身
- ❌ 把教学楼、食堂、球场都当配送点 → 配送图会膨胀到 TSP 不可解

> [!important] 范围控制原则
> **路网可以很细（保留真实拓扑），配送图必须很小（10~20 个点以内）。**
> 本文是 23 顶点路网 → 7 顶点配送图。

## 二、为什么这个问题值得用图论

表面看是"多点访问顺序"，但真正让它是图论问题的是**距离的度量方式**：

> **配送员只能沿校园道路走 ⇒ 两点间距离是"路网上的最短路径长度"，不是直线距离。**

这一句话决定了整个模型结构：

```
第一层（路网图）：求"怎么走最近"      → Dijkstra / Floyd
第二层（配送图）：求"先去哪后去哪"    → TSP
```

## 三、算法路线（复现已有工作，不自创算法）

课程报告定位是**综合应用**，所以第 4 章写成"**已有算法原理与复现**"，
而不是"算法设计"。三级算法栈：

| 层次 | 算法 | 角色 |
|---|---|---|
| 距离层 | **Dijkstra** | 算 7 个配送点两两最短路 → 距离矩阵 |
| 优化层 | **最近邻 + 2-opt** | 求最优访问顺序（工程主力） |
| 对照层 | **Held–Karp** | 小规模精确最优，用来算 Gap、证明启发式够好 |

再叠加**两次交叉验证**保证实现可信：
- Dijkstra / Floyd ↔ **NetworkX**
- Held–Karp ↔ **暴力枚举**

## 五、数据从哪来（最关键、也最容易被扣分）

> [!danger] 当前状态：结构真实，数值待核
> 节点集合（23 个）与边连接关系（E01–E20 + 7 条接入边）**严格来自**
> 《图论应用选题建议》第 44–48 页的候选表；
> 但 **(x, y) 坐标是几何草图**，**边长由草图欧氏距离推算**。

### 采集流程
```
① 高德地图分区截图（北 / 中 / 南 / 西）
② 对照核验清单逐条核对：路存在吗？中间有路口吗？
③ 沿道路中心线量测长度 → 填入 data/edges.csv
④ 实地抽样复核 ≥20%
⑤ verified → yes, length_source → measured
⑥ python main.py 重跑，全文数字自动同步
```

详见 → [[05-数据核验清单|数据核验清单]]
